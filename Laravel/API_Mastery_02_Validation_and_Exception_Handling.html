Validation & Exception Handling

1. Form Requests for APIs

Controllers ke andar validation logic likhna beginner pattern hai. Production APIs mein validation humesha Form Requests mein move kiya jata hai taki Controller "Skinny" rahe.

app/Http/Requests/StoreUserRequest.php
class StoreUserRequest extends FormRequest
{
    public function authorize()
    {
        // Check if the user has permission to create users.
        // Return true if you handle auth via middleware.
        return true;
    }

    public function rules()
    {
        return [
            'name'  => ['required', 'string', 'max:255'],
            'email' => ['required', 'email', 'unique:users,email'],
            'role'  => ['required', Rule::in(['admin', 'editor', 'viewer'])],
        ];
    }
}

Ab aapka controller clean ho gaya:

public function store(StoreUserRequest $request)
{
    $user = User::create($request->validated());
    return $this->successResponse($user, 'User created.', 201);
}

2. Formatting 422 Validation Errors

Default Laravel behavior mein agar validation fail hota hai, toh wo ek ValidationException throw karta hai jo automatically 422 JSON response bhejta hai (agar request me Accept: application/json header ho). Lekin iska format hamare Module 1 ke standard envelope (success, message, errors) se match nahi karta.

FormRequest ke andar failedValidation method override karke hum format fix kar sakte hain:

app/Http/Requests/BaseApiRequest.php
namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Contracts\Validation\Validator;
use Illuminate\Http\Exceptions\HttpResponseException;

abstract class BaseApiRequest extends FormRequest
{
    protected function failedValidation(Validator $validator)
    {
        throw new HttpResponseException(response()->json([
            'success' => false,
            'message' => 'Validation failed. Please check the provided data.',
            'errors'  => $validator->errors()
        ], 422));
    }
}

Ab aapke saare API Requests FormRequest ki jagah is BaseApiRequest ko extend karenge.

3. Global Exception Handler (Laravel 11+)

Kabhi-kabhi aapke code mein `findOrFail()` fail ho jata hai, ya syntax error aa jata hai. Frontend ko HTML error page (`Symfony\Component\HttpKernel\Exception\NotFoundHttpException`) milta hai jo frontend app ko crash kar deta hai.

Laravel 11 mein bootstrap/app.php ka use karke API errors ko global level par handle karein:

bootstrap/app.php
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Database\Eloquent\ModelNotFoundException;
use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;
use Illuminate\Auth\AuthenticationException;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(...)
    ->withExceptions(function (Exceptions $exceptions) {
        
        // Force JSON response for API routes
        $exceptions->shouldRenderJsonWhen(function ($request, $e) {
            return $request->is('api/*');
        });

        // Handle 404 Model Not Found
        $exceptions->render(function (NotFoundHttpException $e, $request) {
            if ($request->is('api/*')) {
                return response()->json([
                    'success' => false,
                    'message' => 'Resource not found.',
                    'errors'  => null
                ], 404);
            }
        });

        // Handle Unauthenticated (401)
        $exceptions->render(function (AuthenticationException $e, $request) {
            if ($request->is('api/*')) {
                return response()->json([
                    'success' => false,
                    'message' => 'Unauthenticated.',
                    'errors'  => null
                ], 401);
            }
        });

    })->create();

4. Custom Domain Exceptions

Business logic mein jab error aata hai (e.g., User bank balance insufficient hai), toh controllers mein multiple if/else likhna buri practice hai.

Aap custom exception banayein jo automatically apna response render karna janti ho.

app/Exceptions/InsufficientBalanceException.php
namespace App\Exceptions;

use Exception;

class InsufficientBalanceException extends Exception
{
    // This render method tells Laravel exactly how to output this exception
    public function render($request)
    {
        return response()->json([
            'success' => false,
            'message' => 'Your account balance is too low for this transaction.',
            'errors'  => [
                'balance' => 'Required amount exceeds current balance.'
            ]
        ], 422);
    }
}

Ab apne service layer ya action class mein bas exception throw karein. Controller ko kuch handle karne ki zaroorat nahi hai!

public function processPayment(User $user, int $amount)
{
    if ($user->balance < $amount) {
        throw new InsufficientBalanceException();
    }
    
    // Process payment...
}
