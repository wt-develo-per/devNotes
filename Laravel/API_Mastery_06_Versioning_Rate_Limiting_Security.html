Architecture

1. API Versioning Strategies

Jab aap database table mein koi field delete karte hain (e.g. first_name aur last_name ko merge karke name kar diya), toh purane mobile apps jo update nahi hue, wo crash ho jayenge. Isliye hum API Versioning use karte hain.

Strategy A: URL Versioning

GET /api/v1/users
GET /api/v2/users

Pros: Easy to implement, browser mein easily testable.
Cons: URL structure badal jata hai, frontend me base URL change karna padta hai.

Strategy B: Header Versioning (Accept)

GET /api/users
Header: Accept: application/vnd.app.v2+json

Pros: URLs clean rehte hain (Restful principle).
Cons: Browser me test karna mushkil hota hai bina extension ke.

Implementation (URL Pattern): Laravel mein folder structure update karein:

routes/api.php
// V1 Routes
Route::prefix('v1')->namespace('App\Http\Controllers\Api\V1')->group(function () {
    Route::apiResource('users', UserController::class);
});

// V2 Routes (Breaking changes applied here)
Route::prefix('v2')->namespace('App\Http\Controllers\Api\V2')->group(function () {
    Route::apiResource('users', UserController::class);
});

2. Dynamic Rate Limiting

Default Laravel throttle:api aapko 60 requests/minute allow karta hai. Lekin real-world mein, aap shayad Free users ko 30 req/min aur Premium users ko 1000 req/min allow karna chahein.

app/Providers/AppServiceProvider.php (Boot method)
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Http\Request;
use Illuminate\Cache\RateLimiting\Limit;

public function boot()
{
    RateLimiter::for('api', function (Request $request) {
        
        // Custom logic based on User Tier
        if ($user = $request->user()) {
            
            if ($user->is_premium) {
                // Premium: 1000 requests per minute
                return Limit::perMinute(1000)->by($user->id);
            }
            
            // Standard user: 60 requests per minute
            return Limit::perMinute(60)->by($user->id);
        }

        // Guest user (IP based tracking): 10 requests per minute
        return Limit::perMinute(10)->by($request->ip());
    });
}

3. Managing CORS (Cross-Origin Resource Sharing)

Jab aapka React app localhost:3000 par chalta hai aur API localhost:8000 par, browser automatically request block kar deta hai CORS policy ki wajah se.

Laravel mein CORS handle karna ab bohot aasan hai. Laravel 11 mein configuration seedha `config/cors.php` se hota hai.

config/cors.php
return [
    // Kin paths par CORS allow karna hai? (Usually sirf API routes)
    'paths' => ['api/*', 'sanctum/csrf-cookie'],

    // Konse methods allowed hain? (GET, POST, etc.)
    'allowed_methods' => ['*'],

    // ❌ Never use '*' in production. Always specify exact domains.
    'allowed_origins' => [
        env('FRONTEND_URL', 'http://localhost:3000'),
        'https://my-production-app.com'
    ],

    // Zaroori agar aap Sanctum SPA auth (cookies) use kar rahe hain
    'supports_credentials' => true,
];

4. Idempotency (Preventing Duplicate Payments)

Maan lijiye user payment submit karta hai, lekin network lag ki wajah se use lagta hai button kaam nahi kiya. Wo 3 baar button dabata hai. Backend par 3 payment requests aati hain, aur uske card se 3 baar paise kat jate hain!

Solution: Idempotency Keys. Har POST request ke sath client ek unique `Idempotency-Key` header bhejta hai. Backend check karta hai: agar ye key pehle process ho chuki hai, toh purana response return kar do bina dobara charge kiye.

app/Http/Middleware/IdempotencyMiddleware.php
public function handle(Request $request, Closure $next)
{
    // Only apply to POST/PUT/PATCH methods
    if ($request->isMethodSafe()) { return $next($request); }

    $key = $request->header('Idempotency-Key');
    if (!$key) { return $next($request); }

    // Check if response exists in cache for this key
    $cacheKey = 'idempotency_' . $key;
    if (Cache::has($cacheKey)) {
        $cachedResponse = Cache::get($cacheKey);
        return response($cachedResponse['content'], $cachedResponse['status']);
    }

    // Execute request normally
    $response = $next($request);

    // Store response in cache for 24 hours (Only if successful)
    if ($response->isSuccessful()) {
        Cache::put($cacheKey, [
            'content' => $response->getContent(),
            'status' => $response->getStatusCode()
        ], now()->addDay());
    }

    return $response;
}
