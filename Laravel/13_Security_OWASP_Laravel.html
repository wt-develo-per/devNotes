Laravel framework out-of-the-box bahut powerful security guardrails deta hai, lekin galat coding patterns se ye shields bypass ho sakti hain:

💉 SQL Injection — A03 (The Database Destroyer)

CRITICAL SQL injection tab hoti hai jab user ke unescaped input ko direct SQL string mein concatenate kiya jata hai, jisse attacker database ke table drop kar sakta hai ya authentication bypass kar leta hai.

❌ Vulnerable Code — Yeh Galatiyan Kabhie Mat Karna!

Neeche diye gaye patterns dekhne mein harmless lagte hain, lekin ye direct remote database execution exploit offer karte hain:

phpVulnerableController.php (Fatal Security Flaws)
<?php

// ❌ CRITICAL FLAW 1: Direct SQL string interpolation
// User input: "'; DROP TABLE users; --"
$name = request('name');
$users = DB::select("SELECT * FROM users WHERE name = '$name'");

// ❌ CRITICAL FLAW 2: whereRaw() with string concatenation
// Attacker input: "0 OR 1=1"
$products = Product::whereRaw("price > " . request('min_price'))->get();

// ❌ CRITICAL FLAW 3: User input directly in orderByRaw()
// Attacker input: "(CASE WHEN (SELECT 1=1) THEN price ELSE id END)"
$column = request('sort');
$products = Product::orderByRaw($column)->get();

// ❌ HIGH FLAW 4: LIKE query bina PDO binding ke
$search = request('q');
$results = DB::select("SELECT * FROM products WHERE name LIKE '%$search%'");
🚨
Real-World Attack Payload Example: Agar login form ke email field mein attacker input de: admin@shopsphere.com' OR '1'='1, aur backend direct string query chala raha ho, toh password check evaluate hi nahi hoga aur attacker sidha admin account mein login ho jayega!
✅ Safe Code — Laravel Ki PDO Prepared Statements Shield

Laravel ka Eloquent ORM by default PDO prepared statements use karta hai jisme SQL structure aur data values alag-alag transmit hoti hain:

phpSecureProductController.php (Production Standard)
<?php

// ✅ SECURE 1: Standard Eloquent Query Builder (Auto-parameterized)
// Koi bhi malicious characters plain string data ki tarah treat honge
$name = request('name');
$users = User::where('name', $name)->get();

// ✅ SECURE 2: whereRaw() with bindings array parameter
$minPrice = request('min_price');
$products = Product::whereRaw('price > ?', [$minPrice])->get();

// ✅ SECURE 3: Whitelist allowed sort columns (Column names bind nahi ho sakte!)
$allowedSorts = ['price', 'name', 'created_at', 'rating'];
$column = in_array(request('sort'), $allowedSorts, true)
    ? request('sort')
    : 'created_at';

$direction = strtolower(request('dir', 'desc')) === 'asc' ? 'asc' : 'desc';
$products = Product::orderBy($column, $direction)->paginate(20);

// ✅ SECURE 4: LIKE search with parameter binding
$search = request('q');
$results = Product::where('name', 'LIKE', '%' . $search . '%')->get();

// ✅ SECURE 5: Raw DB::select with named bindings
$results = DB::select(
    'SELECT * FROM users WHERE email = :email AND status = :status',
    [
        'email'  => request('email'),
        'status' => 'active',
    ]
);
📋 Complex Analytics Queries Mein Safe Raw Queries Likhna

Agar reporting ya complex aggregation ke liye raw SQL likhna majboori ho, toh hamesha input validation, type-casting aur bindings combine karein:

phpAnalyticsReportController.php (Secure Raw Aggregation)
<?php

namespace AppHttpControllers;

use IlluminateHttpRequest;
use IlluminateSupportFacadesDB;

class AnalyticsReportController extends Controller
{
    public function dailyRevenue(Request $request)
    {
        // 1. Pehle strictly validate karo inputs ko
        $validated = $request->validate([
            'start_date' => 'required|date|before_or_equal:end_date',
            'end_date'   => 'required|date|after_or_equal:start_date',
            'category'   => 'required|string|max:50',
        ]);

        // 2. Numeric inputs ko explicitly int cast karo (Zero chance of injection!)
        $limit = max(1, min(100, (int) $request->input('limit', 25)));

        // 3. Query mein values ko question mark (?) binding array mein pass karo
        $revenue = DB::select("
            SELECT
                DATE(created_at) AS order_date,
                SUM(total) AS daily_revenue,
                COUNT(id) AS total_orders
            FROM orders
            WHERE created_at BETWEEN ? AND ?
              AND category = ?
              AND status = 'paid'
            GROUP BY DATE(created_at)
            ORDER BY order_date ASC
            LIMIT ?
        ", [
            $validated['start_date'],
            $validated['end_date'],
            $validated['category'],
            $limit,
        ]);

        return response()->json(['data' => $revenue]);
    }
}

CRITICAL XSS attacker ko doosre users ke browser mein malicious JavaScript inject karne deta hai, jisse session cookies, auth tokens chori ho sakte hain ya user ke behalf par actions execute ho jate hain.

❌ Vulnerable vs ✅ Safe Output in Blade Templates
❌ VULNERABLE (Unescaped)

📋 Content Security Policy (CSP) Header Middleware

CSP browser ko instruct karta hai ki sirf authorized domains se hi scripts, styles, aur iframes execute ho sakein:

phpapp/Http/Middleware/ContentSecurityPolicy.php
<?php

namespace AppHttpMiddleware;

use Closure;
use IlluminateHttpRequest;

class ContentSecurityPolicy
{
    public function handle(Request $request, Closure $next)
    {
        $response = $next($request);

        // CSP Policy definition
        $csp = [
            "default-src 'self'",
            "script-src 'self' https://js.stripe.com https://cdn.jsdelivr.net",
            "style-src 'self' 'unsafe-inline' https://fonts.googleapis.com",
            "font-src 'self' https://fonts.gstatic.com",
            "img-src 'self' data: https: blob:",
            "frame-src https://js.stripe.com",
            "object-src 'none'",
            "base-uri 'self'",
        ];

        $response->headers->set('Content-Security-Policy', implode('; ', $csp));

        return $response;
    }
}

// ⚠️ CRITICAL: Webhooks ko CSRF se hatane ke baad unka Signature verify karna MUST hai!
namespace AppHttpControllers;

use IlluminateHttpRequest;
use StripeWebhook;
use StripeExceptionSignatureVerificationException;

class StripeWebhookController extends Controller
{
    public function handle(Request $request)
    {
        $payload = $request->getContent();
        $sigHeader = $request->header('Stripe-Signature');
        $secret = config('services.stripe.webhook_secret');

        try {
            $event = Webhook::constructEvent($payload, $sigHeader, $secret);
        } catch (SignatureVerificationException $e) {
            // Agar signature match nahi hua toh direct 400 Bad Request
            return response()->json(['error' => 'Invalid Webhook Signature'], 400);
        }

        // Handle event safely
        return response()->json(['status' => 'success']);
    }
}
📋 Mass Assignment Protection — A08

HIGH Mass assignment vulnerability tab aati hai jab HTTP request ke saare parameters ko blindly database model mein pass kar diya jata hai (Model::create($request->all())), jisse attacker unauthorized sensitive fields manipulate kar leta hai.

❌ Vulnerable vs ✅ Secure Architecture
❌ VULNERABLE ($request->all() Trap)
phpDangerousUserController.php
<?php

// Model mein koi fillable restrict nahi hai ya $guarded = [] hai
class User extends Model {
    protected $guarded = []; // FATAL MISTAKE!
}

// Controller:
public function update(Request $request, User $user) {
    // Attacker payload sends:
    // name="Ali"
    // is_admin=1           <-- Injected!
    // email_verified_at=now <-- Injected!
    // balance=999999       <-- Injected!

    $user->update($request->all()); // Attacker superadmin ban gaya!
}
✅ SECURE ($fillable + validated())
phpSecureUserController.php
<?php

// Model explicitly whitelists allowed columns
class User extends Model {
    protected $fillable = [
        'name',
        'email',
        'phone',
        'avatar_url',
    ];
}

// Controller:
public function update(UpdateUserRequest $request, User $user) {
    // ->validated() sirf FormRequest rules ke fields return karta hai
    $user->update($request->validated());
    // is_admin ya balance silently discard ho jayenge!
}
✅ Enterprise Best Practice: Form Requests + $fillable + Strict Dev Mode

Production-grade Laravel applications mein validation aur model defense layer dono milkar kaam karti hain:

phpapp/Http/Requests/StoreProductRequest.php
<?php

namespace AppHttpRequests;

use IlluminateFoundationHttpFormRequest;

class StoreProductRequest extends FormRequest
{
    public function authorize(): bool
    {
        // Authorization check: Only staff or sellers can create products
        return $this->user()?->can('create', AppModelsProduct::class) ?? false;
    }

    public function rules(): array
    {
        return [
            'name'        => ['required', 'string', 'max:255'],
            'sku'         => ['required', 'string', 'unique:products,sku'],
            'price'       => ['required', 'numeric', 'min:0.01'],
            'stock'       => ['required', 'integer', 'min:0'],
            'category_id' => ['required', 'exists:categories,id'],
            'description' => ['nullable', 'string', 'max:5000'],
        ];
        // Notice: 'internal_margin', 'is_promoted', 'vendor_payout' yahan nahi hain!
    }
}
phpapp/Providers/AppServiceProvider.php (Catching Silent Bugs in Dev)
<?php

namespace AppProviders;

use IlluminateDatabaseEloquentModel;
use IlluminateSupportServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        /*
         * SENIOR PRO-TIP:
         * Agar kisi ne galti se un-fillable attribute pass kiya,
         * toh development/local environment mein exception throw karo
         * taaki silent data loss na ho, lekin production mein crash mat hone do.

        Model::preventLazyLoading(! $this->app->isProduction());

🔑 Broken Authentication & IDOR — A07 / A01

CRITICAL Weak password policies, unhashed credentials, session fixation attacks, aur IDOR (Insecure Direct Object Reference) hackers ke sabse aasan darwaze hain.

🔒 Modern Password Security & Have I Been Pwned? Integration

Laravel ka built-in Password validation rule passwords ko dictionary attacks aur compromised database leaks ke khilaf check karta hai:

phpapp/Providers/AppServiceProvider.php (Global Password Rules)
<?php

namespace AppProviders;

use IlluminateSupportServiceProvider;
use IlluminateValidationRulesPassword;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        // Production mein airtight enterprise password rules set karo
        Password::defaults(function () {
            $rule = Password::min(10)
                ->letters()          // Kam az kam 1 alphabet
                ->mixedCase()        // Uppercase aur lowercase dono
                ->numbers()          // Kam az kam 1 number
                ->symbols();         // Special characters (@, #, $, etc.)

            /*
             * uncompromised() Have I Been Pwned API par k-Anonymity SHA-1 hash bhejta hai.
             * Agar password pehle kisi public data breach mein leak ho chuka hai,
             * toh user ko turant reject kar deta hai!
             */
            return $this->app->isProduction()
                ? $rule->uncompromised(3) // 3 ya zyada breaches mein leaked password block karo
                : Password::min(6);
        });
    }
}
phpAuthController.php (Registration Rule Usage)
// Controller validation mein clean default rules use karein

<?php

namespace AppPolicies;

use AppModelsOrder;
use AppModelsUser;

class OrderPolicy
{
    /**
     * Sirf wahi user apna order dekh sakta hai jiska order_id usse belong karta ho,

    public function view(User $user, Order $order): bool

    {

📱 Session Hardening & Session Fixation Prevention

Session hijacking se bachne ke liye config/session.php ko enterprise standard par configure karein aur login par session ID regenerate karein:

return [

phpSecureUploadController.php (Airtight S3 & MIME Defense)
<?php

namespace AppHttpControllers;

use AppModelsProduct;
use IlluminateHttpRequest;
use IlluminateSupportFacadesStorage;
use IlluminateSupportStr;

class ProductImageController extends Controller
{
    public function upload(Request $request, Product $product)
    {
        // 1. Multi-layer validation (MIME sniffing + Size limits + Dimensions)
        $request->validate([
            'image' => [
                'required',
                'file',
                // mimes rule magic bytes (file header) read karta hai, extension nahi
                'mimes:jpeg,jpg,png,webp',
                'max:2048', // Max 2MB (Storage DoS prevention)
                'dimensions:min_width=200,min_height=200,max_width=4000,max_height=4000',
            ],
        ]);

        $file = $request->file('image');

        // 2. Original client filename kabhie use na karein (Path Traversal attack prevention!)
        // Cryptographically secure random UUID / hash generate karein
        $safeName = Str::uuid() . '.' . $file->guessExtension();

        // 3. Kabhie bhi public/ storage mein executeable permissions na dein
        // S3 bucket ya private storage disk mein store karein
        $path = $file->storeAs('products/' . $product->id, $safeName, 's3');

        // 4. Image processing library se EXIF metadata strip off karein (embedded payloads safety)
        // Intervention image parse karti hai aur re-encode karti hai

        $product->images()->create([
            'disk'      => 's3',
            'file_path' => $path,
            'mime_type' => $file->getMimeType(),
            'size_kb'   => round($file->getSize() / 1024, 2),
        ]);

        return response()->json([
            'success' => true,
            'url'     => Storage::disk('s3')->temporaryUrl($path, now()->addMinutes(30)),
        ]);
    }
}

🛡️ Complete SecurityHeaders Middleware Implementation

Yeh custom middleware har HTTP response mein modern browser security directives attach karta hai:

phpapp/Http/Middleware/SecurityHeaders.php
<?php

namespace AppHttpMiddleware;

use Closure;
use IlluminateHttpRequest;

class SecurityHeaders
{
    public function handle(Request $request, Closure $next)
    {
        $response = $next($request);

        // 1. MIME Sniffing Block: Browser ko file type guess karne se roko
        $response->headers->set('X-Content-Type-Options', 'nosniff');

        // 2. Clickjacking Shield: Website ko doosri sites ke iframe mein khulne se roko
        $response->headers->set('X-Frame-Options', 'DENY');

        // 3. Legacy Browser XSS Filter
        $response->headers->set('X-XSS-Protection', '1; mode=block');

        // 4. HSTS (Strict-Transport-Security): 1 saal ke liye HTTPS strictly enforce karo
        if ($request->isSecure() || app()->isProduction()) {
            $response->headers->set(
                'Strict-Transport-Security',
                'max-age=31536000; includeSubDomains; preload'
            );
        }

        // 5. Referrer Policy: Third-party sites ko internal URLs ka leak hona roko
        $response->headers->set('Referrer-Policy', 'strict-origin-when-cross-origin');

        // 6. Permissions Policy: Unused hardware sensors (camera, mic, geo) block karo
        $response->headers->set(
            'Permissions-Policy',
            'camera=(), microphone=(), geolocation=(), payment=(self)'
        );

        // 7. Server fingerprint headers strip off karo (Reconnaissance Defense)
        $response->headers->remove('X-Powered-By');
        $response->headers->remove('Server');

        return $response;
    }
}

📋 Nginx Web Server Security Configuration

Agar kisi ne web server configuration mein mistake ki toh attacker direct browser se https://yoursite.com/.env download kar lega! Nginx level par ye defensive block rules apply karein:

nginx/etc/nginx/sites-available/shopsphere.conf
server {
    listen 443 ssl http2;
    server_name shopsphere.com;
    root /var/www/shopsphere/public;

    index index.php;

    # ✅ RULE 1: Block hidden files (.env, .git, .htaccess) completely!
    location ~ /. {
        deny all;
        access_log off;
        log_not_found off;
    }

    # ✅ RULE 2: Sensitive system file extensions block karo
    location ~ .(ini|log|conf|sh|sql|bak|swp)$ {
        deny all;
    }

    # ✅ RULE 3: Public uploads folder mein PHP execution strictly block karo!
    location /storage {
        location ~ .php$ {
            deny all;
        }
        try_files $uri =404;
    }

    # ✅ RULE 4: Standard PHP-FPM execution route
    location ~ .php$ {
        fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }
}
