🌐 API Resources Kyun Zaroori Hain? (The Decoupling Layer)

Direct Eloquent model return karna ek fatal security aur architectural blunder hai. Jaaniye kaise API Resources aapke database schema ko public mobile/frontend consumers se protect karte hain.

⚠️ The Direct Model Return Disaster

Jab junior developers return response()->json($user); likhte hain, toh teen massive problems paida hoti hain:

❌ Antipattern: Direct Model Return

phpUserController.php (Antipattern)
// Controller — Fatal flaw! Database columns leak ho jati hain
public function show(User $user) {
    return response()->json($user);
}
  • Sensitive Data Leaks: stripe_id, two_factor_secret, ya internal audit columns galti se JSON mein nikal jate hain.
  • Breaking Mobile Apps: Agar kal aapne database migration mein full_name ko name kiya, toh published iOS/Android apps turant crash ho jayengi!
  • Formatting Chaos: Prices kabhi "1200.00" string hoti hain, kabhi 1200 integer. Dates kabhi timestamp hoti hain kabhi non-standard string.

✅ Production Pattern: Laravel API Resource

phpUserController.php (Production Standard)
// Controller — Clean contract! Sirf explicit fields return hoti hain
public function show(User $user) {
    return new UserResource($user);
}
  • 100% Strict Contract: Sirf wahi fields bahar jayengi jo aapne explicitly whitelist ki hain. Zero accidental leaks!
  • Schema Independence: Database column ka naam kuch bhi ho, JSON key ka naam wahi rahega jo frontend expect karta hai.
  • Consistent Formatting: ISO 8601 dates, formatted currencies, aur nested relations hamesha predictable format mein aate hain.
🏛️ The 3-Tier API Architecture

1. Database Layer

MySQL/Postgres tables, migrations, raw columns, foreign keys, aur indexes. Ye internal details hain jo sirf backend ko pata honi chahiye.

2. Eloquent Model Layer

Business logic, relationships, scopes, mutators, aur domain events. Model ka kaam business rules chalana hai, JSON format banana nahi.

3. API Resource Layer (Presenter)

Public API Contract! Model data ko transform karke client-facing clean JSON shape deta hai. Is layer ke badalne se database par koi asar nahi padta.

📜 Production Implementation: OrderResource

Dekhiye kaise whenLoaded() aur conditional attributes enterprise level par data expose karte hain:

phpapp/Http/Resources/OrderResource.php
<?php

namespace AppHttpResources;

use IlluminateHttpRequest;
use IlluminateHttpResourcesJsonJsonResource;

class OrderResource extends JsonResource
{
    /**
     * Transform the resource into an array.
     */
    public function toArray(Request $request): array
    {
        return [
            'id'           => (string) $this->uuid, // Never expose auto-increment integer IDs!
            'order_number' => $this->order_number,
            'status'       => $this->status,
            
            // Consistent monetary formatting
            'pricing' => [
                'subtotal'     => (float) $this->subtotal,
                'tax'          => (float) $this->tax_amount,
                'total'        => (float) $this->total,
                'currency'     => 'PKR',
                'formatted'    => 'PKR ' . number_format($this->total, 2),
            ],

            /*
             * CRITICAL: whenLoaded() - The N+1 Shield!
             * Agar controller ne eager load nahi kiya (e.g. ->with('items')),
             * toh ye key response se gayab ho jayegi. Ye kabhie bhi background
             * mein database query fire nahi karega!
             */
            'customer' => new UserResource($this->whenLoaded('user')),
            'items'    => OrderItemResource::collection($this->whenLoaded('items')),

            // Conditional Attribute: Sirf Admin users ko internal profit margin dikhao
            'admin_metrics' => $this->when($request->user()?->isAdmin(), [
                'profit_margin'  => (float) $this->profit_margin,
                'gateway_fee'    => (float) $this->gateway_fee,
                'warehouse_code' => $this->warehouse_code,
            ]),

            // Strict ISO 8601 Datetime standard
            'placed_at'  => $this->created_at?->toIso8601String(),
            'updated_at' => $this->updated_at?->toIso8601String(),
        ];
    }
}

❌ Galti: Direct Relation Call

phpDangerous N+1 Leak
'items' => OrderItemResource::collection($this->items),

Agar 50 orders list ho rahe hain, toh ye har order ke liye database mein alag se query karega (50 extra queries N+1 disaster!).

✅ Sahi Tarika: whenLoaded() Shield

phpProtected whenLoaded

Sirf tabhi include hoga jab controller ne with('items') se eager load kiya ho. Zero hidden queries!

📜 Production OrderCollection with Top-Level Envelopes

Dekhiye kaise OrderCollection pagination ke sath top-level summary metrics provide karta hai:

phpapp/Http/Resources/OrderCollection.php
<?php

namespace AppHttpResources;

use IlluminateHttpRequest;
use IlluminateHttpResourcesJsonResourceCollection;

class OrderCollection extends ResourceCollection
{
    /**
     * Specify the underlying resource class for each item.
     */
    public $collects = OrderResource::class;

    public function toArray(Request $request): array
    {
        return [
            'data' => $this->collection,
        ];
    }

    /**
     * Add top-level metadata outside the paginated 'data' array.
     */
    public function with(Request $request): array
    {
        return [
            'api_version' => 'v1.4',
            'server_time' => now()->toIso8601String(),
            'status'      => 'success',
        ];
    }
}
🔗 API Versioning: URI vs Header Versioning

Mobile apps ko bina crash kiye API contracts ko evolve karne ke architectural strategies — V1 aur V2 ko side-by-side run karna.

⚠️ Versioning Kyun Mandatory Hai? (The App Store Problem)

Web applications mein aap code deploy karte hain toh sabhi users ko naya JavaScript bundle mil jata hai. Lekin Mobile Apps (iOS/Android) mein hazaron users app ko mahinon tak update nahi karte. Agar aapne API response ka structure change kiya bina versioning ke, toh puraane users ki app crash ho jayegi!

🚀 Strategy 1: URI Versioning (Production Industry Standard)

Stripe, Shopify, aur GitHub sabse zyada URI versioning use karte hain kyunki ye transparent, debuggable, aur predictable hoti hai:

phproutes/api.php
use IlluminateSupportFacadesRoute;

/*
|--------------------------------------------------------------------------
| API Version 1 Routes (/api/v1/...)
|--------------------------------------------------------------------------
| Mobile App Version 1.0 — 1.5 ke liye stable legacy contract.
*/
Route::prefix('v1')
    ->name('api.v1.')
    ->namespace('AppHttpControllersApiV1')
    ->group(function () {
        Route::apiResource('products', 'ProductController');
        Route::apiResource('orders', 'OrderController');
    });

/*
|--------------------------------------------------------------------------
| API Version 2 Routes (/api/v2/...)
|--------------------------------------------------------------------------
| New Features: Multi-currency, GraphQL-style partials, new checkout schema.
*/
Route::prefix('v2')
    ->name('api.v2.')
    ->namespace('AppHttpControllersApiV2')
    ->group(function () {
        Route::apiResource('products', 'ProductController');
        Route::apiResource('orders', 'OrderController');
    });

⏱️ Dynamic Tiered Rate Limiting

Bots, scrapers aur brute-force attacks se APIs ko shield karna — Guest, Customer aur Enterprise API Keys ke liye tiered rate limits.

🛡️ Tiered Rate Limiter Configuration

In modern Laravel, configure dynamic rate limits inside AppServiceProvider (ya RouteServiceProvider) based on user authentication status and role:

phpapp/Providers/AppServiceProvider.php
use IlluminateCacheRateLimitingLimit;
use IlluminateHttpRequest;
use IlluminateSupportFacadesRateLimiter;

public function boot(): void
{
    RateLimiter::for('api', function (Request $request) {
        $user = $request->user();

        // 1. Enterprise / Merchant API Key: 1,200 requests/min
        if ($user?->tokenCan('enterprise-tier')) {
            return Limit::perMinute(1200)->by($user->id);
        }

        // 2. Logged-in Customer: 300 requests/min
        if ($user) {
            return Limit::perMinute(300)->by($user->id);
        }

        // 3. Anonymous Guest: 60 requests/min by Client IP
        return Limit::perMinute(60)
            ->by($request->ip())
            ->response(function (Request $request, array $headers) {
                return response()->json([
                    'error'       => 'Too Many Requests',
                    'message'     => 'Aapne rate limit exceed kar di hai. Kripya thodi der baad koshish karein.',
                    'retry_after' => $headers['Retry-After'] ?? 60,
                ], 429, $headers);
            });
    });
}

🔐 Sanctum Tokens & Granular Abilities

Mobile apps aur third-party integrations ke liye secure Personal Access Tokens, granular permission scopes (abilities), aur revocation management.

🔑 Generating Scoped Personal Access Tokens

Kabhie bhi mobile app ya third-party webhook ko full-access token mat dijiye. Hamesha Least Privilege principle follow karte hue specific abilities assign karein:

phpapp/Http/Controllers/Api/AuthController.php
use AppModelsUser;
use IlluminateHttpRequest;
use IlluminateSupportFacadesHash;

public function login(Request $request)
{
    $request->validate([
        'email'       => 'required|email',
        'password'    => 'required',
        'device_name' => 'required|string',
    ]);

    $user = User::where('email', $request->email)->first();

    if (! $user || ! Hash::check($request->password, $user->password)) {
        return response()->json([
            'error' => 'Invalid credentials provided.',
        ], 401);
    }

    // Assign specific abilities based on user role
    $abilities = ['orders:read', 'profile:update'];
    if ($user->isVendor()) {
        $abilities[] = 'products:manage';
    }

    // Generate token (only displayed once!)
    $token = $user->createToken($request->device_name, $abilities)->plainTextToken;

    return response()->json([
        'token'     => $token,
        'token_type' => 'Bearer',
        'abilities'  => $abilities,
    ]);
}
🛡️ Protecting Endpoints with Abilities Middleware
phproutes/api.php
use IlluminateSupportFacadesRoute;

Route::middleware(['auth:sanctum'])->group(function () {
    // Har user apni orders dekh sakta hai
    Route::get('/orders', [OrderController::class, 'index'])
        ->middleware('ability:orders:read');

    // Sirf 'products:manage' ability wale tokens product create kar sakte hain
    Route::post('/products', [ProductController::class, 'store'])
        ->middleware('ability:products:manage');

    // Logout current device only
    Route::post('/logout', function (Request $request) {
        $request->user()->currentAccessToken()->delete();
        return response()->json(['message' => 'Current device token revoked.']);
    });

    // Force logout all devices (password reset security event)
    Route::post('/logout-all-devices', function (Request $request) {
        $request->user()->tokens()->delete();
        return response()->json(['message' => 'All active device sessions terminated.']);
    });
});
🛡️ Standardized Error Contracts & Exception Handling

Consistent, predictable error JSON responses create happy frontend teams and prevent sensitive SQL database leaks.

⚠️ The Problem of Inconsistent Error Formats

Agar aapki API kabhi HTML exception page return kare, kabhi {"message": "..."}, aur kabhi {"errors": [...]}, toh React/Flutter frontend developers ko har request ke liye alag error handling likhni padti hai. Hamesha ek Standard Enterprise Error Contract maintain karein:

jsonShopSphere Pro Enterprise Error Contract

    "details": []
  },

🔧 Centralized Exception Rendering (Laravel 11 bootstrap/app.php)

Laravel 11 mein centralized exceptions ko bootstrap/app.php ke withExceptions() callback mein handle kiya jata hai:

phpbootstrap/app.php
use IlluminateDatabaseEloquentModelNotFoundException;
use IlluminateValidationValidationException;
use SymfonyComponentHttpKernelExceptionNotFoundHttpException;

->withExceptions(function (Exceptions $exceptions) {
    // Catch 404 Model Not Found (Never leak raw database table names!)
    $exceptions->render(function (NotFoundHttpException $e, $request) {
        if ($request->is('api/*')) {
            return response()->json([
                'success'   => false,
                'error'     => [
                    'code'    => 'RESOURCE_NOT_FOUND',
                    'message' => 'Manga gaya resource maujood nahi hai.',
                ],
                'timestamp' => now()->toIso8601String(),
            ], 404);
        }
    });

    // Catch 422 Validation Errors with clean key-value map
    $exceptions->render(function (ValidationException $e, $request) {
        if ($request->is('api/*')) {
            return response()->json([
                'success'   => false,
                'error'     => [
                    'code'    => 'VALIDATION_FAILED',
                    'message' => 'Input validation fail ho gaya.',
                    'fields'  => $e->errors(),
                ],
                'timestamp' => now()->toIso8601String(),
            ], 422);
        }
    });
})

⚡ JsonResource Methods Quick Reference
Relationship Protection
