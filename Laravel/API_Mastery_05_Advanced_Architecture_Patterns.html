Architecture Review

1. The "Fat Controller" Anti-Pattern

Junior level par, e-commerce checkout ka API method aesa dikhta hai:

CheckoutController.php (Bad)
public function store(Request $request)
{
    // 1. Validation mixed in controller
    $request->validate([...]);
    
    // 2. Business logic mixed in controller
    $cart = Cart::where('user_id', $request->user()->id)->first();
    if (!$cart) { return response()->json(['error'=>'Empty']); }
    
    // 3. External API calls
    $payment = Stripe::charge($request->token, $cart->total);
    
    // 4. DB Operations
    $order = Order::create([...]);
    
    // 5. Sending Emails
    Mail::to($request->user())->send(new OrderConfirmation($order));
    
    return response()->json($order);
}

⚠️ Why is this bad?

Testability zero hai. Code reusability nahi hai. Agar same logic CLI artisan command ya background job se call karni ho, toh aapko pura logic copy-paste karna padega.

Expert Pattern

2. Data Transfer Objects (DTOs)

Arrays pass karna (e.g. $data = $request->validated()) PHP mein safe nahi hai. Array mein keys typo ho sakti hain aur IDE auto-completion kaam nahi karta.

Solution: DTOs. Ek simple class jo sirf strongly typed data hold karti hai.

app/DTOs/Order/CreateOrderDTO.php
namespace App\DTOs\Order;

use Illuminate\Http\Request;

readonly class CreateOrderDTO
{
    public function __construct(
        public int $userId,
        public string $stripeToken,
        public string $shippingAddress,
        public ?string $discountCode = null
    ) {}

    // Factory method to build DTO from Request
    public static function fromRequest(Request $request): self
    {
        return new self(
            userId: $request->user()->id,
            stripeToken: $request->validated('stripe_token'),
            shippingAddress: $request->validated('shipping_address'),
            discountCode: $request->validated('discount_code')
        );
    }
}
Expert Pattern

3. Action Classes

Ek Controller method ek "Action" hai. Is logic ko ek dedicated single-responsibility class mein move karein jisse hum Action Class kehte hain. (Some call it Service layer, but Action classes are more granular).

app/Actions/Order/ProcessCheckoutAction.php
namespace App\Actions\Order;

use App\DTOs\Order\CreateOrderDTO;
use App\Models\Order;
use Illuminate\Support\Facades\DB;

class ProcessCheckoutAction
{
    public function execute(CreateOrderDTO $dto): Order
    {
        // Use DB transaction so if payment fails, order isn't saved
        return DB::transaction(function () use ($dto) {
            
            // 1. Calculate total from DB
            $total = $this->calculateCartTotal($dto->userId, $dto->discountCode);
            
            // 2. Charge via Stripe 
            $paymentId = StripeService::charge($dto->stripeToken, $total);
            
            // 3. Create Order Model
            $order = Order::create([
                'user_id' => $dto->userId,
                'total' => $total,
                'transaction_id' => $paymentId,
                'address' => $dto->shippingAddress
            ]);
            
            // 4. Dispatch async job for emails (Don't delay the API!)
            dispatch(new SendOrderConfirmationJob($order));
            
            return $order;
        });
    }
}

💡 Key Takeaway

Ye Action class API se bilkul anjaan hai. Isay nahi pata HTTP request kya hai. Ye class ab CLI command se, WebSocket se, ya Background job se independently call ki ja sakti hai!

The Final Result

4. Bringing It All Together

Ab dekhte hain aapka Controller kaisa dikhta hai jab usme se Form Request, DTO, aur Action class nikal di gayi ho.

app/Http/Controllers/Api/CheckoutController.php
namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Http\Requests\Api\CheckoutRequest;
use App\DTOs\Order\CreateOrderDTO;
use App\Actions\Order\ProcessCheckoutAction;
use App\Http\Resources\OrderResource;

class CheckoutController extends Controller
{
    // Dependency injection of the Action class
    public function store(CheckoutRequest $request, ProcessCheckoutAction $action)
    {
        // 1. Build DTO from validated Request
        $dto = CreateOrderDTO::fromRequest($request);
        
        // 2. Execute business logic
        $order = $action->execute($dto);
        
        // 3. Return standardized API response
        return $this->successResponse(
            data: new OrderResource($order),
            message: 'Order processed successfully.',
            statusCode: 201
        );
    }
}

Mastery Level Unlocked: Ab aapka controller bas ek "Traffic Cop" ban gaya hai. Wo Request leta hai, DTO banata hai, Action ko deta hai, aur Resource return karta hai. That's beautiful API architecture.
