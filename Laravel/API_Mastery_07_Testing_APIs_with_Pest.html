Testing APIs with Pest

Bina tests ke code likhna production mein aag lagane ke barabar hai. Pest PHP Laravel ka naya testing framework hai jo tests ko English jaisa readable banata hai. Let's master API testing.

Testing

1. Why Pest over PHPUnit?

Laravel default PHPUnit use karta tha, par Laravel 11 se Pest default ban gaya hai. Pest ki syntax bohot elegant hai, exactly like Jest (JavaScript).

PHPUnit test aesa dikhta tha:

public function test_user_can_view_profile() { ... }

Pest mein same test aesa dikhta hai:

it('allows users to view their profile', function () { ... });

Benefits

No boilerplate classes, parallel execution fast hai, aur expectation API (expect($var)->toBeTrue()) bohot natural lagti hai.

Implementation

2. Feature Testing Endpoints

API endpoints ko test karne ke liye hum Feature Tests likhte hain. Ye real database (in-memory SQLite) use karte hain aur pura HTTP cycle check karte hain.

tests/Feature/Api/OrderTest.php
use App\Models\User;
use function Pest\Laravel\{actingAs, postJson, getJson};

it('requires authentication to create order', function () {
    postJson('/api/v1/orders', [])
        ->assertStatus(401);
});

it('creates an order successfully', function () {
    // 1. Arrange
    $user = User::factory()->create();
    $payload = [
        'stripe_token' => 'tok_visa',
        'shipping_address' => '123 Main St'
    ];

    // 2. Act & Assert
    actingAs($user)
        ->postJson('/api/v1/orders', $payload)
        ->assertStatus(201)
        ->assertJson([
            'success' => true,
            'message' => 'Order processed successfully.'
        ]);
        
    // Verify Database state
    assertDatabaseHas('orders', [
        'user_id' => $user->id,
        'address' => '123 Main St'
    ]);
});
Mastery

3. Asserting JSON Structure (Fluent API)

Hardcoding pura JSON array test mein buri practice hai. Laravel ek Fluent JSON Testing API provide karta hai, jo deep structure aur types check karne deta hai.

tests/Feature/Api/UserTest.php
use Illuminate\Testing\Fluent\AssertableJson;

it('returns the correct user resource structure', function () {
    $user = User::factory()->create();

    actingAs($user)
        ->getJson('/api/v1/profile')
        ->assertJson(fn (AssertableJson $json) =>
            $json->where('success', true)
                 ->has('data', fn ($data) => 
                     $data->where('id', $user->id)
                          ->has('full_name')
                          ->whereType('is_active', 'boolean')
                          ->missing('password') // Ensures sensitive data isn't leaked!
                          ->etc() // Allows other keys to exist
                 )
                 ->etc()
        );
});
Expert Architecture

4. Mocking External APIs

Tests run karte waqt aap kabhi bhi actual Stripe ya third-party APIs ko hit nahi karna chahte (paisa kategi ya rate limit trigger hogi). Hum Http::fake() use karte hain external calls ko mock karne ke liye.

tests/Feature/Api/StripePaymentTest.php
use Illuminate\Support\Facades\Http;

it('handles third party API failures gracefully', function () {
    
    // Intercept any HTTP request to Stripe and force it to return a 500 Error
    Http::fake([
        'api.stripe.com/*' => Http::response(['error' => 'Gateway timeout'], 500),
    ]);

    $user = User::factory()->create();

    actingAs($user)
        ->postJson('/api/v1/checkout', ['amount' => 100])
        ->assertStatus(503) // Service Unavailable
        ->assertJsonPath('message', 'Payment gateway is currently down.');
        
    // Ensure we actually tried calling Stripe
    Http::assertSent(function ($request) {
        return $request->url() == 'https://api.stripe.com/v1/charges';
    });
});

Final Tip for 4 YOE Devs

Aapki API ka test suite ek living documentation hona chahiye. Har endpoint ke liye at least ek Happy path aur ek Failure path (e.g. invalid validation) test likhna zaroori hai.
