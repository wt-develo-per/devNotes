📐 Core Concepts • Part 1 • The Big Debate

Interface vs Type Aliases

Donon lagbhag ek jaisa kaam karte hain (object ka shape define karna), lekin inke under-the-hood behaviors kaafi alag hote hain. Node.js backend mein kab kya use karein?

📐 `interface` (The Blueprint)

Hamesha sirf Objects (ya classes) ke liye use hota hai. Iski ek special property hoti hai: "Declaration Merging". Yani aap same naam ke do interfaces bana sakte hain, aur wo automatically merge ho jayenge.
Best for: Database Entity definitions, Express Request objects ko extend karna.

🏷️ `type` (The Alias)

Type koi naya blueprint nahi banata, sirf kisi bhi type ka "nickname" rakhta hai. Ye primitive (string/number), union, aur tuples ke liye use ho sakta hai.
Best for: Complex unions (e.g. `Success | Error`), utility types, ya simple primitives ko naam dena.

TypeScript • Syntax Differences 
// --- INTERFACE EXAMPLE ---
interface User {
    id: number;
    email: string;
}

// Declaration Merging (Only works with Interface!)
interface User {
    createdAt: Date;
}
// Now 'User' automatically has id, email, AND createdAt. 
// This is exactly how we add 'req.user' to Express!


// --- TYPE ALIAS EXAMPLE ---
type Status = 'PENDING' | 'ACTIVE'; // You CANNOT do this with interface!

type Product = {
    id: number;
    price: number;
}

// type Product = { name: string } ❌ ERROR! Duplicate identifier 'Product'

💡 Pro Tip for Backend

API Response payloads, Database schemas (Prisma/TypeORM models), aur external libraries ko extend karne ke liye hamesha interface use karein. Baaki choti moti unions aur primitives ke liye type use karein.

🔗 Types Composition • Part 2 • Connecting Shapes

Union (|) & Intersection (&)

TypeScript ki sabse badi power hai types ko jodne (combine karne) ki ability.

Union (OR) |
Yeh variable either Type A ka ho sakta hai YA Type B ka. Zyadatar API responses jahan `SuccessData` ya `ErrorData` return hota hai.
Intersection (AND) &
Yeh variable ko dono Type A AUR Type B ki sabhi properties fulfill karni padengi. Multiple interfaces ko merge karke bada object banane ke kaam aata hai.
TypeScript • Unions & Intersections 
// 1. UNION TYPES (One or the other)
type StringOrNumber = string | number;

function getUserId(id: StringOrNumber) {
    // Agar id string hai toh uppercase karein, warna string me convert karein
    if (typeof id === 'string') {
        return id.toUpperCase();
    }
    return id.toString();
}

// 2. INTERSECTION TYPES (Combine multiple objects)
interface Timestamps {
    createdAt: Date;
    updatedAt: Date;
}

interface Document {
    title: string;
    content: string;
}

// Combine both!
type DatabaseDocument = Document & Timestamps;

const article: DatabaseDocument = {
    title: "TypeScript Guide",
    content: "...",
    createdAt: new Date(),
    updatedAt: new Date()
};
⚠️ Safety Overrides • Part 3 • Type Assertions

Type Assertions (`as`)

Kabhi kabhi developer TS Compiler se zyada janta hai (For example, DOM events ya DB raw queries). Wahan hum TS ko force karte hain ki "Trust me, main janta hu iska type kya hai".

⚠️ Warning: "as" can be dangerous!

Type assertion runtime pe data change nahi karta, yeh sirf compile-time par error chupata hai. Agar data aapke assertion se match nahi karta, toh Node.js crash ho sakta hai! Use it rarely.

TypeScript • Type Assertion 
const rawJsonResponse = '{"name":"Pankaj", "role":"admin"}';
const parsedData = JSON.parse(rawJsonResponse); // Type is 'any'

// Hamein pata hai ki ye string aayega, let's tell TS:
interface ParsedUser {
    name: string;
    role: string;
}

// Way 1: using 'as' (Recommended)
const user = parsedData as ParsedUser;
console.log(user.name); 

// ❗ The Non-Null Assertion Operator (!)
// Sometimes TS thinks something might be null/undefined, but you know it isn't.
let jwtSecret: string | undefined = process.env.JWT_SECRET;

// Using ! tells TS: "I guarantee this will NEVER be null/undefined"
const secretForToken: string = jwtSecret!;
🛡️ Runtime Checks • Part 4 • Narrowing

Type Guards (Safe Narrowing)

Jab ek variable `Union` type ka hota hai (A | B), toh usko properly handle karne ke liye "Type Guards" (if statements) use karne padte hain. Isko TypeScript mein "Narrowing" kehte hain.

1. `typeof` Guard

Primitives ke liye (string, number, boolean) use karein.
if (typeof value === 'string')

2. `in` Guard

Objects ke liye check karta hai ki kya us object mein koi specific property exist karti hai ya nahi.
if ('email' in userObj)

TypeScript • Type Guards 
interface Admin {
    name: string;
    privileges: string[];
}

interface Employee {
    name: string;
    startDate: Date;
}

type UnknownUser = Admin | Employee;

function printUserInfo(user: UnknownUser) {
    // console.log(user.privileges); ❌ ERROR: Property 'privileges' does not exist on type 'Employee'.
    
    // Type Guard using 'in'
    if ('privileges' in user) {
        // In this block, TS knows 100% that 'user' is an Admin!
        console.log(`Admin privileges: ${user.privileges.join(', ')}`);
    } else {
        // In this block, TS knows it MUST be an Employee!
        console.log(`Employee started on: ${user.startDate}`);
    }
}
