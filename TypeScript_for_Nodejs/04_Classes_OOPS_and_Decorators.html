🧱 Structure • Part 1 • Access Modifiers

TypeScript OOPs (Public, Private, Protected)

Vanilla JS classes mein sab kuch public hota hai. TypeScript aapko data encapsulation deta hai.

🟢 public (Default)
Class ke andar aur bahar kahin se bhi access kiya ja sakta hai.
🔴 private
Sirf usi class ke methods use kar sakte hain. Instance (object) se direct access nahi hota. Good for internal state.
🟠 protected
Class ke andar AUR un classes mein jo isko extend karti hain (child classes) wahan access allowed hai.
TypeScript • Class Constructor Shortcut 
class DatabaseService {
    // 'readonly' means it can only be set once inside the constructor
    private readonly connectionString: string;
    public isConnected: boolean = false;

    constructor(url: string) {
        this.connectionString = url;
    }

    public connect() {
        console.log(`Connecting to ${this.connectionString}`);
        this.isConnected = true;
    }
}

// 💡 THE TS SHORTCUT (Parameter Properties)
// Constructor mein access modifier lagane se TS automatically 
// usko class property bana deta hai aur assign bhi kar deta hai!
class UserService {
    constructor(
        private db: DatabaseService,  // Auto-assigned!
        public tableName: string = "users"
    ) {}

    public fetchUsers() {
        // this.db is perfectly available here!
    }
}
📐 Architecture • Part 2 • Contracts

Implements vs Extends

Backend architecture (Solid principles) mein Interface ek "Contract" ki tarah kaam karta hai. Classes us contract ko `implement` karti hain.

TypeScript • Interfaces for Classes 
// Contract: Any Logger class MUST have these two methods.
interface ILogger {
    log(message: string): void;
    error(message: string): void;
}

// implements: "Main promise karta hu ki main ILogger ki saari shartein manunga"
class ConsoleLogger implements ILogger {
    public log(message: string) {
        console.log(`[INFO]: ${message}`);
    }
    
    public error(message: string) {
        console.error(`[ERROR]: ${message}`);
    }
}

// Ab aap easily dependency injection kar sakte hain!
class OrderController {
    // Yahan humne class ka naam nahi, Interface ka naam diya.
    // Isse hum kal ko "ConsoleLogger" ki jagah "FileLogger" bhej sakte hain bina code change kiye!
    constructor(private logger: ILogger) {}
}
✨ Metaprogramming • Part 3 • The Magic Symbol

What are Decorators (`@`)?

Agar aapne NestJS, TypeORM, ya Angular dekha hai, toh wahan @Get() ya @Entity() use hota hai. Yeh Decorators hain.

🤔 Simple Definition

Decorator ek normal JavaScript function hota hai jo ek Class, Method, ya Property ke upar lagaya jata hai usko modify ya track karne ke liye. Yeh aapko boilerplate code chupa kar metaprogramming karne deta hai.

Note: Decorators use karne ke liye tsconfig.json mein "experimentalDecorators": true on karna zaruri hai.

TypeScript • Creating a basic Class Decorator 
// 1. Humne ek Decorator function banaya
function Timestamped(constructor: Function) {
    // Hum dynamically class ke andar ek property add kar rahe hain!
    constructor.prototype.createdAt = new Date();
}

// 2. Usko Class ke upar use kiya
@Timestamped
class Article {
    constructor(public title: string) {}
}

const doc = new Article("TypeScript Decorators");
// TS compiler won't know about createdAt directly unless casted,
// but at runtime doc.createdAt will have the current Date!
console.log((doc as any).createdAt);
🚀 Framework Level • Part 4 • Under the Hood

Decorators in Action (Method Decorators)

Frameworks route handling (jaise @Get('/users')) aur validation ke liye Method decorators use karte hain. Chaliye ek simple `Execution Time Logger` decorator banate hain.

TypeScript • Measuring Execution Time via Decorator 
// Method Decorator function
function LogExecutionTime(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value; // The actual function (e.g., processData)

    // Hum us function ko override (wrap) kar rahe hain
    descriptor.value = async function (...args: any[]) {
        console.time(propertyKey); // Start timer
        
        const result = await originalMethod.apply(this, args); // Run actual function
        
        console.timeEnd(propertyKey); // Stop timer & print
        return result;
    };
    return descriptor;
}

class DataProcessor {
    
    @LogExecutionTime
    async processData() {
        // Simulate heavy work
        await new Promise(resolve => setTimeout(resolve, 1500));
        return "Processing Complete";
    }
}

const processor = new DataProcessor();
// Output will automatically print: "processData: 1.503s" without writing console logs inside the method!
processor.processData();

✅ Why this is amazing for Backend Devs

Is approach se business logic (apka asli code) bilkul saaf rehta hai. Validation, Logging, Authentication checks... sab aap Decorators (`@IsAdmin()`, `@Validate()`) ke through method ke upar add kar sakte hain. Yehi NestJS ka core design pattern hai!
