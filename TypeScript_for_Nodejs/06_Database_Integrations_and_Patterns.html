🗄️ Persistence • Part 1 • The Database Bridge

TypeScript ORMs (TypeORM vs Prisma)

Backend app bina database ke adhoori hai. TypeScript mein Sequelize purana ho chuka hai, aaj kal TypeORM aur Prisma rule kar rahe hain.

🛡️ TypeORM (The OOP Way)

TypeORM completely Classes aur Decorators par based hai. Ye NestJS ka default choice hai.
Syntax: @Entity() class User { @PrimaryGeneratedColumn() id: number; }

💎 Prisma (The Modern Way)

Prisma decorators use nahi karta. Aap ek schema.prisma file mein database design karte hain, aur Prisma automatically aapke liye TypeScript Types generate karta hai.
Currently the most loved ORM by Node.js developers.

💡 How Prisma saves you time

Prisma automatically har model ke liye ek TypeScript Interface bana deta hai.
For example, aap directly import { User } from '@prisma/client' kar sakte hain, aur us Type ko apne Express controllers aur functions mein use kar sakte hain bina manully Interface likhe!

🚨 Architecture • Part 2 • Standardizing Fails

Custom Error Classes

Jab aap Node.js mein error throw karte hain (throw new Error("Not found")), toh usme HTTP Status code nahi hota. TypeScript OOPs ka use karke hum AppError class bana sakte hain.

TypeScript • Extending the Error Class 
// 1. Hum native Error class ko 'extend' (inherit) kar rahe hain
export class AppError extends Error {
    public readonly statusCode: number;
    public readonly isOperational: boolean;

    constructor(message: string, statusCode: number) {
        super(message); // Call parent Error constructor
        
        this.statusCode = statusCode;
        this.isOperational = true; // True matlab expected error (e.g. invalid password)

        // Capturing stack trace prevents constructor from polluting the trace
        Error.captureStackTrace(this, this.constructor);
    }
}

// 2. Usage in Controller
const findUser = async (id: number) => {
    const user = null; // DB Mock
    if (!user) {
        // Ab hum specific status code ke sath throw kar sakte hain!
        throw new AppError("User not found in Database", 404);
    }
};

Module 05 mein banaye gaye Global Error Handler mein aap if (err instanceof AppError) check karke user ko proper HTTP status send kar sakte hain, jabki baaki errors ko 500 (Internal Server Error) treat kar sakte hain.

⚠️ Security • Part 3 • The Illusion of Safety

Compile-Time vs Runtime Validation

TypeScript siraf code likhte waqt kaam aati hai (Compile-Time). Jab aapka Node.js server chal raha hota hai (Runtime), tab TypeScript gayab ho chuki hoti hai! Ye ek bahut bada security risk ban sakta hai.

❌ The "as" Trap

Maan lijiye aapne express mein likha: const body = req.body as CreateUserPayload;
TypeScript khush ho jayega aur errors nahi dega. Lekin jab Postman se koi hacker password ke bina request bhejega, toh server runtime pe fail ho jayega kyunki "as" keyword ne actually data validate nahi kiya, sirf type enforce kiya!

Isliye, humein Runtime par object shape validate karne ke liye Joi, Yup, ya sabse best: Zod ki zaroorat padti hai.

💎 The Ultimate Combo • Part 4 • Zod

Zod + TypeScript (Type Inference)

Zod ek schema declaration aur validation library hai. Iski sabse badi khasiyat ye hai ki aap schema banate hain, aur TypeScript automatically us schema se Type infer (generate) kar leta hai. Aapko Interface alag se likhne ki zaroorat nahi!

TypeScript • Zod Schema & Type Inference 
import { z } from 'zod';

// 1. Define the Runtime Validation Schema (ZOD)
const userSchema = z.object({
    username: z.string().min(3, "Username too short"),
    email: z.string().email(),
    age: z.number().optional()
});

// 2. THE MAGIC: Extract the TypeScript Type from the Schema!
// Ab aapko 'interface UserPayload { ... }' alag se likhne ki zarurat nahi!
type UserPayload = z.infer<typeof userSchema>;

/* TS implicitly knows that UserPayload is:
   {
      username: string;
      email: string;
      age?: number | undefined;
   }
*/

// 3. Express Controller Example
export const register = (req: Request, res: Response) => {
    try {
        // .parse() runtime pe check karega ki data sahi hai ya nahi
        // Agar sahi hai, toh 'validatedData' automatically 'UserPayload' type ka ban jayega!
        const validatedData = userSchema.parse(req.body);
        
        console.log(validatedData.email); // 100% Type Safe and Verified!
        res.json({ success: true });

    } catch (err) {
        // Zod errors are caught here (e.g. invalid email)
        res.status(400).json(err);
    }
};
