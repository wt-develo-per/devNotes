🧬 Foundations • Part 1 • The Unknown Variable

What the heck is <T>? (Generics)

Aap JavaScript function mein arguments (data) pass karte hain taaki function reusable ban jaye. Same tarike se, TypeScript mein hum Types ko pass karte hain as an argument (<T>) taaki Interfaces reusable ban jayein.

🤔 The Problem without Generics

Imagine ek function hai jo array ko reverse karta hai. Agar hum parameter arr: any[] rakhein, toh return aane par TS bhool jayega ki array ke andar elements kya the (Type inference toot jayega). Generics allow us to say: "Jo Type andar jaayega, wahi Type bahar aayega."

TypeScript • Basic Generic Function 
// 'T' is just a placeholder (variable name for a Type). You can call it 'Type', 'ItemType', etc.
function getFirstElement<T>(arr: T[]): T {
    return arr[0];
}

// Usage 1: Passes 'number' automatically (Type Inference)
const firstNumber = getFirstElement([10, 20, 30]); 
// TypeScript knows firstNumber is exactly of type 'number'

// Usage 2: Explicitly passing 'string'
const firstString = getFirstElement<string>(["A", "B", "C"]); 
// firstString is exactly 'string'
📡 Real World • Part 2 • Backend Payloads

Generic API Responses & DB Wrappers

Node.js APIs hamesha ek standard format (e.g. { success: true, data: ... }) follow karti hain. Hum Generics ka use karke is format ko DRY (Don't Repeat Yourself) bana sakte hain.

TypeScript • Generic Interface 
// Master Wrapper Interface
interface ApiResponse<T> {
    success: boolean;
    message: string;
    data: T; // This is dynamic!
}

interface User { id: number; name: string; }
interface Product { id: number; price: number; }

// User API Response
const userRes: ApiResponse<User> = {
    success: true,
    message: "User found",
    data: { id: 1, name: "Alex" } // TS enforces User shape here!
};

// Product List API Response
const productsRes: ApiResponse<Product[]> = {
    success: true,
    message: "Products loaded",
    data: [ { id: 101, price: 500 } ] // TS enforces Array of Products here!
};

💡 Pro Tip: Generic Database Services

ORM banate waqt aap ek Base Repository bana sakte hain jaise class BaseRepository<T> jisme findById(id: string): Promise<T> ek generic function ho. Isse aapko har Table ke liye `findById` dobara nahi likhna padega!

✂️ Time Savers • Part 3 • Built-in Utilities

Partial, Pick & Omit

Aksar database model me 20 columns hote hain, par jab hum Naya User banate hain toh `id` aur `createdAt` nahi bhejna hota. Kya humein ek naya Interface banana padega? Nahi! TypeScript utilities use karein.

TypeScript • Pick & Omit 
interface DatabaseUser {
    id: number;
    email: string;
    passwordHash: string;
    createdAt: Date;
}

// 1. OMIT (Remove specific fields)
// Perfect for POST payloads or DTOs (Data Transfer Objects)
type CreateUserPayload = Omit<DatabaseUser, 'id' | 'createdAt'>;
/* Resulting Type:
   { email: string, passwordHash: string }
*/

// 2. PICK (Select only specific fields)
// Perfect for Data returned to Frontend (hiding passwordHash)
type PublicProfile = Pick<DatabaseUser, 'id' | 'email'>;
/* Resulting Type:
   { id: number, email: string }
*/

// 3. PARTIAL (Makes everything optional '?' )
// Perfect for PATCH / Update payloads where user might update only 1 field
type UpdateUserPayload = Partial<CreateUserPayload>;
/* Resulting Type:
   { email?: string, passwordHash?: string }
*/
🗂️ Dictionaries • Part 4 • The Object Type

Record (Dynamic Keys)

Jab aapke object ki Keys pehle se fix na hon (e.g. Caching mapping, language dictionaries, configuration objects), toh Record<KeyType, ValueType> use karte hain.

❌ Avoid the `object` type

let config: object = {} ek bahut bekar practice hai. TS compiler allow nahi karega key access karna (config.port gives error) kyunki `object` empty shape signify karta hai.

✅ Use `Record`

Record<string, number> ka matlab hai "Koi bhi string key ho sakti hai, par value hamesha number hogi".

TypeScript • Record utility 
// A mapping of HTTP Status codes to their String messages
const HttpStatusNames: Record<number, string> = {
    200: "OK",
    404: "Not Found",
    500: "Internal Server Error"
};

// A User permissions matrix (Role mapping)
type Role = 'admin' | 'manager' | 'employee';

const permissions: Record<Role, boolean> = {
    admin: true,
    manager: true,
    employee: false
};
// TS Error: Agar humne 'employee' skip kiya toh compiler error dega!
