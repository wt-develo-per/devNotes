🚀 Fundamentals • Part 1 • The "Why"

Why TypeScript for Node.js Backend?

Jab JavaScript aasan hai aur bina compile kiye chalti hai, toh backend developers TypeScript ki taraf kyun shift ho rahe hain?

🛡️
Runtime Errors = 0
JS mein "Cannot read property 'email' of undefined" error server pe aane ke baad pata chalta hai. TS mein yeh error code likhte time (compile time) hi IDE pakad leta hai.
🧠
Auto-Complete Magic
Jab aap database query chalate hain, TS pehle se jaanta hai ki User object mein kaunsi properties hain. Postman check karne ki zaroorat nahi padti!

💡 The Compiler Mental Model

Node.js directly TypeScript execute nahi kar sakta (Deno aur Bun kar sakte hain, par Node nahi).
Iska matlab server.ts hamesha pehle transpile hota hai server.js mein, aur phir Node.js us .js file ko run karta hai. Types sirf development time ke liye hote hain, production JavaScript mein unka koi nishaan nahi hota!

⚙️ Configuration • Part 2 • Best Practices

Node.js Setup & The Golden tsconfig

TypeScript Node project start karna bahut simple hai. Hum development ke liye tsx ya ts-node-dev use karte hain, aur production ke liye compile karte hain.

BASH • Initializing a Project 
# 1. Initialize Node project
npm init -y

# 2. Install TypeScript and Node types as dev dependencies
npm install typescript @types/node tsx --save-dev

# 3. Initialize tsconfig.json
npx tsc --init

The Perfect tsconfig.json for Node.js (ES2022)

Default tsconfig.json bahut purani JavaScript generate karta hai. Backend developers ko hamesha Node ke latest features (like async/await without polyfills) use karne chahiye.

JSON • tsconfig.json 
{
  "compilerOptions": {
    /* Language and Environment */
    "target": "ES2022",         // Node 18+ natively supports ES2022
    "module": "CommonJS",       // Standard for Node.js (or NodeNext for ES Modules)
    "rootDir": "./src",         // Aapka TypeScript code kahan hai
    "outDir": "./dist",         // Compile hui JS file kahan jayegi

    /* Type Checking - Enable Strict Mode! */
    "strict": true,             // YEH SABSE ZARURI HAI!
    "noImplicitAny": true,      // 'any' ko prevent karta hai
    "strictNullChecks": true,   // "Cannot read property of undefined" se bachata hai

    /* Modules */
    "esModuleInterop": true,    // Import CommonJS packages smoothly
    "skipLibCheck": true,       // Speeds up compilation
    "forceConsistentCasingInFileNames": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}

🔥 Developer Tool: tsx

Pehle log `nodemon` + `ts-node` use karte the, jo kaafi slow tha. Ab modern Node.js apps mein npx tsx watch src/server.ts use hota hai. Yeh instantly compile aur reload karta hai (esbuild under the hood use karta hai).

🧱 Basics • Part 3 • Core Types

Basic Primitive Types

TypeScript implicitly types deduce (infer) kar leta hai, par API request/response mein humein explicit types define karne padte hain.

TypeScript • Basic Typing 
// Explicitly specifying types (Variable declaration)
let username: string = "alex_dev";
let age: number = 28;
let isActive: boolean = true;

// Type Inference (TS is smart, it knows this is a string)
let dbConnectionUrl = "postgres://user:pass@localhost:5432/mydb"; 
// You don't need to write ': string' here!

// Function typing: Type the arguments AND the return type
function calculateTax(amount: number, taxRate: number): number {
    return amount + (amount * taxRate);
}

// Optional parameters (using ?)
function logMessage(msg: string, userId?: number): void {
    if (userId) {
        console.log(`[User ${userId}]: ${msg}`);
    } else {
        console.log(`[System]: ${msg}`);
    }
}
📦 Collections • Part 4 • Structuring Data

Arrays, Tuples & Enums

Arrays aur Constants ko TypeScript mein strict boundary dena zaroori hai.

📚 Arrays

string[] ya Array<string> use karke list of items define karein. let roles: string[] = ['admin', 'user'];

🏷️ Tuples

Fixed length array jisme har position ka type fix ho. E.g., Database pagination return: [number, any[]] (total count aur rows).

TypeScript • Enums vs Const Enums 
// Enum: Database status ya Roles define karne ke liye
enum OrderStatus {
    PENDING = 'PENDING',
    SHIPPED = 'SHIPPED',
    DELIVERED = 'DELIVERED',
    CANCELLED = 'CANCELLED'
}

// Type safe function argument
function updateStatus(orderId: number, status: OrderStatus) {
    // Database query here...
}

updateStatus(101, OrderStatus.SHIPPED); // ✅ Works perfectly
// updateStatus(101, 'DELIVERED'); ❌ TS Error! Requires the enum type.
🚨 Advanced • Part 5 • The Developer Trap

The "any" Disease vs The "unknown" Savior

TypeScript use karte time any use karna matlab TypeScript compiler ko switch off kar dena. 3-year experienced backend dev ko yeh samajhna zaroori hai.

❌ The Problem with `any`

Agar aap API se aaya data any type mein hold karte ho, toh aap us variable pe koi bhi method bula sakte ho (e.g. data.push() ya data.trim()). Agar data waisa nahi hua toh Node.js runtime pe crash ho jayega. Never use any!

✅ The Solution: `unknown`

unknown TypeScript ka Type-Safe any hai. Yeh aapko allow karta hai third-party unknown data (like Express req.body) hold karne ka, lekin yeh aapko us data ko use nahi karne dega jab tak aap uska type check nahi karte (Type Narrowing).

TypeScript • Type Narrowing in Action 
let externalApiData: unknown;

// Fetching some data...
externalApiData = "hello world";

// ❌ ERROR: Object is of type 'unknown'.
// console.log(externalApiData.toUpperCase()); 

// ✅ Solution: Type Checking (Narrowing) first
if (typeof externalApiData === "string") {
    // Now TS knows for sure it is a string inside this block!
    console.log(externalApiData.toUpperCase()); 
}
