📦 Environment • Part 1 • The Definitions

Setup & Express Type Definitions (`@types`)

Express JavaScript mein likhi gayi hai. TypeScript ko kaise pata chalega ki req.body ya res.json() exist karta hai? Hum DefinitelyTyped (@types) packages use karte hain.

BASH • Installation 
# Install Express normally
npm install express

# Install TypeScript declarations for Express (Crucial for TS!)
npm install @types/express --save-dev
Request Type
import { Request } from 'express'
Yeh batata hai TS ko ki incoming request object ke paas `body`, `params`, `query`, aur `headers` properties hain.
Response Type
import { Response } from 'express'
Yeh batata hai TS ko ki aap `res.status()`, `res.json()`, ya `res.send()` functions call kar sakte hain.
🎮 Logic • Part 2 • Request Handlers

Strongly Typed Controllers

Sabse zyada bugs backend mein aate hain jab humein pata nahi hota ki req.body ya req.params ka shape kya hai. Express ke Request type mein generics hote hain inhe handle karne ke liye!

💡 The Request Generic Signature

Request<Params, ResBody, ReqBody, ReqQuery>
Aap Express ke Request object mein specifically define kar sakte hain ki Request ke kis hisse mein kaisa data aayega!

TypeScript • Typed Express Controller 
import { Request, Response } from 'express';

// Payloads define karein
interface CreateUserBody {
    email: string;
    password: string;
}

interface UserParams {
    userId: string;
}

export const createUser = (
    // Type definition: params={}, resBody=any, reqBody=CreateUserBody
    req: Request<{}, any, CreateUserBody>, 
    res: Response
) => {
    // 100% Type-Safe! TS will auto-complete .email and .password
    const { email, password } = req.body; 
    
    // req.body.username ❌ TS Error! username does not exist on CreateUserBody
    
    res.status(201).json({ message: "User created" });
};

export const getUserById = (
    // Type definition: params=UserParams
    req: Request<UserParams>, 
    res: Response
) => {
    // 100% Type-Safe!
    const userId = req.params.userId; 
    res.json({ id: userId });
};
🛠️ Hack the Core • Part 3 • Declaration Merging

Extending the Request Object (`req.user`)

Jab aap JWT verify karte hain, toh aap extracted user ID ko req.user mein dalte hain. Lekin TypeScript error deta hai: "Property 'user' does not exist on type 'Request'". Isko kaise solve karein?

✅ Solution: Declaration Merging

Module 02 mein humne padha tha ki Interfaces merge ho jate hain. Hum Express ki core library (global namespace) ko open karke uske Request interface mein apni user property add kar denge!

TypeScript • create a "types/express/index.d.ts" file 
// Hum global Express namespace ko modify kar rahe hain
declare global {
  namespace Express {
    
    // Humara custom payload
    export interface UserPayload {
      id: number;
      role: string;
    }

    // Express Request interface ko merge (extend) kar rahe hain
    export interface Request {
      user?: UserPayload; // Optional, kyuki login route pe ye nahi hoga
    }
  }
}

// Important: Is file ko module banane ke liye ek empty export zaroori hai
export {};

Note: Make sure aapka tsconfig.json is .d.ts (declaration file) ko include kar raha hai (e.g. "include": ["src/**/*"]). Ab aap poore project mein kahin bhi req.user.id safely access kar sakte hain bina TypeScript ke error diye!

🛡️ Architecture • Part 4 • The Pipeline

Type-Safe Middleware (Auth & Error Handling)

Express ki power uske Middlewares mein hai. Authentication middleware likhna aur global error handler likhna TypeScript mein thoda alag hota hai kyunki humein NextFunction import karna padta hai.

TypeScript • Authentication Middleware 
import { Request, Response, NextFunction } from 'express';

// Standard Middleware Signature: (req, res, next)
export const isAuth = (req: Request, res: Response, next: NextFunction) => {
    const token = req.headers.authorization;
    
    if (!token) {
        // Note: Humne return lagaya taaki next() call na ho
        return res.status(401).json({ message: "Unauthorized" });
    }

    // Verify token and append user... (Declaration Merging working here!)
    req.user = { id: 99, role: "admin" }; 
    
    // Move to the next controller
    next();
};
TypeScript • Global Error Handler 
// Error Handling Middleware (Always takes 4 arguments)
export const errorHandler = (
    err: Error,             // We type 'err' as the built-in Error object
    req: Request, 
    res: Response, 
    next: NextFunction
) => {
    console.error(err.stack);
    
    res.status(500).json({
        success: false,
        message: err.message || "Internal Server Error"
    });
};
