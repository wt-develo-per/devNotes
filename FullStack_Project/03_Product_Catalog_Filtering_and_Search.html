Controller Bloat vs Clean Pipeline Pattern

❌ Messy Controller Filter (Unmaintainable & Brittle)

public function index(Request $request) {
    $query = Product::query();
    if ($request->has('search')) {
        $query->where('title', 'like', '%'.$request->search.'%');
    }
    if ($request->has('cat')) {
        $query->where('category_id', $request->cat);
    }
    if ($request->has('min')) {
        $query->where('base_price', '>=', $request->min);
    }
    // 50 lines of duplicate if-else checks in every listing method!
    return Inertia::render('Catalog', ['items' => $query->get()]);
}

✅ Dedicated Filter Pipeline (Reusable & Testable)

// In ProductCatalogController.php
public function index(Request $request, ProductFilter $filter): Response {
    $products = Product::query()
        ->where('is_active', true)
        ->with(['category:id,name', 'vendor:id,store_name', 'variants'])
        ->tap(fn ($q) => $filter->apply($q))
        ->paginate(12)
        ->withQueryString();

    return Inertia::render('Storefront/Catalog/Index', [
        'products' => $products,
        'filters' => $request->all(['search', 'category', 'min_price', 'sort']),
    ]);
}

MySQL 8 Fulltext MATCH AGAINST vs LIKE '%term%' (150,000 Products)

Search Strategy Query Type Execution Time (150k Rows) Explain Plan Behavior
Naive Wildcard
WHERE title LIKE '%nike shoes%'		 Full Table Scan 642.8 ms (Severe CPU spike) type: ALL, rows: 150000 (Bypasses B-Tree index)
Prefix Wildcard
WHERE title LIKE 'nike%'		 Range Scan 38.2 ms type: range, key: title_idx (Cannot find middle words)
MySQL 8 Fulltext
WHERE MATCH(title, summary) AGAINST('nike*' IN BOOLEAN MODE)		 Inverted Index Scan 1.9 ms (⚡ Blazing Fast) type: fulltext, key: products_fulltext_idx

Inertia.js Navigation Parameters for High-Performance Filters

Option Key Recommended Value Architectural Purpose
preserveState true Prevents React component state (e.g. search input focus, slider position) from resetting.
preserveScroll true Prevents the browser window from jumping back to top (0,0) when updating filter results.
replace true Replaces current history entry instead of pushing a new history state for every keystroke.
only ['products'] Partial reload: Tells Laravel to evaluate and transmit ONLY the 'products' prop, skipping layout props.
