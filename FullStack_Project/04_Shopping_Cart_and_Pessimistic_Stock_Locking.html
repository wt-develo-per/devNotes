Flash Sale Concurrency: Naive Race Condition vs Pessimistic Locking

Timeline Naive Eloquent (No Lock) Pessimistic Locking (lockForUpdate())
T = 0 ms Buyer 1 reads stock_quantity = 1 Buyer 1 issues SELECT ... FOR UPDATE. Locks Row!
T = 1 ms Buyer 2 reads stock_quantity = 1 (Race condition!) Buyer 2 issues FOR UPDATE. BLOCKED (Waits for Lock)
T = 12 ms Buyer 1 decrements stock to 0 and commits Buyer 1 decrements stock to 0 and COMMIT
T = 13 ms Buyer 2 decrements stock to -1! (Double-Sold!) Lock released. Buyer 2 acquires lock, reads 0 stock. ABORT 422!

Vulnerable Checkout Controller vs Bulletproof Reservation Action

❌ Vulnerable Controller (Zero Concurrency Protection)

public function checkout(Request $request) {
    foreach ($request->items as $item) {
        $variant = ProductVariant::find($item['id']);
        if ($variant->stock >= $item['qty']) {
            $variant->decrement('stock', $item['qty']);
        }
    }
    // High probability of overselling under simultaneous requests!
}

✅ Production-Hardened Action (Sorted IDs + lockForUpdate)

DB::transaction(function () use ($items) {
    // 1. Sort IDs to prevent cross-transaction deadlocks!
    $sortedIds = collect($items)->pluck('variant_id')->sort()->all();

    // 2. Acquire exclusive InnoDB row lock
    $variants = ProductVariant::whereIn('id', $sortedIds)
        ->lockForUpdate()
        ->get()
        ->keyBy('id');

    // 3. Atomically verify and decrement
    foreach ($items as $item) {
        $v = $variants->get($item['variant_id']);
        if ($v->stock_quantity < $item['quantity']) {
            throw new InsufficientStockException("Out of stock: {$v->sku}");
        }
        $v->decrement('stock_quantity', $item['quantity']);
    }
});

Cyclical Lock Deadlock vs Sorted Deterministic Order

Scenario Transaction 1 (Cart: SKU 10 & 25) Transaction 2 (Cart: SKU 25 & 10) Database Outcome
Unsorted Order (Deadlock) Locks #10, attempts to lock #25 Locks #25, attempts to lock #10 💥 DEADLOCK DETECTED! MySQL kills one worker with Error 1213.
Sorted Order (Ascending) Locks #10 first, then locks #25 Attempts to lock #10 first (Waits cleanly in queue) ✅ Zero Deadlocks! Pure linear execution without failures.
