Multi-Guard vs Single Table Spatie RBAC Architecture

Design Dimension Multi-Guard (Separate Admins, Vendors, Users) Single Table + Spatie RBAC (ShopSphere Pro)
User Duplication High: Same person needing admin + vendor access needs 2 emails Zero: Single identity with multi-role assignment
Social OAuth (Google/GitHub) Nightmare: Must map OAuth tokens across 3 guard tables Clean: Single Socialite user link
Inertia Shared Props Complex: Must detect active guard (Auth::guard('vendor')->check()) Effortless: Standard $request->user() with roles array
Permission Granularity Rigid: Guard-based binary checks Dynamic: Granular permissions assignable on the fly

Eager Evaluation Overhead vs Lazy Closure Optimization

❌ Naive Middleware (Eager DB Queries on EVERY Request)

public function share(Request $request): array {
    return [
        ...parent::share($request),
        // Executes DB query on every request even when not authenticated!
        'user' => $request->user()?->load('roles.permissions'),
        // Runs count query even on asset/ping requests!
        'cartCount' => Cart::where('user_id', Auth::id())->count(),
    ];
}

✅ Production-Hardened Middleware (Lazy Closures)

public function share(Request $request): array {
    return [
        ...parent::share($request),
        // Wrapped in closure: Evaluated ONLY when page props are consumed
        'auth' => [
            'user' => fn () => $request->user() ? [
                'id' => $request->user()->id,
                'name' => $request->user()->name,
                'roles' => $request->user()->getRoleNames(),
                'permissions' => $request->user()->getAllPermissions()->pluck('name'),
            ] : null,
        ],
        'cart_count' => fn () => $request->user() 
            ? $request->user()->cartItems()->sum('quantity')
            : count($request->session()->get('guest_cart', [])),
    ];
}

✅ Persistent Inertia Layout (Clean & Uninterrupted)

// In Pages/Products/Index.jsx

    return ;
}

// Layout is defined on the function object
ProductsIndex.layout = (page) => {page};
// Consequence: Inertia reconciles only the page contents!
// Sidebar, theme states, audio streams, and search filters persist seamlessly.
