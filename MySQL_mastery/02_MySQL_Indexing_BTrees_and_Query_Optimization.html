Mass Assignment Vulnerability — Security Checklist

Yeh ek real-world attack vector hai. Neeche dangerous vs safe patterns compare karein:

Approach Code Security Risk Verdict
request()->all() User::create($request->all()) Attacker POST mein is_admin=1 bhej sakta hai ❌ NEVER USE
request()->only() User::create($request->only(['name','email'])) Sirf allowed fields pass hoti hain ✅ SAFE
$request->validated() User::create($request->validated()) Sirf validated fields — Form Request use karo ✅ BEST PRACTICE
$fillable defined Model mein protected $fillable = [...] Whitelist — fillable mein nahi hai to ignore hoga ✅ MANDATORY
$guarded = [] protected $guarded = [] Koi protection nahi — every field fillable! ❌ Avoid in production
Bulk Operations Performance Comparison (10,000 Records)

CSV import ya sync jobs mein correct pattern use karna zaroori hai:

Pattern Queries Run Time (10k rows) Model Events Verdict
foreach { create() } 10,000 INSERT queries ~90 seconds ✅ Yes (creating/created) ❌ Production mein mat karo
foreach { updateOrCreate() } 20,000 queries (SELECT + INSERT) ~210 seconds ✅ Yes ❌ Extreme slow for bulk
DB::table()->insert([]) 1 query (all rows) ~1.5 seconds ❌ No (bypass model) ✅ Fast bulk insert
Model::upsert(chunk 1000) 10 batch queries ~1.2 seconds ❌ No events ⭐ BEST — Insert + Update both
1 Million Users Ko Email Bhejne Ka Sahi Tarika

User::all() se PHP memory crash hogi. Yeh teeno approaches memory-safe hain: 

// WRONG: Server crash guaranteed!
User::all()->each(fn($u) => Mail::to($u)->send(new Newsletter()));

// OPTION 1: chunkById() — Fastest for large tables
User::where('subscribed', true)->chunkById(500, function ($users) {
    foreach ($users as $user) {
        Mail::to($user)->send(new Newsletter());
    }
    // Har chunk ke baad memory free ho jaati hai
    // Offset ki jagah WHERE id > :last_id use hoti hai — fast!
});

// OPTION 2: lazy() — PHP Generator based, memory light
User::where('subscribed', true)->lazy(500)->each(function ($user) {
    Mail::to($user)->send(new Newsletter());
});

// OPTION 3: Laravel Queued Jobs — BEST APPROACH for emails!
User::where('subscribed', true)->chunkById(200, function ($users) {
    foreach ($users as $user) {
        dispatch(new SendNewsletterJob($user))->onQueue('emails');
    }
    // Queue mein push ho jaati hai — web request free hai turant!
});
Query Debugging Cheatsheet — Locally aur Staging Par

Queries dekhne ke liye yeh tools use karo bina manually SQL likhne ke: 

// 1. Generated SQL dekho (values without binding — Laravel 9 and below):
$sql = User::where('status', 'active')->toSql();
// "select * from users where status = ?"

// 2. Values ke sath SQL dekho (Laravel 10+):
$sql = User::where('status', 'active')->toRawSql();
// "select * from users where status = 'active'"

// 3. Ek block mein saari queries capture karo:
DB::enableQueryLog();
$result = User::with('orders')->where('active', true)->get();
$queries = DB::getQueryLog();
// $queries = [['query' => '...', 'bindings' => [], 'time' => 2.45], ...]

// 4. Quick dump and die:
User::where('active', true)->dd();   // Execute + die
User::where('active', true)->dump(); // Execute + continue

// 5. Laravel Telescope (install karein: composer require laravel/telescope):
// Web dashboard: /telescope/queries
// Saari queries with execution time, N+1 detection, slow query alerts!

// 6. AppServiceProvider mein slow query logger:
DB::listen(function ($query) {
    if ($query->time > 200) { // 200ms se slow
        Log::channel('slow_queries')->warning($query->sql, [
            'time' => $query->time,
            'bindings' => $query->bindings,
        ]);
    }
});
