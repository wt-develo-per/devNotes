Emoji Bug Fix: utf8 se utf8mb4 Migration Guide

Production par "Incorrect string value" error aa raha hai jab user 😊 type karta hai? Ye step-by-step fix karo: 

// Step 1: .env file update karo
DB_CHARSET=utf8mb4
DB_COLLATION=utf8mb4_unicode_ci

// Step 2: config/database.php mein verify karo
'charset'   => 'utf8mb4',
'collation' => 'utf8mb4_unicode_ci',

// Step 3: MySQL server variables check karo (Tinker mein)
DB::select("SHOW VARIABLES LIKE 'character_set%'");
DB::select("SHOW VARIABLES LIKE 'collation%'");
// character_set_connection hona chahiye: utf8mb4

// Step 4: Existing tables convert karo
// (Naya migration create karo: php artisan make:migration convert_charset)
DB::statement("ALTER TABLE users CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci");
DB::statement("ALTER TABLE posts CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci");
DB::statement("ALTER TABLE comments CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci");

// Step 5: my.cnf (production server) mein add karo:
// [mysqld]
// character-set-server = utf8mb4
// collation-server = utf8mb4_unicode_ci
Float vs Decimal — Billing Bug Ka Sabse Bada Source!

Float mein paise store karna ek silent, dangerous bug hai jo months baad catch hota hai: 

// WRONG APPROACH - Float ka Floating Point Error:
// Migration: $table->float('price');
// Stored: 10.50 + 10.20 = ?

$a = 10.50;
$b = 10.20;
var_dump($a + $b); // float(20.699999999999999) - NOT 20.70!

// Database mein bhi same problem:
// SELECT 10.50 + 10.20 = 20.699999999999999

// CORRECT APPROACH - DECIMAL:
// Migration: $table->decimal('price', 10, 2);
// Stored: 10.50 + 10.20 = 20.70 (EXACT!)

// Laravel Model Casting - automatic hai:
protected $casts = [
    'price' => 'decimal:2',       // Float nahi, string ke roop mein return hoga
    'tax_amount' => 'decimal:2',
    'wallet_balance' => 'decimal:2',
];

// Usage mein sahi tarika:
$total = bcadd($order->subtotal, $order->tax, 2);  // PHP bcmath functions use karo
$total = number_format($order->total, 2);            // Display ke liye
Laravel Tinker Se MySQL Architecture Diagnose Karo

php artisan tinker se in commands se apne database ki health instantly check karo: 

// 1. MySQL version aur settings check karo:
DB::select('SELECT VERSION() as version');
// => [{"version":"8.0.32"}]

// 2. Database character set verify karo:
DB::select("SHOW VARIABLES LIKE 'character_set_database'");
// character_set_database = utf8mb4 hona chahiye!

// 3. Table ka engine aur charset check karo:
DB::select("SHOW TABLE STATUS LIKE 'users'");
// Engine: InnoDB | Collation: utf8mb4_unicode_ci

// 4. Query log enable karke N+1 detect karo:
DB::enableQueryLog();
$users = User::with('orders')->get();
$log = DB::getQueryLog();
echo count($log) . ' queries ran';
// Agar count > 2, to N+1 problem hai!
foreach ($log as $query) {
    echo $query['query'] . ' [' . round($query['time'], 2) . 'ms]' . PHP_EOL;
}

// 5. Apna connection stats dekhna:
DB::select("SHOW STATUS LIKE 'Connections'");
DB::select("SHOW STATUS LIKE 'Threads_connected'");
