Interactive: New Feature Ke Liye Schema Design Pipeline

"Orders" feature build karna hai — schema design karne ka step-by-step thought process dekhein:

Laravel Migration Column Types — Quick Decision Guide
Situation Wrong Choice Right Choice Why?
Primary Key integer('id') id() or bigIncrements('id') BIGINT UNSIGNED = 18 quintillion rows, no negative IDs
Foreign Key integer('user_id') foreignId('user_id')->constrained() Type must match parent PK exactly + auto-creates index + FK
Price / Money float('price') decimal('price', 10, 2) Float has rounding errors — 1.1 + 2.2 ≠ 3.3!
Status field enum('status', [...]) string('status', 20)->default('pending') Enum = table rebuild to add new value; string = just INSERT
Long text content string('body') mediumText('body') VARCHAR max 65KB; mediumText = 16MB for full articles
Dynamic config Multiple boolean columns json('settings') JSON = flexible schema; no migration needed for new settings
True/False flags tinyInteger('is_active') boolean('is_active')->default(false) boolean() is clearer intent + Model auto-casts to bool
Future dates (after 2038) timestamp('scheduled_at') dateTime('scheduled_at') TIMESTAMP range: 1970–2038; DATETIME range: 1000–9999
MySQL ENUM vs PHP 8.1 Backed Enum + String Column

Har senior developer MySQL enum se kyun door rehte hain — aur modern solution kya hai: 

// BAD: MySQL ENUM
// $table->enum('status', ['pending', 'shipped', 'delivered']);
// Naya value 'processing' add karna chahte ho?
// ALTER TABLE orders MODIFY status ENUM('pending','processing','shipped','delivered');
// 50 million rows = 2+ ghante table lock! Production down!

// GOOD: PHP 8.1 Backed Enum + string column
// Migration:
$table->string('status', 30)->default('pending')->index();

// PHP Enum definition:
enum OrderStatus: string
{
    case Pending    = 'pending';
    case Processing = 'processing';
    case Shipped    = 'shipped';
    case Delivered  = 'delivered';
    case Cancelled  = 'cancelled';

    // Helper methods add kar sakte hain:
    public function label(): string
    {
        return match($this) {
            self::Pending    => 'Awaiting Payment',
            self::Processing => 'Being Prepared',
            self::Shipped    => 'Out for Delivery',
            self::Delivered  => 'Delivered',
            self::Cancelled  => 'Order Cancelled',
        };
    }

    public function color(): string
    {
        return match($this) {
            self::Pending    => 'yellow',
            self::Processing => 'blue',
            self::Shipped    => 'purple',
            self::Delivered  => 'green',
            self::Cancelled  => 'red',
        };
    }
}

// Order Model:
protected $casts = [
    'status' => OrderStatus::class,
];

// Usage (type-safe!):
$order->status = OrderStatus::Shipped;
$order->save();

if ($order->status === OrderStatus::Pending) {
    // Process payment...
}

// Naya status add karna (future mein)?
// Sirf PHP Enum mein ek case add karo — NO schema change needed!
TIMESTAMP vs DATETIME — Laravel Timezone Handling Guide

India-based app mein IST mein dates dikhana aur UTC mein store karna — sahi setup: 

// config/app.php:
'timezone' => 'Asia/Kolkata',  // IST (UTC+5:30)

// config/database.php mein timezone:
'options' => [
    PDO::MYSQL_ATTR_INIT_COMMAND => "SET time_zone = '+05:30'",
],
// Ya: SET GLOBAL time_zone = '+05:30'; in MySQL

// TIMESTAMP Columns: timezone-aware
// - MySQL TIMESTAMP UTC mein store karta hai
// - Read karte waqt server timezone mein convert karta hai
// - Laravel Carbon automatically correct timezone mein return karta hai

$user->created_at->format('d/m/Y h:i A');
// Output: "08/09/2024 10:30 AM" (IST mein — automatic conversion!)

// DATETIME Columns: timezone-naive
// - Jo value doge, wahi store hogi — no conversion
$meeting->scheduled_at = '2024-09-08 10:30:00';
// Stored exactly as: 2024-09-08 10:30:00
// Read: 2024-09-08 10:30:00 (same — no conversion)

// Carbon ke sath explicit timezone:
$carbon = Carbon::parse('2024-09-08 10:30:00', 'Asia/Kolkata');
echo $carbon->toUtcString();    // UTC equivalent
echo $carbon->toIso8601String(); // ISO format

// API response mein timezone:
return response()->json([
    'created_at' => $user->created_at->toIso8601String(), // '2024-09-08T05:00:00+05:30'
    'created_at_utc' => $user->created_at->utc()->toIso8601String(),
]);
Production-Ready Migration Pattern — Real-World Example

E-commerce products table ka complete migration jo production mein deploy karne ke liye ready hai: 

// php artisan make:migration create_products_table

public function up(): void
{
    Schema::create('products', function (Blueprint $table) {
        // 1. Primary Key
        $table->id();

        // 2. Foreign Keys (foreignId = unsignedBigInteger + FK + index automatically)
        $table->foreignId('category_id')->constrained()->restrictOnDelete();
        $table->foreignId('brand_id')->nullable()->constrained()->nullOnDelete();
        $table->foreignId('created_by')->constrained('users');

        // 3. Identifiers
        $table->string('name', 255);
        $table->string('slug', 255)->unique();   // SEO URL — must be unique
        $table->string('sku', 50)->unique();     // Stock keeping unit

        // 4. Content
        $table->string('short_description', 500)->nullable();
        $table->mediumText('full_description')->nullable();

        // 5. Pricing (ALWAYS decimal for money!)
        $table->decimal('price', 10, 2);
        $table->decimal('compare_price', 10, 2)->nullable(); // Crossed-out price
        $table->decimal('cost_price', 10, 2)->nullable();    // Internal cost

        // 6. Inventory
        $table->unsignedInteger('stock')->default(0);
        $table->unsignedInteger('low_stock_threshold')->default(5);

        // 7. Status (PHP Enum backed by string — NOT MySQL enum!)
        $table->string('status', 20)->default('draft')->index();
        $table->boolean('is_featured')->default(false)->index();
        $table->boolean('is_digital')->default(false);

        // 8. Flexible attributes (JSON for variant properties)
        $table->json('attributes')->nullable();  // {'color': 'red', 'size': 'L'}
        $table->json('seo_meta')->nullable();

        // 9. Timestamps
        $table->timestamps();
        $table->softDeletes();

        // 10. Composite Indexes (for common query patterns)
        $table->index(['category_id', 'status', 'price']); // Category page filter
        $table->index(['status', 'is_featured']);           // Featured products
    });
}

public function down(): void
{
    Schema::dropIfExists('products');
}
