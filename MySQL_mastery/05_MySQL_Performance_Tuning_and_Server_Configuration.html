Interactive: Eloquent Relationships Ka Actual SQL — Under The Hood

Har relationship type ke liye MySQL mein kya SQL generate hoti hai — step by step dekhein:

SQL JOIN Types — Laravel Query Builder Examples
JOIN Type Laravel Method Result Use Case
INNER JOIN ->join() Only matching rows from both tables Orders with valid users; posts with authors
LEFT JOIN ->leftJoin() All left table rows + matching right (NULL if no match) All users even if no orders; posts with optional category
RIGHT JOIN ->rightJoin() All right table rows + matching left (rare in practice) Rarely needed — restructure query with LEFT JOIN instead
CROSS JOIN ->crossJoin() Cartesian product (every row x every row) Generating combinations; test data; matrix reports 

// INNER JOIN — Common report query:
$salesReport = DB::table('orders')
    ->join('users', 'orders.user_id', '=', 'users.id')
    ->join('order_items', 'orders.id', '=', 'order_items.order_id')
    ->join('products', 'order_items.product_id', '=', 'products.id')
    ->select(
        'users.name as customer',
        'products.name as product',
        'order_items.qty',
        DB::raw('order_items.qty * order_items.unit_price as line_total')
    )
    ->where('orders.status', 'delivered')
    ->whereBetween('orders.created_at', [now()->startOfMonth(), now()->endOfMonth()])
    ->get();

// LEFT JOIN — Find users who have NOT placed any orders:
$usersWithoutOrders = DB::table('users')
    ->leftJoin('orders', 'users.id', '=', 'orders.user_id')
    ->whereNull('orders.id')   // No matching order = never ordered!
    ->select('users.*')
    ->get();
whereHas() vs join() — Performance Comparison
Scenario whereHas() SQL join() SQL Winner
Users with published posts EXISTS subquery (correlated) INNER JOIN + DISTINCT join() for large tables
Small tables (< 10K rows) Readable, clean code More verbose whereHas() — simplicity wins
Need data from related table too Extra query needed Single query gets both join() clearly
doesntHave / NOT EXISTS whereDoesntHave() — cleanest! LEFT JOIN + WHERE NULL whereDoesntHave() wins on clarity 
// Pattern 1: whereHas — cleaner for simple existence:
$activeUsers = User::whereHas('orders', function ($q) {
    $q->where('status', 'completed')->where('created_at', '>', now()->subMonth());
})->get();

// Pattern 2: join — faster for large datasets + need joined data:
$activeUsers = User::join('orders', 'users.id', '=', 'orders.user_id')
    ->where('orders.status', 'completed')
    ->where('orders.created_at', '>', now()->subMonth())
    ->select('users.*', DB::raw('COUNT(orders.id) as order_count'))
    ->groupBy('users.id')
    ->having('order_count', '>', 0)
    ->get();

// Pattern 3: whereDoesntHave — users who never ordered:
$neverOrdered = User::whereDoesntHave('orders')->get();
// SQL: WHERE NOT EXISTS (SELECT * FROM orders WHERE user_id = users.id)
// vs LEFT JOIN + WHERE NULL — same result, whereDoesntHave() is cleaner!
Subquery Selects — Single Query Mein Extra Data
// SCENARIO 1: Users list with last order date
$users = User::addSelect([
    'last_order_at' => Order::select('created_at')
        ->whereColumn('user_id', 'users.id')
        ->latest()
        ->limit(1),
    'total_spent' => Order::select(DB::raw('COALESCE(SUM(total_amount), 0)'))
        ->whereColumn('user_id', 'users.id')
        ->where('status', 'completed')
])
->withCasts(['last_order_at' => 'datetime', 'total_spent' => 'decimal:2'])
->get();

// Access:
echo $user->last_order_at->diffForHumans(); // "3 days ago"
echo number_format($user->total_spent, 2);   // "15,230.50"

// SCENARIO 2: Posts with comment count + last comment date (without N+1):
$posts = Post::addSelect([
    'comments_count' => Comment::selectRaw('COUNT(*)')
        ->whereColumn('post_id', 'posts.id'),
    'last_commented_at' => Comment::select('created_at')
        ->whereColumn('post_id', 'posts.id')
        ->latest()
        ->limit(1),
])->get();

// SCENARIO 3: Products with stock status label:
$products = Product::addSelect([
    DB::raw("CASE WHEN stock = 0 THEN 'out_of_stock'
                  WHEN stock < 5 THEN 'low_stock'
                  ELSE 'in_stock' END as stock_status")
])->get();

Pivot Table Patterns — belongsToMany Advanced Usage
// SETUP: Products and Categories (many-to-many with extra pivot data)
// category_product table: category_id, product_id, display_order, is_primary

// Product Model:
public function categories(): BelongsToMany
{
    return $this->belongsToMany(Category::class)
                ->withPivot(['display_order', 'is_primary'])
                ->withTimestamps()
                ->orderByPivot('display_order');
}

// ATTACH (add relationship):
$product->categories()->attach($categoryId, [
    'display_order' => 1,
    'is_primary' => true,
]);

// DETACH (remove relationship):
$product->categories()->detach($categoryId);
$product->categories()->detach(); // All categories detach

// SYNC (replace all):
$product->categories()->sync([1, 2, 3]); // Only these categories remain

// SYNC with pivot data:
$product->categories()->sync([
    1 => ['display_order' => 1, 'is_primary' => true],
    2 => ['display_order' => 2, 'is_primary' => false],
]);

// TOGGLE (attach if not present, detach if present):
$product->categories()->toggle([1, 2]); // Like a checkbox toggle

// ACCESS pivot data:
foreach ($product->categories as $category) {
    echo $category->name;                    // Category name
    echo $category->pivot->display_order;    // Pivot column
    echo $category->pivot->is_primary ? 'Primary' : 'Secondary';
}

// QUERY pivot data in whereHas:
$primaryProducts = Product::whereHas('categories', function ($q) {
    $q->wherePivot('is_primary', true);
})->get();
