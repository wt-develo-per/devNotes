EXPLAIN Output — Laravel Developer Ka Cheatsheet
EXPLAIN type Meaning Example Query Performance
const Single row via PK or unique WHERE id = 1 ⭐⭐⭐⭐⭐ BEST
eq_ref 1 row per JOIN on unique FK JOIN on unique column ⭐⭐⭐⭐⭐ EXCELLENT
ref Multiple rows via non-unique index WHERE user_id = 42 ⭐⭐⭐⭐ GOOD
range Index range scan WHERE price BETWEEN 100 AND 500 ⭐⭐⭐ OK
index Full index scan (no filter) ORDER BY indexed col ⭐⭐ MEDIOCRE
ALL Full table scan — NO index used! WHERE non_indexed_col = x ❌ DANGER — Add index!

Extra ValueMeaningAction

Eager Loading Patterns — Common Laravel Scenarios
// PATTERN 1: Basic eager loading
$posts = Post::with('user')->get();

// PATTERN 2: Multiple relationships
$posts = Post::with(['user', 'category', 'tags'])->get();

// PATTERN 3: Nested relationships
$posts = Post::with('user.profile')->get();      // user -> profile
$posts = Post::with('comments.user')->get();     // comments -> each comment's user

// PATTERN 4: Select specific columns from relationship
$posts = Post::with('user:id,name,avatar')->get();  // Sirf 3 columns!
// SQL: SELECT id, name, avatar FROM users WHERE id IN (...)

// PATTERN 5: Conditional eager loading
$posts = Post::with([
    'comments' => function ($query) {
        $query->where('approved', true)
              ->latest()
              ->limit(5);
    }
])->get();

// PATTERN 6: withCount, withSum, withAvg (no N+1!)
$users = User::withCount('posts')
             ->withCount(['comments' => fn($q) => $q->where('approved', true)])
             ->withSum('orders', 'total_amount')
             ->get();
// Access: $user->posts_count, $user->comments_count, $user->orders_sum_total_amount

// PATTERN 7: Lazy Eager Loading (load after collection)
$posts = Post::all();
// ... some processing...
if ($needsUsers) {
    $posts->load('user');  // Load relationship on existing collection
}

// PATTERN 8: withExists — boolean check (memory efficient)
$posts = Post::withExists('comments')->get();
// $post->comments_exists = true/false (single JOIN, no subquery)

// ANTI-PATTERN: Loop mein relationship access mat karo:
foreach ($posts as $post) {
    $post->user->name;      // N+1 if not eager loaded!
    $post->comments->count(); // N+1! Use withCount() instead
}
Composite Index — Leftmost Prefix Rule Practical Guide
Index Definition Query WHERE Clause Index Used? Why?
(user_id, status, created_at) WHERE user_id = 1 ✅ Yes — partial Leftmost column present
WHERE user_id = 1 AND status = 'active' ✅ Yes — partial First two columns present
WHERE user_id = 1 AND status = 'a' AND created_at > '...' ✅ Yes — full All three columns present
WHERE status = 'active' ❌ No Leftmost (user_id) missing
WHERE created_at > '2024-01-01' ❌ No user_id AND status both missing

Design tip: Composite index mein columns ko selectivity (cardinality) ke order mein rakho — jo column sabse zyada unique values rakhta ho wo pehle aana chahiye. Jaise (user_id, status) user_id high cardinality (unique per user) aur status low cardinality (few values), isliye user_id pehle theek hai.

Laravel Telescope + Debugbar — N+1 Aur Slow Query Detection
# Install Telescope (local/staging only):
composer require laravel/telescope --dev
php artisan telescope:install
php artisan migrate

# Dashboard URL:
# http://localhost:8000/telescope
// config/telescope.php — Slow query threshold set karo:
'slow_query_threshold' => 100, // 100ms se slow = flagged in dashboard

// AppServiceProvider.php — Only local mein load karo:
public function register(): void
{
    if ($this->app->environment('local', 'staging')) {
        $this->app->register(TelescopeServiceProvider::class);
    }
}

// Telescope Features For Laravel Devs:
// Queries Tab:
//   - Saari SQL queries with execution time
//   - "Duplicate queries" warning = N+1 problem detected!
//   - Slow queries highlighted in red
// Requests Tab:
//   - Total queries per request
//   - Memory usage
// Laravel Debugbar (browser toolbar alternative):
// composer require barryvdh/laravel-debugbar --dev
// Automatically show karega:
// - Query count per page
// - N+1 warning badge
// - Individual query times
// - Memory usage graph

// Manual N+1 detection code:
DB::enableQueryLog();
// ... your code ...
$queries = DB::getQueryLog();
$duplicates = array_filter(array_count_values(
    array_column($queries, 'query')
), fn($count) => $count > 1);
if (!empty($duplicates)) {
    Log::warning('Possible N+1 detected!', $duplicates);
}
