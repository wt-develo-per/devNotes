Cross-Site Request Forgery (CSRF) * **The Attack:** A hacker builds a fake website. Inside that website, there is an invisible form pointing to `yourbank.com/transfer?amount=1000`. If you are currently logged into your bank on another tab, the bank's cookie is sent automatically by the browser, and the transfer happens! * **The Fix:** Use CSRF Tokens (a unique hidden string in your forms) or set your login Cookies to `SameSite=Strict` so the browser refuses to send them if the request comes from a different domain. ### 4. CORS (Cross-Origin Resource Sharing) * **What is it?** Not an attack, but a defense mechanism built into browsers. By default, a browser will block a website running on `http://localhost:3000` from making API calls to a backend running on `http://localhost:8080`. * **The Fix:** You must configure your Node.js backend to explicitly send headers saying, "I allow `localhost:3000` to talk to me!" (In Express, this is just `app.use(cors())`). > [!IMPORTANT] > **Where to Store JWTs in the Browser?** > Never store JWTs in `localStorage`! Any XSS attack can easily read `localStorage`. You should store JWT Access Tokens in **`HttpOnly` Cookies**. An `HttpOnly` cookie is locked inside the browser and is physically impossible for JavaScript (and therefore XSS hackers) to read.
