Top 30 Database & SQL Interview Questions

From SQL Joins to NoSQL Scaling (Hinglish Explanations)

Q1. What is the difference between SQL (Relational) and NoSQL databases?
"SQL (MySQL, Postgres) ek Excel sheet ki tarah hai jisme fixed columns (schema) hote hain. Ye complex relationships (Joins) ke liye best hai. NoSQL (MongoDB) ek JSON document ki tarah hai jisme schema flexible hota hai. Ye unstructured data aur massive horizontal scaling ke liye best hai."
Q2. Explain the ACID properties in databases.
"ACID ensures karta hai ki database transactions safe rahen (jaise banking).
A - Atomicity: Ya toh pura kaam hoga ya kuch nahi hoga (All or Nothing).
C - Consistency: Data hamesha valid state me rahega (Negative balance nahi ho sakta).
I - Isolation: Do log ek sath transaction karein toh unhe ek dusre ka partial data nahi dikhega.
D - Durability: Agar server power-cut ho jaye, toh bhi data hard-drive me safe rahega."
Q3. What are Database Indexes and how do they work?
"Index ek kitab ke piche bane 'Index page' ki tarah hota hai. Agar aap index nahi lagaoge, toh DB ko 1 million rows scan karni padengi ek user dhundhne ke liye (Full Table Scan). Index lagane se DB B-Tree data structure banata hai, aur O(log N) speed me data nikal leta hai." Drawback: Indexes slow down WRITE operations (INSERT/UPDATE) because the B-Tree has to be reorganized.
Q4. What is the difference between Primary Key and Unique Key?
"Dono duplicates ko rokte hain, par ek table me sirf ek hi Primary Key ho sakti hai (jo automatically clustered index banati hai), jabki Unique Keys bohot saari ho sakti hain. Aur Primary Key kabhi NULL nahi ho sakti, par Unique Key me 1 bar NULL allow hota hai."
Q5. What is a Foreign Key?
"Foreign Key 2 tables ko link karti hai. Ye 'Referential Integrity' maintain karti hai. Agar User ID 5 exist nahi karti, toh aap Orders table me us user ke liye order insert nahi kar sakte. Foreign key error fek degi."
Q6. Explain INNER JOIN vs LEFT JOIN.
"INNER JOIN me sirf wahi data aata hai jo dono tables me match hota ho. LEFT JOIN me left table ka SARA data aata hai, bhale hi right table me uski details na ho (wahan NULL dikhega)."
Q7. What is the difference between WHERE and HAVING in SQL?
"`WHERE` filter tab lagta hai jab data rows ko group karne se pehle filter karna ho. `HAVING` tab lagta hai jab aapko `GROUP BY` karne ke baad aggregates par filter lagana ho (e.g. `HAVING COUNT(*) > 5`)."
Q8. What is the N+1 Query Problem?
"Ye ORMs (jaise Prisma/Sequelize) ka sabse bada bug hai. Maan lo aap 100 users mangwate ho (1 query). Fir har user ke post mangwane ke liye loop me ek query chalate ho (100 queries). Total 101 queries ho gayin! Ise bachane ke liye SQL me JOIN ya ORM me `include`/`populate` use karna chahiye taaki sab 1 query me aa jaye."
Q9. How do you handle Pagination in databases? (OFFSET vs Cursor)
"Chhote data ke liye hum `LIMIT 10 OFFSET 20` use karte hain. Par agar OFFSET 10000 ho jaye, toh DB pehle 10000 rows ginta hai fir discard karta hai (bohot slow!). Bade scale (Twitter/Facebook) par hum **Cursor-based Pagination** use karte hain: `WHERE id > last_seen_id LIMIT 10`, jo O(1) me run hoti hai."
Q10. What are Database Transactions?
"Transaction multiple queries ka ek group hota hai jisko Atomicity (All or nothing) milti hai. Hum `BEGIN` se start karte hain, aur agar sab theek ho toh `COMMIT` karte hain. Agar kisi ek query me error aa jaye, toh hum `ROLLBACK` kar dete hain aur purana data wapas aa jata hai."
Q11. What is Database Normalization?
"Data ki duplication ko kam karne ki technique. Ek badi table jisme User aur Order dono ka data hai, usko tod kar 2 alag tables banana taaki storage bache aur data inconsistency na ho (1NF, 2NF, 3NF)."
Q12. What is Denormalization and why do we use it in NoSQL?
"Normalization reads ko slow kar deti hai kyunki Joins lagane padte hain. Denormalization (MongoDB) me hum intentionally data duplicate karte hain (ek hi JSON document me sab daal dete hain) taaki disk se 1 hi baar me sab read ho jaye aur performance super-fast ho!"
Q13. What is the CAP Theorem?
"Distributed databases me aapko teeno me se sirf 2 cheezein mil sakti hain: Consistency (sabko same data dikhe), Availability (system kabhi down na ho), Partition Tolerance (internet break hone par bhi chale). Banks CP choose karte hain, Amazon/Instagram AP choose karte hain."
Q14. What is Master-Slave Replication?
"Database par traffic kam karne ke liye. Hum ek 'Master' server banate hain jo sirf Writes (INSERT/UPDATE) leta hai. Wo Master apna data 3 'Slaves' (Replicas) me copy karta rehta hai. Ab hamari Node.js API saari 'READ' queries un 3 slaves par bhejti hai. Isse master overload nahi hota."
Q15. What is Database Sharding?
"Jab ek Database ki Hard-Drive full ho jati hai (Vertical scaling limit), tab hum ek badi table ko horizontally 2 hisso me tod dete hain. Users A-M Node 1 par jayenge, aur Users N-Z Node 2 par jayenge. Ise Sharding kehte hain."
Q16. Explain the 'Hot Key' problem in Sharding.
"Agar aap UserID ke hisaab se sharding karte ho, aur Virat Kohli (High traffic user) Node 1 par hai, toh jab Virat tweet karega, saara traffic Node 1 par jayega aur wo crash ho jayega. Ise Hot Key problem kehte hain. Isse bachne ke liye hum Consistent Hashing use karte hain."
Q17. What is Eventual Consistency in NoSQL?
"Jab hum Amazon AP system (Availability over Consistency) use karte hain, toh agar master me data update hota hai, usko slaves tak pohchne me 2 seconds lag sakte hain. In 2 seconds me kuch users ko purana data dikhega. Par 'eventually' (kuch der baad) sabko sahi data dikhne lagega."
Q18. What is a MongoDB Replica Set?
"MongoDB me High Availability ke liye minimum 3 nodes lagaye jate hain (1 Primary, 2 Secondary). Agar Primary node jal jaye/crash ho jaye, toh baaki 2 nodes apas me 'Election' karte hain aur ek naya Primary chun lete hain bina downtime ke!"
Q19. When should you NOT use MongoDB?
"MongoDB me complex JOINs (Aggregation pipelines) slow hote hain, aur Multi-document transactions native SQL jitne robust nahi hote. Agar aapki app me bohot strict relational data hai (jaise ERP ya Banking software), wahan hamesha Postgres/MySQL use karna chahiye."
Q20. What are Stored Procedures?
"Stored procedure database ke andar likha hua ek function (code) hota hai jise aap pre-compile karke save kar sakte ho. Isse network traffic bachta hai kyunki Node.js ko lambi SQL query bhejne ke bajaye sirf us procedure ka naam call karna padta hai."
Q21. Explain Database Triggers.
"Trigger ek automatic action hota hai. Jaise aap rule set kar sakte ho: 'Jab bhi `orders` table me naya INSERT aaye, automatically `inventory` table me se 1 item kam kar dena'. Isme backend Node code ki zarurat nahi padti."
Q22. What is the difference between TRUNCATE and DELETE?
"`DELETE` ek DML command hai jo row-by-row data delete karta hai aur Rollback ho sakta hai. `TRUNCATE` ek DDL command hai jo table ki storage ko reset kar deta hai. Ye bohot fast hota hai par Rollback nahi kiya jaa sakta."
Q23. How does Redis caching work?
"Redis ek NoSQL Key-Value database hai jo Hard-Drive ke bajaye server ki RAM me data store karta hai. Hard-drive se query karne me 50ms lagte hain, jabki Redis (RAM) se 1ms me data aa jata hai. Ye viral data caching aur session storage ke liye use hota hai."
Q24. Explain Cache-Aside Strategy.
"Backend pehle Redis (Cache) me check karta hai. Agar data mil gaya (Cache Hit) toh wapas bhej deta hai. Agar nahi mila (Cache Miss) toh MySQL se nikalta hai, Redis me save karta hai, aur fir user ko bhejta hai. Lazy loading!"
Q25. What is Connection Pooling?
"Database se connection banana (TCP handshake) bohot heavy process hai. Agar har API request par naya connection banaoge toh DB crash ho jayega. Connection Pool me hum pehle se hi (e.g. 10) connections bana kar rakhte hain, requests unhi 10 pipes ko re-use karti hain."
Q26. What is a Graph Database (like Neo4j) used for?
"Jab data me relationships hi sabse zyada important ho (Jaise Facebook: You -> friends with -> John -> likes -> Nike). Aise highly connected data ko SQL me 10 JOINs lagane padenge, par Graph DB me ye milliseconds me query ho jata hai."
Q27. What is MongoDB Aggregation?
"Aggregation MongoDB ka tarika hai SQL ke 'GROUP BY' aur 'JOIN' jaisi complex queries karne ka. Isme ek pipeline hoti hai (array of steps): pehle `$match` se filter karo, fir `$group` se combine karo, fir `$sort` se order karo."
Q28. Explain the difference between Clustered and Non-Clustered Indexes.
"Clustered index (Primary Key) directly table ka data ussi order me hard-drive par save karta hai. Isliye 1 table me sirf 1 clustered index ho sakta hai. Non-clustered index ek alag pointer file banata hai (jaise book ke last me index page)."
Q29. What is an ORM (like Prisma/Sequelize) and ODM (like Mongoose)?
"Ye libraries hume raw SQL ya MongoDB queries likhne se bachati hain. Hum Node.js me simple Javascript Objects/Methods (`User.find()`) use karte hain, aur ORM internally usko safe SQL query me convert kar deta hai (preventing SQL injection)."
Q30. How do you store passwords in the database?
"Passwords ko KABHI BHI plain text me store nahi karna chahiye. Unko one-way Hash kiya jata hai using algorithms like bcrypt (with Salting). Taki agar database hack bhi ho jaye, toh hackers reverse engineering karke asli password na nikal payein."
