Top 30 System Design (HLD) Interview Questions

The Ultimate Guide to Scaling and Architecture (Hinglish Explanations)

Q1. What is System Design?
"System Design ka matlab hai ki 1 million users ka traffic aane par aapka system crash na ho. Isme hum architecture banate hain ki kitne servers lagenge, kaunsa database use hoga, aur load balancer kaise traffic divide karega."
Q2. Explain Vertical Scaling vs Horizontal Scaling.
"Vertical scaling (Scale Up) matlab purane 2GB RAM wale server ko delete karke ek mehenga 64GB RAM wala server kharidna (Iski ek limit hoti hai). Horizontal scaling (Scale Out) matlab us 2GB RAM wale 10 saste servers aur laga dena. Google Horizontal scaling use karta hai."
Q3. What is a Load Balancer?
"Ye ek Traffic Police ki tarah hota hai. Jab aapke paas 10 servers hon, toh user directly kis server par jayega ye Load Balancer decide karta hai (Round-Robin tarike se). Jaise NGINX ya AWS ALB."
Q4. What is the difference between TCP and UDP?
"TCP reliable hai (WhatsApp message ki tarah), agar data nahi pahucha toh dobara bhejta hai, but thoda slow hai. UDP super fast hai par unreliable hai (Video Call ki tarah), agar frame drop hua toh bhool jao, naya frame aayega."
Q5. What is an API Gateway?
"Microservices architecture me frontend ko nahi pata hota ki 'Payment Service' kis IP par chal rahi hai. API Gateway ek receptionist hota hai. Frontend request Gateway ko bhejta hai, aur Gateway usko sahi service ke paas route kar deta hai (aur auth/rate-limiting bhi handle karta hai)."
Q6. What is the difference between Monolithic and Microservices Architecture?
"Monolith me ek hi codebase me Users, Products, aur Payments sab ek sath hote hain. Ek bug aaya toh puri app crash! Microservices me hum in teeno ki alag-alag apps bana dete hain. Agar payment fail ho, toh at least log products toh dekh sakein."
Q7. When should you NOT use Microservices?
"Agar aap ek early-stage startup ho jiske paas sirf 2 developers hain, toh Microservices banana bewakoofi hai. Isme deployment aur inter-service communication ka bohot overhead hota hai. Aise me Monolith best hai."
Q8. What is a CDN (Content Delivery Network)?
"Agar aapka main server USA me hai, toh India wale user ko image load hone me 2 seconds lagenge. CDN (jaise Cloudflare) static assets (images, videos) ko copy karke duniya bhar ke servers me rakh deta hai. Ab India wala user India ke hi CDN server se image 10ms me download kar lega."
Q9. What is Caching? How does Redis work?
"Database queries (Hard-drive) slow hoti hain. Caching me hum frequently accessed data (jaise viral tweet) ko RAM me save kar lete hain. Redis ek In-Memory data structure store hai jo 1 millisecond me data return kar deta hai."
Q10. Explain Cache Eviction Policies (LRU).
"RAM ki memory limited (e.g. 2GB) hoti hai. Jab wo full ho jaye, toh naya data kaha aayega? LRU (Least Recently Used) policy kehti hai ki jo data sabse zyada time se kisi ne read nahi kiya hai, usko delete kardo aur uski jagah naya data daal do."
Q11. What is the difference between Cache-Aside and Write-Through caching?
"Cache-Aside (Lazy loading): Request aati hai, pehle Cache check hota hai, agar nahi mila toh DB se nikal kar cache me daalte hain. Write-Through: Jab DB me data save hota hai, toh usi waqt use Cache me bhi update kar dete hain taaki data hamesha 100% fresh rahe."
Q12. What is a Message Queue (Kafka/RabbitMQ) and why do we use it?
"Agar ek heavy task hai (jaise 4K video encode karna) jisme 30 minute lagenge. Node.js 30 minute tak user ko wait nahi kara sakta. Hum ek event Message Queue me daal dete hain aur user ko turant 'Success' dikha dete hain. Background workers (servers) aaram se wo message queue se uthate hain aur video process karte rehte hain (Asynchronous Processing)."
Q13. RabbitMQ vs Kafka. When to use what?
"RabbitMQ ek simple post-office ki tarah hai. Ek bar message padh liya, toh delete ho jata hai (Email sending ke liye best). Kafka ek giant 'Log file' hai. Message delete nahi hota, hazaro systems use ek sath padh sakte hain (Analytics aur massive data streaming ke liye best)."
Q14. What is Object Storage (AWS S3) and why not save images in DB?
"Relational DB (MySQL) lambe binary files (images/pdfs) store karne par bohot slow ho jate hain (Table scan ruk jata hai). Isliye hum images AWS S3 (Object Storage) me save karte hain, aur S3 hume ek URL deta hai, wo URL hum DB me as text save kar lete hain."
Q15. How would you design a URL Shortener like Bitly?
"Long URL ko 7 character ki short string me convert karne ke liye Base62 Encoding [a-z, A-Z, 0-9] use hoti hai (isse 3.5 Trillion unique links ban sakte hain). Hum is Short-URL aur Long-URL ke relation ko ek NoSQL DB (DynamoDB) me save karte hain. Viral links ke liye aage Redis cache laga dete hain."
Q16. How would you design a Pastebin?
"10,000 lines ka text MySQL me save mat karo! Text ko `.txt` file bana kar AWS S3 me daal do. Aur S3 ka link MySQL me user ke metadata (name, date) ke sath save kar lo. Jab user paste dekhe, toh frontend directly S3 se text file utha lega."
Q17. How would you design Twitter's Feed?
"Jab Virat Kohli tweet karta hai, toh agar system 10 million followers ki feed me insert karne gaya toh ruk jayega! Instead, famous log jab tweet karte hain, toh unka tweet cache me rakha jata hai, aur jab unka follower app kholta hai, tab on-the-fly uske timeline me wo tweet chipkaya jata hai (Fan-out on read)."
Q18. How does WhatsApp handle real-time chat?
"HTTP slow hota hai aur har bar connection tod deta hai. Chat apps **WebSockets** use karti hain, jisse Server aur Client dono continuously ek dusre se connected rehte hain (Bi-directional communication) aur real-time message bhej sakte hain."
Q19. What is Long Polling?
"Jab WebSockets available na hon, toh frontend backend ko request bhejta hai. Backend turant reply dene ke bajaye request ko 'Hold' par rakhta hai (jaise 30 seconds tak). Jab naya data aata hai, tab reply deta hai. Fir frontend turant ek nayi request bhej deta hai. (Ye purana tarika tha real-time apps ka)."
Q20. What is a Distributed Cache?
"Jab 1 server ki RAM full ho jaye (e.g. 64GB Redis), toh hum data ko multiple Redis servers me baant dete hain. Isko manage karne ke liye Consistent Hashing use hoti hai taaki pata chale ki kaunsi cache key kis server par hai."
Q21. Explain Consistent Hashing.
"Agar aapke paas 4 Database Shards hain, aur ek naya (5th) shard add karna hai, toh normal hashing (`ID % 4` to `ID % 5`) me saara data hil jayega. Consistent Hashing ek 'Ring' algorithm use karti hai jisse sirf wahi data move hota hai jo naye server ke aas paas hai. 90% data safe rehta hai!"
Q22. What is the Strangler Fig Pattern?
"Purani Monolith app ko 1 raat me rewrite karna suicide hai. Is pattern me hum purani app ke aage API Gateway lagate hain, aur dheere-dheere ek-ek route ko nayi Microservice par redirect karte jate hain. 6 mahine me purani app completely khatam ho jati hai bina kisi downtime ke!"
Q23. How do Microservices communicate with each other?
"Synchronous baaton ke liye wo gRPC (HTTP/2 base binary protocol jo bohot fast hai) ya REST API use karte hain. Asynchronous baaton ke liye (fire and forget) wo RabbitMQ ya Kafka use karte hain."
Q24. What is a Reverse Proxy?
"Normal Proxy aapki identity chhupati hai (jaise VPN). Reverse Proxy (e.g. NGINX) Backend Server ki identity chhupati hai. User pehle NGINX pe aata hai, fir NGINX internally Node.js tak request le jata hai. Ye SSL encryption aur load balancing bhi karta hai."
Q25. What is Event Sourcing?
"Database me directly current state (`Balance: 50`) save karne ke bajaye, hum saare events save karte hain (`Added 100`, `Spent 50`). Isse fada ye hai ki hum kisi bhi time piche jaa kar system ki state dekh sakte hain (Jaise Bank passbook ya Redux DevTools)."
Q26. How does Netflix stream video without buffering?
"Duniya bhar me unke Open Connect Appliances (custom CDNs) IPS ke andar lage hote hain. Jab aap movie click karte ho, toh wo America se nahi, aapke shahar ke local ISP hub se stream hoti hai. Aur wo DASH/HLS protocols use karte hain jo internet speed ke hisaab se quality change karte rehte hain."
Q27. What is Blue-Green Deployment?
"Zero downtime update karne ki technique. Aapke 5 purane servers (Blue) chal rahe hain. Aap 5 naye servers (Green) banate ho updated code ke sath. Jab Green completely ready ho jata hai, toh Load Balancer ka traffic instantly Blue se Green par switch kar dete hain. Agar koi bug aaya, toh wapas Blue par switch!"
Q28. What is Rate Limiting and Token Bucket Algorithm?
"Token Bucket ek bucket hai jisme har second 10 tokens girte hain. Jab user request karta hai toh 1 token use hota hai. Agar bucket khali hai toh 429 Too Many Requests error aata hai. Isse DDOS attacks ko roka jata hai (AWS WAF ya API Gateway me)."
Q29. Explain Service Discovery.
"Microservices architecture me roz naye servers bante aur delete hote hain (IP change hoti rehti hai). Service Discovery (like Consul/ZooKeeper) ek register ki tarah hoti hai. Jab bhi naya server banta hai, wo apna IP wahan likhwa deta hai, taaki baaki services use easily dhoondh sakein bina hardcoded IP ke."
Q30. How would you handle a viral flash sale (like Flipkart Big Billion Days)?
"10 lakh log ek sath button dabayenge. MySQL turant crash ho jayega. Hum request aate hi usko seedha Message Queue (Kafka) me daal kar user ko bol denge 'Your order is being processed'. Phir piche se kuch worker nodes dheere-dheere queue se order uthaenge aur aram se MySQL me insert karte rahenge (Asynchronous Order Processing)."
