Top 30 LLD & Design Patterns Interview Questions

Mastering OOPs, SOLID, and Gang of Four Patterns (Hinglish Explanations)

Q1. What is Object-Oriented Programming (OOP)?
"OOP ek programming style hai jisme hum variables aur functions ko khula chhodne ke bajaye, unhe ek 'Object' (jaise Car ya User) ke andar pack kar dete hain. Isse code real-world chizon se match karta hai aur maintain karna easy ho jata hai."
Q2. Name the 4 Pillars of OOPs.
"1. Encapsulation (Data chhupana). 2. Abstraction (Complexity chhupana). 3. Inheritance (Code reuse karna). 4. Polymorphism (Ek function, bohot saare roop)."
Q3. Explain Encapsulation.
"Capsule ki tarah data ko andar lock kar dena. Ek User class me 'balance' variable ko `private` banana taaki bahar se koi usko direct edit (`user.balance = 5000`) na kar sake. Usme paise dalne ke liye public method (`depositMoney`) allow karna."
Q4. What is the difference between Encapsulation and Abstraction?
"Encapsulation ka goal 'Security' (hiding internal state) hota hai. Abstraction ka goal 'Simplicity' (hiding internal complexity) hota hai. Jaise gaadi (car) me steering wheel Abstraction hai (engine kaise kaam karta hai ye nahi janna padta), aur bonnet ke andar locked engine Encapsulation hai (koi chedchad nahi kar sakta)."
Q5. What is Inheritance?
"Maa-baap ke features bacchon me aana. Agar ek `BaseUser` class me `login()` function hai, toh hum `Admin` aur `Customer` class banate waqt `BaseUser` ko extend kar sakte hain. Hume login ka code 3 baar nahi likhna padega (Code Reusability)."
Q6. Explain Polymorphism.
"Polymorphism matlab 'Many Forms'. Jaise ek `sendNotification()` function hai. Agar main usko 'Email' object du toh wo email bhejega, 'SMS' object du toh SMS bhejega. Function ka naam same hai, par uska kaam input ke hisaab se badal jata hai bina kisi if-else ke."
Q7. What is the difference between an Interface and an Abstract Class?
"Interface ek contract hota hai jisme sirf functions ke naam hote hain (koi logic nahi hota). Multiple interfaces ek class me lag sakti hain. Abstract class me kuch functions ka logic ho sakta hai aur kuch khali chode ja sakte hain (abstract). Lekin aap sirf 1 hi abstract class ko inherit kar sakte ho."
Q8. What is Method Overloading vs Method Overriding?
"Overloading (Compile-time Polymorphism): Ek hi class me same naam ke 2 functions par arguments alag hon (e.g. `add(a,b)` aur `add(a,b,c)`). Overriding (Runtime Polymorphism): Child class Parent class ke function ko rewrite karti hai apna logic daalne ke liye."
Q9. What does S.O.L.I.D stand for?
"S - Single Responsibility Principle, O - Open/Closed Principle, L - Liskov Substitution Principle, I - Interface Segregation Principle, D - Dependency Inversion Principle. Ye uncle bob ke 5 rules hain clean code likhne ke liye."
Q10. Explain Single Responsibility Principle (SRP).
"Ek class ka sirf EK HI kaam hona chahiye (One reason to change). Agar ek 'UserController' validation bhi kar raha hai, database me save bhi kar raha hai, aur Email bhi bhej raha hai, toh SRP toot gaya. Teeno kaamon ke liye alag service classes banani chahiye."
Q11. Explain Open/Closed Principle (OCP).
"Class should be OPEN for extension but CLOSED for modification. Agar VIP discount add karna hai, toh purani file khol kar `if(VIP)` mat likho (bugs aa sakte hain). Ek nayi `VIPDiscount` class banao aur extend karo. Purana code untouched rehna chahiye."
Q12. Explain Liskov Substitution Principle (LSP).
"Child class Parent ki jagah le sakti hai bina kisi error ke. Agar Parent me `fly()` method hai, aur Penguin (Child) usme error throw kar de, toh aapne LSP tod diya! Jo promise parent karta hai, child wo promise nahi tod sakta."
Q13. Explain Interface Segregation Principle (ISP).
"Ek bohot bada 'Fat Interface' mat banao. Agar aapki interface me 10 methods hain (e.g. `print()`, `scan()`, `fax()`), toh ek basic Printer ko scan aur fax zabardasti implement karna padega. Badi interface ko 3 choti interfaces me tod dena chahiye."
Q14. Explain Dependency Inversion Principle (DIP).
"High-level module low-level module par depend nahi karna chahiye. Matlab aapka Checkout system directly 'Stripe' library se tightly-coupled nahi hona chahiye. Beech me ek 'PaymentInterface' hona chahiye taaki kal ko Stripe hata kar PayPal lagana ho toh 1 line me ho jaye."
Q15. What are Design Patterns?
"Software development me kuch problems baar-baar aati hain (jaise DB connection manage karna). Design Patterns un problems ke proven, ready-made solutions hain jo 'Gang of Four' (4 senior engineers) ne 1994 me likhe the."
Q16. Name the 3 types of Design Patterns.
"1. Creational (Object kaise banega - e.g. Singleton, Factory). 2. Structural (Classes aapas me kaise judengi - e.g. Adapter, Decorator). 3. Behavioral (Classes ek dusre se baat kaise karengi - e.g. Observer, Strategy)."
Q17. Explain the Singleton Pattern.
"Jab hum chahte hain ki puri app me kisi class ka sirf EK HI object bane. Jaise Database connection. Agar har file `new DB()` karegi toh MySQL crash ho jayega. Hum constructor ko `private` kar dete hain aur `getInstance()` method banate hain."
Q18. What is the Factory Method Pattern?
"Jab object banane ka logic bohot bada ho (lamba if-else block). Hum wo kachra logic Controller se nikal kar ek 'Factory' class me daal dete hain. Controller bas bolta hai `Factory.create('Email')` aur factory usko object bana kar de deti hai."
Q19. Explain the Observer Pattern.
"Ye event-driven programming (Pub-Sub) hai. Jab User register hota hai toh 3 aur cheezein karni hain (Email, Analytics, Bonus). Hum un teeno ko main function me tightly-couple karne ke bajaye ek 'UserRegistered' event EMIT karte hain, aur teeno classes apna-apna kaam sun (LISTEN) ke kar leti hain."
Q20. What is the Strategy Pattern?
"Jab aapke paas ek kaam karne ke 10 algorithms (tarike) hon (Jaise 10 alag-alag Discount Coupons). Inko `if-else` me fasane ke bajaye, har algorithm ki alag class banate hain (Strategy), aur runtime par jisko chahein swap kar lete hain."
Q21. Explain the Decorator Pattern.
"Agar ek class me runtime par naye features add karne hon bina usko modify kiye (OCP). Jaise ek `Coffee` class hai. Hum uske upar `MilkDecorator` aur `SugarDecorator` lapet (wrap) sakte hain uska price badhane ke liye."
Q22. What is the Adapter Pattern?
"Do incompatible (alag-alag) interfaces ko jodne ka kaam karta hai. Jaise aapke paas 2-pin charger hai aur board 3-pin hai. Aap beech me Adapter lagate ho! Code me ye legacy code (XML) aur naye code (JSON) ko connect karne ke kaam aata hai."
Q23. Explain the Facade Pattern.
"Facade ka matlab 'Mukhauta' (Front door). Piche 10 complex APIs/Classes chal rahi hain (OrderProcessor, PaymentGateway, InventoryCheck), par Frontend ko wo sab handle nahi karna! Hum ek simple `OrderFacade` class banate hain jisme ek simple `placeOrder()` function hota hai."
Q24. What is the Builder Pattern?
"Jab ek object banane me 15 arguments pass karne padein (Telescoping constructor problem: `new User(name, age, null, null, null, address)`). Builder pattern ek step-by-step approach deta hai: `new UserBuilder().setName('A').setAge(20).build()`."
Q25. What does DRY stand for?
"Don't Repeat Yourself. Agar aapne ek hi logic 2 alag-alag jagah likh diya hai (copy-paste), toh jab usme bug aayega toh aapko dono jagah theek karna padega. Us logic ko ek helper/utility function me nikal kar reuse karna chahiye."
Q26. What does KISS stand for?
"Keep It Simple, Stupid. Engineers over-engineering karke simple array filter ko map-reduce-promise-all me ghuma dete hain jisko koi aur samajh nahi pata. Code hamesha simple aur readable hona chahiye 'Smart' dikhne ke bajaye."
Q27. What does YAGNI stand for?
"You Aren't Gonna Need It. Developers aage ke 5 saal ka soch kar aise complex abstract classes aur interfaces bana dete hain jinme aaj ki date me kuch bhi use nahi ho raha. 'Future-proofing' ke chakkar me aaj ka code complex mat banao. Jab zaroorat hogi tab add karlena."
Q28. What is tight coupling vs loose coupling?
"Tight coupling: Class A directly Class B ka naam (`new Stripe()`) use kar rahi hai. Agar B me bug aaya toh A bhi toot jayegi. Loose coupling: Class A ko pata hi nahi hai B kaun hai, wo ek Interface (`IPayment`) ke through baat karti hai. Aise me B ko delete karke C lagana bohot easy hota hai (Dependency Inversion)."
Q29. Why is composition preferred over inheritance?
"Inheritance (is-a relationship) me ek time baad 'Gorilla-Banana' problem aa jati hai (Banana mangoge toh pura jungle sath aayega). Composition (has-a relationship) me hum dusri classes ke features inherit karne ke bajaye unke objects apni class me inject kar lete hain. Ye bohot flexible hota hai."
Q30. How do you test private methods in a class?
"Tricky question! Best practice kehti hai ki aapko Private methods ko unit test nahi karna chahiye. Aapko sirf Public methods (jo un private methods ko use kar rahe hain) unko test karna chahiye. Agar koi private method itna complex hai ki testing mang raha hai, toh use extract karke ek nayi class ka public method bana do!"
