Top 30 Node.js & Express Interview Questions

Specially curated for Startups & Mid-Size Companies (Hinglish Explanations)

Q1. What is Node.js and how does it work?
"Node.js ek runtime environment hai jo Chrome ke V8 engine par chalta hai. Ye Javascript ko browser ke bahar (server par) chalne ki takat deta hai. Iska architecture Single-Threaded, Non-Blocking, aur Event-Driven hota hai." Node.js uses a single thread to handle all incoming requests. When an I/O operation (like DB query or file read) is encountered, it delegates it to the C++ Libuv library (Thread Pool) and moves to the next request without waiting.
Q2. Explain the Event Loop in Node.js.
"Event Loop Node.js ka dil (heart) hai. Ye check karta hai ki kya koi async task complete ho gaya hai. Agar ho gaya hai, toh uske callback function ko wapas Call Stack me daal deta hai execute hone ke liye." It runs in 6 phases: Timers (setTimeout) -> Pending Callbacks -> Idle/Prepare -> Poll (I/O callbacks) -> Check (setImmediate) -> Close Callbacks.
Q3. What is the difference between `setTimeout` and `setImmediate`?
"Dono functions async hain, par execution order alag hota hai. `setTimeout` tab chalta hai jab uska time khatam ho jaye (Timers phase me). `setImmediate` tab chalta hai jab current Poll phase khatam ho jaye (Check phase me)." If called from within an I/O cycle (like inside `fs.readFile`), `setImmediate` will always execute BEFORE `setTimeout(..., 0)`.
Q4. What is `process.nextTick()`?
"Ye Event Loop ka part nahi hai! Agar aap `process.nextTick(cb)` use karte ho, toh uska callback EVENT LOOP KI NEXT PHASE SHURU HONE SE PEHLE (instantly) chalega. Ye `setImmediate` se bhi fast hai." It is used for urgent operations that must complete before any other I/O events are processed.
Q5. Node.js is Single Threaded. Then how does it handle concurrency?
"Node.js ka main code ek thread me chalta hai, par uske peeche **Libuv** naam ki library hoti hai jiske paas 4 se 128 background threads hote hain (Thread Pool). Sabhi heavy I/O operations (file read, DB, cryptography) un background threads par bhej diye jate hain."
Q6. What are Streams in Node.js?
"Agar 5GB ki movie file read karni hai, toh `fs.readFile()` RAM ko full karke server crash kar dega. Streams data ko chhote-chhote tukdo (Chunks) me read/write karti hain (Netflix buffering ki tarah)." Types of streams: Readable, Writable, Duplex (Both), and Transform (Modify data while passing).
Q7. What are Buffers?
"Jab hum Streams use karte hain, toh raw binary data aane ka wait karta hai. Buffer ek temporary memory location (RAM me) hai jahan data ikattha hota hai jab tak usko process nahi kiya jata." It is essentially an array of integers representing memory allocation outside the V8 heap.
Q8. What is the difference between `fs.readFile` and `fs.createReadStream`?
"`readFile` puri file ko ek sath RAM me load karta hai, jisse memory full ho sakti hai. `createReadStream` file ko chunks (e.g. 64KB) me read karta hai, jo memory-efficient hai."
Q9. What is Event Emitter?
"Ye Observer Design Pattern ka Node.js implementation hai. Iske through ek class event emit kar sakti hai (`emitter.emit('event')`), aur dusri files usko listen kar sakti hain (`emitter.on('event', cb)`). Ye decoupled code likhne ke kaam aata hai."
Q10. How do you handle CPU-intensive tasks in Node.js?
"Kyunki Node.js Single Threaded hai, koi bhi heavy video processing ya image editing us main thread ko block kar degi. Isko solve karne ke liye hum **Worker Threads** ya **Child Processes** ka use karte hain taaki heavy kaam alag thread me chalta rahe."
Q11. What is Middleware in Express.js?
"Middleware wo function hota hai jiske paas Request (req) aur Response (res) object ka access hota hai. Ye Request aane par aur Controller chalu hone ke beech me chalta hai. Iska main kaam Auth check karna ya data modify karna hota hai. Isme hamesha `next()` call karna zaroori hai."
Q12. What is the difference between `app.use()` and `app.get()`?
"`app.use()` middleware mount karne ke liye hota hai aur ye har HTTP method (GET, POST, PUT) par chalta hai agar route match ho. `app.get()` specifically sirf GET requests ke liye chalega."
Q13. How do you handle Uncaught Exceptions in Node.js?
"Agar aapke code me koi error throw hua jisko try-catch nahi kiya, toh app crash ho jati hai. Ise bachane ke liye hum `process.on('uncaughtException')` use karte hain. Lekin best practice ye hai ki error log karke server gracefully restart (via PM2) kar diya jaye."
Q14. What is the difference between Uncaught Exception and Unhandled Rejection?
"`UncaughtException` tab aata hai jab synchronous code me error aaye. `UnhandledRejection` tab aata hai jab kisi Async Promise me error (reject) aaye aur aapne `.catch()` ya try-catch na lagaya ho."
Q15. Explain CORS (Cross-Origin Resource Sharing).
"Browser default policy ke hisaab se ek website (`a.com`) dusri website (`b.com`) ki API hit nahi kar sakti security reasons ke liye. Ise bypass karne ke liye Express me CORS middleware use hota hai jo headers set karta hai (`Access-Control-Allow-Origin`)."
Q16. How does JWT authentication work?
"User login karta hai, server usko ek encrypted Token (JWT) bana kar bhejta hai. Ab har request me user wo token Headers me bhejta hai. Server token ko verify karta hai. JWT stateless hota hai (matlab session ko DB me store nahi karna padta)." Structure: Header (Algorithm) . Payload (User Data) . Signature (Verification).
Q17. What happens if a JWT is stolen? How do you prevent it?
"Agar JWT chori ho gaya toh hacker use login karne ke liye use kar lega (kyunki JWT ko invalidate nahi kiya ja sakta). Isse bachne ke liye JWT ki expiry time bohot kam (15 mins) rakhte hain. Aur ek 'Refresh Token' DB me save karte hain naya JWT lene ke liye. Token hamesha HttpOnly secure cookies me store karna chahiye."
Q18. Why is Node.js not recommended for Heavy CPU operations?
"Node.js single threaded hai. Agar aapne 10 second ka math calculation (ya image resize) main thread par laga diya, toh wo 10 second ke liye ruk jayega aur kisi bhi naye user ki HTTP request serve nahi karega. (Server hang ho jayega!)."
Q19. What is Cluster module in Node.js?
"Cluster module Node.js ki ek trick hai jisse hum ek single-threaded app ko multicore (e.g. 8 cores) server par scale karte hain. Ye main process banata hai aur 8 'worker processes' fork (copy) kar deta hai, taaki app 8x zyada traffic handle kar sake. PM2 usually ye internally handle kar leta hai (`pm2 start app.js -i max`)."
Q20. What is dependency injection in Node.js?
"Ye ek SOLID principle (Dependency Inversion) hai. Iska matlab hai classes ko andar create (`new UserService()`) karne ke bajaye, unhe bahar se (constructor ke through) bhej do. Isse code easily testable ho jata hai (Mocks use karke)."
Q21. How do you prevent SQL Injection/NoSQL Injection in Node.js?
"User se aaye data ko kabhi bhi query me directly merge nahi karna chahiye (`SELECT * FROM users WHERE email = '${email}'`). Hamesha **Parameterized Queries / Prepared Statements** (`[email]`) ya ORM/ODM (like Prisma, Mongoose) use karna chahiye jo automatically injection rok dete hain."
Q22. What is the purpose of `package-lock.json`?
"`package.json` me versions me `^` (caret) laga hota hai. Jiska matlab hai next update install ho jayega. `package-lock.json` exact version (down to the last decimal) aur dependency-tree lock karke rakhta hai. Taaki jo code aapke laptop me chal raha hai, exactly wahi production server par chale!"
Q23. Explain Rate Limiting. Why is it used?
"Rate limiting ensure karta hai ki ek User ya IP address ek minute me sirf fixed number of requests (e.g. 100 requests) bhej sake. Iska use DDOS attacks aur Brute-force password guessing se bachne ke liye hota hai. (Usually implemented using `express-rate-limit` package)."
Q24. How does Garbage Collection work in V8?
"V8 engine automatically RAM free karta hai jab variables ka use khatam ho jata hai. Ye **Mark and Sweep** algorithm use karta hai. Jo memory unreachable ho jati hai (jisko koi variable point nahi kar raha), usko 'Sweep' karke clean kar deta hai."
Q25. What causes Memory Leaks in Node.js?
"Memory leak tab hota hai jab Garbage collector kisi object ko delete nahi kar pata kyunki koi global variable usko still reference kar raha hota hai. Common causes: Global Arrays push hote rehna bina khali kiye, aur Unclosed database/event listeners."
Q26. What is REPL in Node.js?
"REPL ka matlab hai Read-Eval-Print-Loop. Ye Node.js ka command line environment (shell) hai jahan aap seedhe JS likh kar execute kar sakte ho bina file banaye (Terminal me sirf `node` likhne par jo start hota hai)."
Q27. What is the purpose of `module.exports` vs `exports`?
"`module.exports` real object hai jo return hota hai. `exports` sirf ek chhota reference (shortcut pointer) hai `module.exports` ka. Agar aap `exports = function() {}` likhoge, toh link toot jayega aur kuch export nahi hoga. Hamesha `module.exports` use karna best practice hai."
Q28. How do you debug a Node.js application?
"Sirf `console.log()` use karna amateur approach hai. Senior devs Node.js inspector (`node --inspect index.js`) use karte hain jo Chrome DevTools se connect ho jata hai, ya fir VS Code ka inbuilt debugger use karke breakpoints lagate hain."
Q29. What is the difference between Dependencies and DevDependencies?
"`Dependencies` wo libraries hain jo app ko Production server par chalne ke liye chahiye (e.g. express, mongoose). `DevDependencies` sirf aapko development ke time chahiye (e.g. typescript, nodemon, jest). Production me `npm install --production` sirf main dependencies install karta hai."
Q30. How do you handle file uploads in Express?
"Express directly multipart/form-data (files) handle nahi kar sakta. Humko **Multer** naam ka middleware use karna padta hai. Multer file ko binary se nikal kar server ke temporary folder me save karta hai, jiske baad hum usko AWS S3 par bhej dete hain."
