Component Refactoring: Bootstrap HTML vs Tailwind React

Side-by-side comparison of a modern responsive Button with loading spinner:

❌ Bootstrap HTML (Rigid, needs custom CSS): 
<button class="btn btn-primary btn-lg shadow-sm">
    <span class="spinner-border spinner-border-sm" role="status"></span>
    Save Changes
</button>
✅ React + Tailwind Component (Clean Props API): 
export function Button({ variant = 'primary', loading, children, ...props }) {
    return (
        <button 
            className={cn(
                "inline-flex items-center justify-center px-4 py-2 font-medium rounded-xl transition-all focus:ring-2",
                variant === 'primary' ? "bg-indigo-600 hover:bg-indigo-700 text-white shadow-sm" : "bg-slate-100 text-slate-800"
            )}
            disabled={loading}
            {...props}
        >
            {loading && <Spinner className="mr-2 h-4 w-4" />}
            {children}
        </button>
    );
}
Step-by-Step Tailwind Installation & tailwind.config.js for Laravel 11

Terminal installation workflow and production configuration for scanning Blade templates, React JSX files, and custom theme tokens:

# 1. Install Tailwind, PostCSS & Autoprefixer
npm install -D tailwindcss postcss autoprefixer

# 2. Generate tailwind.config.js & postcss.config.js
npx tailwindcss init -p

# 3. Add to resources/css/app.css:
@tailwind base; @tailwind components; @tailwind utilities; 
import defaultTheme from 'tailwindcss/defaultTheme';
import forms from '@tailwindcss/forms';
import typography from '@tailwindcss/typography';

export default {
    darkMode: 'class', // Controlled via <html class="dark">
    content: [
        './vendor/laravel/framework/src/Illuminate/Pagination/resources/views/*.blade.php',
        './resources/views/**/*.blade.php',
        './resources/js/**/*.jsx', // Essential for scanning React components!
    ],
    theme: {
        extend: {
            fontFamily: {
                sans: ['Inter', ...defaultTheme.fontFamily.sans],
            },
            colors: {
                brand: {
                    50: '#eef2ff',
                    600: '#4f46e5',
                    700: '#4338ca',
                }
            }
        },
    },
    plugins: [forms, typography],
};
Why Overusing @apply in React is an Anti-Pattern

Don't recreate Bootstrap inside CSS files when building React applications:

Approach Code Drawback in React
Overusing @apply in CSS ❌ .my-btn { @apply px-4 py-2 bg-blue-600 rounded; } Re-introduces CSS context switching; cannot pass dynamic React props like variant="danger".
React Component Extraction ✅ <Button variant="primary"> Complete design freedom; single source of truth in JSX; 100% purged minimal CSS bundle.
