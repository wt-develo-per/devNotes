EC2, VPC & Load Balancing

🏰 Networking • Part 1

Virtual Private Cloud (VPC)

VPC aapka AWS ke andar ek apna "Private Data Center" hai. Isme aap decide karte ho kaunsi cheez internet se connect hogi aur kaunsi nahi.

🌐 Public Subnets

Yeh wo hissa hai jo directly Internet se connected hota hai (via Internet Gateway).
Kisko rakhein yahan? Load Balancers aur frontend/backend servers (agar aap simple setup kar rahe ho) yahan rakhe jaate hain. Yahan resources ke paas ek Public IP address hota hai.

🔒 Private Subnets

Yahan koi Public IP address nahi hota. Bahar se koi hacker seedha yahan nahi pahunch sakta.
Kisko rakhein yahan? Databases (RDS, PostgreSQL) hamesha yahan rakhe jate hain! Sirf Public Subnet mein baithe hue Node.js servers hi Database se baat kar sakte hain.

Note: Agar Private Subnet ki kisi machine ko software update ke liye internet chahiye, toh hum Public subnet mein ek NAT Gateway banate hain, jo uske liye traffic fetch karke laata hai.

🔥 Firewalls • Part 2

Security Groups (The Bouncers of EC2)

Security Groups (SG) virtual firewalls hain jo EC2 instance par lagte hain. Yeh decide karte hain kaunsa traffic andar aa sakta hai (Inbound) aur bahar jaa sakta hai (Outbound).

🚨 Common Mistake

Databases (Port 5432) par 0.0.0.0/0 (All Traffic) open rakhna ek disaster hai. Hacker internet se DB try karega.
The Right Way: Database ke Security Group mein sirf "Allow traffic from Node.js Security Group" rule add karein. Yani Internet -> Node.js -> Database.

⚖️ Traffic Management • Part 3

Application Load Balancer (ALB)

Maan lijiye aapka Node.js server 1000 requests per second (RPS) handle kar sakta hai. Traffic achanak 3000 RPS ho gaya. Ab kya hoga? Ek server crash ho jayega.

Solution: Aap 3 EC2 servers chalayenge. Par user kis IP address par hit karega? Yahan ALB aata hai.

  • User hamesha ALB ke URL par request bhejta hai.
  • ALB dekhta hai: "Server A busy hai, Server B thoda free hai. Chalo request B ko bhej dete hain". Isko Round Robin algorithm kehte hain.
  • ALB hamesha Health Checks karta rehta hai. Agar Server C crash ho gaya, toh ALB usko traffic bhejna band kar dega aur baki do ko bhejega (High Availability).

✅ ALB is Layer 7

Application Load Balancer HTTP/HTTPS URLs ko samajhta hai. Aap rules laga sakte ho: Agar URL /api/* hai toh traffic Node.js Servers ko bhejo, agar /blog/* hai toh WordPress server ko bhejo.

📈 Automation • Part 4

Auto Scaling Groups (ASG)

Agar traffic raat mein zyada aata hai aur din mein kam, toh har waqt 10 servers chalana paise ki barbadi hai. ASG yeh kaam automate karta hai.

Kaise kaam karta hai?

  1. Aap ek Launch Template banate hain jisme batate hain ki jab bhi naya server bane, usme Ubuntu ho, Node.js install ho, aur code Github se clone ho jaye.
  2. Aap ASG mein ek rule lagate hain: "Agar sabhi current servers ka CPU utilization 70% se zyada ho jaye, toh 2 naye servers aur launch kar do."
  3. Jaise hi naye servers ready hote hain, ASG unko Load Balancer (ALB) ke saath connect kar deta hai.
  4. Jab traffic wapas kam ho jata hai (e.g., CPU < 30%), toh ASG automatically un extra servers ko terminate kar deta hai, paise bachane ke liye (Scale In).

Reminder: Modue 02 me humne "Stateless" rule padha tha. Agar Node server stateful hoga (files HDD pe hongi), toh jab ASG scale-in karke server delete karega, toh aapka data bhi chala jayega! Isiliye S3 & RDS zaroori hain.
