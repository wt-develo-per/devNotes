🧱 Architecture • Part 1

The "Stateless Server" Rule

Sabse badi galti naye developers kya karte hain? Wo Node.js mein Multer use karke files ko EC2 instance ke `/uploads` folder mein save kar dete hain.

❌ Stateful Server (Bad)

Agar aapki website popular ho gayi aur Load Balancer ne 3 EC2 servers on kar diye, toh jab user photo upload karega wo Server 1 par jayegi. Par jab agle din wo user login karega, toh Load Balancer usko Server 2 par bhej sakta hai... wahan photo nahi hogi! User ko broken image dikhegi.

✅ Stateless Server (Good)

EC2 instances kabhi bhi terminate aur recreate ho sakte hain (Auto Scaling). Isliye servers par sirf code hona chahiye, data nahi. Saari files directly S3 me jani chahiye, aur S3 ka URL database me save hona chahiye.

🔐 Security • Part 2

Pre-signed URLs (Downloads)

Agar aap paid video courses ya private PDFs bech rahe hain, toh S3 bucket ko Public nahi kar sakte (warna koi bhi download kar lega). Toh paid users ko file kaise dein?

💡 Solution: Time-limited Magic Links

Node.js backend AWS SDK se ek "Pre-signed URL" maangta hai. Yeh ek URL hota hai jiske end me ek lamba cryptographic signature aur Expiry Time hota hai (e.g., 3600 seconds).

Aap ye URL frontend ko bhejte ho. User video play kar leta hai. Agar wo URL copy karke doston ko WhatsApp pe bhejta hai, toh 1 ghante baad link hamesha ke liye expire ho jayegi aur doston ko "Access Denied" milega.

📤 Performance • Part 3

Pre-signed URLs (Uploads) & Bypassing Backend

Maan lijiye user 2GB ki 4K video upload kar raha hai. Agar aap ye frontend -> Node.js -> S3 bhejenge, toh aapka Node.js server RAM crash kar dega aur baki API requests block ho jayengi!

The Pro Pattern: Client-Side Direct Upload

  1. Frontend: React.js bolega "Hey Node, mujhe video.mp4 S3 me daalni hai."
  2. Node.js: AWS SDK use karke ek Pre-signed UPLOAD URL banayega aur React ko wapas de dega. (Server par koi file touch nahi hui).
  3. Frontend: React directly us URL par PUT request marega aur 2GB ki file seedha AWS S3 me jayegi. Node.js free betha hai doosre users ko serve karne ke liye!
  4. Node.js: Upload hone ke baad, Frontend Node ko bas itna batayega "File chali gayi", aur Node database me entry save kar dega.

Note: S3 bucket me CORS (Cross-Origin Resource Sharing) allow karna padta hai taaki browser directly S3 se communicate kar sake.

💻 Code • Part 4

Generating Pre-signed URLs in Node.js

AWS SDK v3 ka syntax thoda different aur modular hai. Chaliye Express.js me Upload URL generate karne ka code dekhte hain.

TypeScript • SDK v3 S3 Upload URL 
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

// Remember Module 1? Credentials automatically resolve ho jayenge!
const s3Client = new S3Client({ region: "ap-south-1" });

export const generateUploadURL = async (fileName: string, contentType: string) => {
    const bucketName = "my-production-bucket";
    // Always generate unique names in S3 to prevent overwriting
    const uniqueKey = `uploads/${Date.now()}-${fileName}`;

    const command = new PutObjectCommand({
        Bucket: bucketName,
        Key: uniqueKey,
        ContentType: contentType // e.g., 'image/png' or 'video/mp4'
    });

    // Create a URL that expires in 60 seconds
    const uploadUrl = await getSignedUrl(s3Client, command, { expiresIn: 60 });

    return { uploadUrl, key: uniqueKey };
};

// Express Route
app.post('/api/get-upload-link', async (req, res) => {
    const { fileName, fileType } = req.body;
    const data = await generateUploadURL(fileName, fileType);
    res.json({ success: true, data });
});

Frontend par ab hum directly `axios.put(data.uploadUrl, file, { headers: { 'Content-Type': fileType } })` call karenge, aur Node.js ki memory puri tarah safe rahegi!
