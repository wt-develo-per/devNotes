☁️ Fundamentals • Part 1

What is Serverless?

"Serverless" ka matlab yeh nahi ki servers nahi hain. Iska matlab hai "Aapko" servers manage nahi karne hain.

❌ Traditional EC2

Aap EC2 instance chalu karte hain aur uspar Node.js server chalate hain (listening on port 3000). Aap har ghante ka paisa dete hain, chahe koi user website par aaye ya na aaye (idle cost).

✅ AWS Lambda (Serverless)

Aap sirf apna JavaScript code AWS ko de dete hain. Jab koi request aati hai, AWS automatically ek naya mini-container banata hai, aapka code run karta hai, aur phir container destroy kar deta hai. Aap sirf Execution Time (in milliseconds) ka paisa dete hain. Zero users = Zero bill!

🚪 Routing • Part 2

Amazon API Gateway (The Entry Point)

Lambda functions khud internet se URL par listen nahi kar sakte (jaise app.listen(3000) in Express). Unhe trigger karna padta hai.

Yahan API Gateway ka role aata hai:

  • Yeh ek managed service hai jo HTTP Requests (GET, POST) accept karti hai.
  • Aap API Gateway ko batate ho: "Agar POST /users par request aaye, toh 'CreateUserLambda' ko trigger karo."
  • Yeh scaling bhi handle karta hai (Agar 100,000 log ek sath hit karein, API Gateway AWS ko bolega 100,000 Lambda functions spawn kar do!)
  • Aap isme Rate Limiting, API Keys, aur IAM/Cognito Authorization bhi directly set kar sakte hain bina code likhe.

💡 The Serverless Monolith (Serverless Express)

Naye developers ek-ek endpoint ke liye alag Lambda banate hain (Microservices). Isse manage karna mushkil ho jata hai.
Pro Pattern: Aap apni poori Express.js app ko ek hi Lambda mein wrap kar sakte hain (using packages like serverless-http). API Gateway saari requests ko ek hi Lambda par bhejta hai, aur Express khud decide karta hai ki kaunsa router chalana hai.

💻 Implementation • Part 3

The Node.js Lambda Handler

Express.js me req aur res hote hain. Lambda me event aur context hote hain.

JavaScript • Simple Lambda Handler 
export const handler = async (event, context) => {
    // 'event' me API Gateway se aayi hui request details hoti hain
    const httpMethod = event.httpMethod;
    const body = JSON.parse(event.body || "{}");

    try {
        // DB logic here (e.g. DynamoDB call)
        
        // Response wapas API Gateway ko bhejna (Must be this exact format)
        return {
            statusCode: 200,
            headers: {
                "Content-Type": "application/json",
                "Access-Control-Allow-Origin": "*" // CORS
            },
            body: JSON.stringify({
                message: "Hello from Serverless Node.js!",
                receivedData: body
            })
        };
    } catch (error) {
        return {
            statusCode: 500,
            body: JSON.stringify({ error: "Internal Server Error" })
        };
    }
};
❄️ Performance • Part 4

The "Cold Start" Problem

Serverless ka sabse bada dushman. Agar Lambda kafa der tak use nahi hua, toh AWS container ko destroy kar deta hai.

Jab agli request aati hai, AWS ko:

  1. Naya container banana padta hai.
  2. Node.js environment initialize karna padta hai.
  3. Aapka code (aur saari dependencies) load karni padti hain.
  4. Database connections open karne padte hain.

Is process me 1-3 seconds lag sakte hain. Isko "Cold Start" kehte hain. Iske baad aane wali requests microseconds me serve hoti hain (Warm Start).

🛠️ How to fix Cold Starts in Node.js

  • Keep dependencies small: Lambda ka size jitna bada hoga (e.g., heavily packed `node_modules`), cold start utna zyada hoga. Sirf zaroori packages use karein.
  • Initialize connections outside the handler: DB connections handler function ke bahar (global scope me) banayein, taaki wo warm starts me reuse ho sakein.
  • Provisioned Concurrency: Agar app production me hai aur cold starts acceptable nahi hain, toh aap AWS ko extra paise de kar kuch containers hamesha "Warm" rakhne ke liye bol sakte hain.
