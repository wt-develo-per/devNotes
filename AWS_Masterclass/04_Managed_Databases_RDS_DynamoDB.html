Managed Databases (RDS & DynamoDB)

Data aapki application ka sabse important hissa hai. Ek EC2 instance banakar usme PostgreSQL install karna sabse badi galti hai! AWS "Managed" databases offer karta hai jo scaling, backups aur failovers automatically handle karte hain.

🚫 Fundamentals • Part 1

The EC2 Database Trap (Unmanaged)

Shuruwat mein har developer EC2 instance leta hai, apt-get install postgresql chalata hai aur sochta hai paise bach gaye.

❌ Unmanaged DBs on EC2

Agar raat 3 baje server crash ho gaya, toh aapko uthkar restart karna padega. Backups manually lene padenge. OS patches manually lagane padenge. Aur agar hard drive (EBS volume) fail hui, toh saara data gayab!

✅ Managed DBs (RDS / DynamoDB)

AWS kehta hai: "Aap sirf query likho, baaki main sambhalunga". Managed DBs mein AWS automatically OS updates, daily automated backups, aur hardware failures ko fix karta hai bina aapko uthaye.

🐘 Relational • Part 2

Amazon RDS (Relational Database Service)

RDS aapko PostgreSQL, MySQL, MariaDB, ya Oracle database chalaane deta hai cloud mein. Yeh exactly waisa hi kaam karta hai jaise aapka local DB, bas features "Enterprise" level ke hote hain.

🔑 Backend Developer Tip

Jaise hi RDS banayein, hamesha usko Private Subnet mein rakhein aur "Publicly Accessible" ko False mark karein. Aapke Node.js backend ko hi sirf DB se baat karne ki permission (via Security Groups) honi chahiye.

🔄 High Availability • Part 3

Multi-AZ & Read Replicas (Zero Downtime)

Maan lijiye AWS ka ek data center (Availability Zone "A") fail ho jata hai. App down nahi honi chahiye!

1. Multi-AZ (Disaster Recovery)

  • Jab aap RDS mein Multi-AZ on karte hain, toh AWS ek "Standby" database doosre data center (Zone B) mein bana leta hai.
  • Aapka app sirf Primary (Zone A) pe write karta hai. AWS khud data ko Standby pe copy karta rehta hai (Synchronous replication).
  • Agar Zone A crash hua, toh AWS 1 minute mein connection Standby par shift kar dega. Apke Node.js app ko connection string badalne ki bhi zaroorat nahi padti!

2. Read Replicas (Scaling Queries)

  • Maan lo aapke Node.js app par din me 10,000 log "View Profile" kar rahe hain (Read) aur 10 log "Update Profile" kar rahe hain (Write).
  • Aap RDS mein Read Replicas bana sakte ho (Upto 15 copies). Apka backend saari "SELECT" queries Read Replicas par bhejega, aur "INSERT/UPDATE" queries Master par. Isse database ki speed double ho jayegi!
⚡ NoSQL • Part 4

Amazon DynamoDB (The Scalability Beast)

RDS servers use karta hai (e.g., `db.t3.medium`). Jab traffic badhta hai toh aapko server bada karna padta hai. DynamoDB Serverless NoSQL database hai!

Performance at Any Scale
Chahe database me 10 records hon ya 10 Billion (1,000 Crores), DynamoDB har query ka result Single-digit millisecond (<10ms) me wapas deta hai.
No Servers to Manage
DynamoDB mein EC2 instance choose nahi karna padta. Aap bas batate ho mujhe "10,000 Reads Per Second" chahiye, aur wo handle kar leta hai.

⚠️ The Catch: Table Design

PostgreSQL mein aap pehle data dalte ho aur baad mein JOIN ya complex WHERE queries sochte ho.
DynamoDB mein JOIN nahi hote! Aapko pehle apni saari "Access Patterns" (e.g., GetUserById, GetUserOrders) likhni padti hain, aur phir Partition Keys (`PK`) aur Sort Keys (`SK`) design karni padti hain. Ye seekhne mein kaafi time lagta hai.
