AI ko sirf baatein karne ke bajaye real-world Laravel actions execute karne ki power dein. Seekhenge Prism Tools banana, Strict JSON Schema output validation, multi-turn ReAct autonomous loops, DB transaction rollback safety, aur human-in-the-loop authorization gates!

⚙️ Function Calling Architecture & The Security Boundary
AI ko "Text Generator" se "Autonomous Operations Engine" mein transform karne ka mechanism.

Abhi tak humne dekha ki LLM sirf text ya Markdown generate karta tha. Lekin real enterprise software mein client chahta hai: "Mera order #8841 cancel kar do", "Subscription upgrade kar do", "Stripe par credit limit badha do."

Kaise Kaam Karta Hai Function Calling? (The Delegation Protocol)

LLM kabhi bhi directly aapke MySQL database ya PHP code ko run nahi karta (na hi use run karna chahiye). Yeh 4-step delegation cycle par kaam karta hai:

architecture function-calling-loop.txt 
[Step 1: Declare Tools]
Laravel ──► LLM: "Mere paas yeh 2 tools hain:
                   - getOrderStatus(order_id: int)
                   - processRefund(order_id: int, amount: float)"

[Step 2: User Prompt]
User ──► LLM: "Order #4092 ka status check karo aur $20 refund initiate karo."

[Step 3: Intent Detection & Tool Call Request]
LLM ──► Laravel: "Main text generate nahi kar raha. Kripya processRefund tool run karo:
                  Arguments: {'order_id': 4092, 'amount': 20.00}"

[Step 4: Secure PHP Execution & Resolution]
Laravel: Checks $user->can('refund', $order) ──► Calls Stripe ──► DB Update
Laravel ──► LLM: Tool Result: "{'status': 'success', 'refund_id': 're_9812'}"

[Step 5: Final Natural Language Summary]
LLM ──► User: "Order #4092 ke liye $20 ka refund successfully process kar diya gaya hai (Refund ID: re_9812)."

🚨 The Dangerous Misconception

Kuch developers sochte hain ki AI ko direct raw SQL run karne dena chahiye ya direct controller action execute karne dena chahiye. Yeh severe security vulnerability hai! Agar user prompt inject karega, toh AI poora database wipe out kar sakta hai.

🛡️ The Laravel Security Boundary

LLM is only an Intent Parser & Parameter Formatter.
Aapka Laravel backend Executive Authority hai. Tool execute hone se pehle Laravel Gate/Policy check karta hai, DB constraints enforce karta hai aur DB::transaction() ke andar safe execution karta hai.

💡 Why Function Calling is 100x More Reliable Than Prompting

Agar aap prompt mein likhenge: "Output JSON with order_id and amount", toh standard chat model kabhi ```json likh dega, kabhi extra commentary add kar dega, aur aapka PHP json_decode() fatal crash karega. Function Calling hardware-level constrained decoding use karta hai jo guarantee karta hai ki output valid, type-safe arguments honge!

🛠️ Defining Tools in Prism-PHP with Strict Type Schemas
Kaise Prism fluent API se self-documenting, type-safe tools define kiye jaate hain.

Prism-PHP mein tool define karna Laravel validation rules likhne jaisa intuitive hai. Model ko tool ka Name, Description aur Parameters provide kiye jaate hain.

💡 The Power of Tool Descriptions

LLM aapke PHP code ko nahi dekhta; woh sirf ->for('...') aur ->withParameter('...', 'Description') ko padhta hai! Agar aapki description descriptive hogi (e.g. "Use this tool whenever the customer mentions order delivery delay, shipping status, or tracking numbers"), toh LLM 99.9% accuracy ke saath right tool pick karega.

Tool 1: Anonymous Inline Tool Definition

Lightweight utility actions ke liye inline tool syntax:

php Inline Tool Definition 
use Prism\Prism\Facades\Tool;
use App\Models\Order;

$orderStatusTool = Tool::as('getOrderStatus')
    ->for('Retrieve live shipping status, tracking link, and estimated delivery date for a specific order.')
    ->withNumberParameter('order_id', 'The numeric ID of the customer order (e.g. 1042)', required: true)
    ->using(function (int $order_id): string {
        $order = Order::find($order_id);

        if (! $order) {
            return json_encode(['error' => 'Order not found in database.']);
        }

        return json_encode([
            'order_id'           => $order->id,
            'status'             => $order->status, // 'shipped', 'delivered', 'pending'
            'tracking_number'    => $order->tracking_code,
            'estimated_delivery' => $order->delivery_date?->format('Y-m-d'),
        ]);
    });

Tool 2: Standalone Enterprise Tool Class

Complex business actions ke liye reusable tool classes banana best practice hai (dependency injection aur testability ke liye):

php app/Ai/Tools/ProcessRefundTool.php 
<?php

namespace App\Ai\Tools;

use Prism\Prism\Tool;
use App\Models\Order;
use App\Services\PaymentGatewayService;
use Illuminate\Support\Facades\DB;

class ProcessRefundTool extends Tool
{
    public function __construct(
        protected PaymentGatewayService $paymentService
    ) {
        $this
            ->as('processOrderRefund')
            ->for('Process a partial or full refund for a customer order through Stripe.')
            ->withNumberParameter('order_id', 'The target order ID to refund', required: true)
            ->withNumberParameter('amount', 'The monetary amount in USD to refund (e.g. 24.50)', required: true)
            ->withStringParameter('reason', 'Customer reason for refund (e.g. late delivery, damaged item)', required: true)
            ->using($this->handle(...));
    }

    public function handle(int $order_id, float $amount, string $reason): string
    {
        return DB::transaction(function () use ($order_id, $amount, $reason) {
            $order = Order::lockForUpdate()->find($order_id);

            if (! $order) {
                return json_encode(['success' => false, 'error' => 'Order not found']);
            }

            if ($order->refunded_amount + $amount > $order->total_amount) {
                return json_encode([
                    'success' => false,
                    'error'   => 'Refund amount exceeds remaining order balance.'
                ]);
            }

            // Call Payment Gateway (e.g. Stripe)
            $refund = $this->paymentService->createRefund(
                chargeId: $order->stripe_charge_id,
                amountInCents: (int) ($amount * 100)
            );

            // Update Database
            $order->increment('refunded_amount', $amount);
            $order->update(['status' => 'partially_refunded']);

            return json_encode([
                'success'   => true,
                'refund_id' => $refund->id,
                'amount'    => $amount,
                'message'   => "Successfully refunded ${$amount} for Order #{$order_id}.",
            ]);
        });
    }
}
📐 Strict JSON Outputs & Grammar-Constrained Decoding
Kyun prompt mein "Return JSON" kehna amateur hai aur Strict JSON Schema 100% reliability deta hai.

Legacy AI integration mein developers prompt mein likhte the: "Please return your response as valid JSON only". Lekin production mein 100 mein se 4 baar model markdown backticks (```json) laga deta tha ya beech mein extra commentary bol deta tha, jisse backend parser crash ho jata tha.

Modern LLMs (GPT-4o, Claude 3.5, Gemini 1.5) Constrained Grammar Decoding support karte hain. Isme LLM ke logits ko token-by-token constrain kiya jata hai taaki woh aapke defined schema ke alawa koi aur character emit kar hi na sake!

namespace App\DataTransferObjects;

readonly class LeadData
{
    public function __construct(
        public string $customerName,
        public string $intent,
        public int $teamSize,

🔄 The Multi-Turn ReAct Agent Loop & Recursion Guards
Kaise AI model multi-step reasoning aur consecutive tool calls execute karke complex tasks solve karta hai.

Real-world problems aksar ek single tool call se solve nahi hote. User keh sakta hai: "Mera order #1042 check karo, agar delayed hai toh cancel karke refund issue karo aur mujhe new delivery policy email kar do."

The ReAct Pattern (Reasoning + Action) Cycle

architecture react-agent-steps.txt 
[TURN 1: REASONING]
Thought: Pehle mujhe order status check karna padega.
Action: Calls getOrderStatus(order_id: 1042)
Observation: {'status': 'delayed', 'delay_days': 6}

[TURN 2: REASONING]
Thought: Order 6 din delayed hai, policy ke anusaar cancel karke full refund karna hai.
Action: Calls processOrderRefund(order_id: 1042, amount: 89.99, reason: 'delayed')
Observation: {'success': true, 'refund_id': 're_5541'}

[TURN 3: REASONING]
Thought: Refund ho gaya. Ab user ko confirmation email bhejni hai.
Action: Calls sendEmailNotification(to: 'user@example.com', template: 'refund_issued')
Observation: {'queued': true}

[TURN 4: FINAL ANSWER]
Thought: Sabhi steps complete ho gaye. Ab customer ko polite response do.
Answer: "Aapka order #1042 delay hone ke karan cancel kar diya gaya hai. $89.99 ka full refund initiate ho chuka hai (ID: re_5541) aur confirmation email aapke inbox mein bhej di gayi hai."

Prism's Native Autonomous Loop with withMaxSteps()

Prism-PHP internally poore ReAct loop ko automate kar deta hai jab aap ->withTools([...]) aur ->withMaxSteps(...) specify karte hain:

php Autonomous Agent Execution 
use Prism\Prism\Facades\Prism;
use Prism\Prism\Enums\Provider;

$response = Prism::text()
    ->using(Provider::Anthropic, 'claude-3-5-sonnet-20241022')
    ->withSystemPrompt('You are an autonomous e-commerce concierge with authority to check orders, issue refunds, and send emails.')
    ->withTools([
        app(\App\Ai\Tools\GetOrderStatusTool::class),
        app(\App\Ai\Tools\ProcessRefundTool::class),
        app(\App\Ai\Tools\SendCustomerEmailTool::class),
    ])
    // CRITICAL: Max steps limit recursion guard!
    ->withMaxSteps(5)
    ->withPrompt('Order #1042 check karke refund karo agar delay hua hai.')
    ->generate();

// Final response after all tools finished executing
$finalMessage = $response->text;

// Audit all intermediate steps taken by the AI
foreach ($response->steps as $stepNumber => $step) {
    if (!empty($step->toolCalls)) {
        foreach ($step->toolCalls as $toolCall) {
            \Log::info("AI Step #{$stepNumber}: Called [{$toolCall->name}] with args: ", $toolCall->arguments());
        }
    }
}
🚨 The Infinite Loop Money Drain Trap

Agar aap ->withMaxSteps(5) nahi lagayenge aur koi tool exception return karta hai (e.g. "Stripe API timeout"), toh LLM use dobara retry karne ki koshish kar sakta hai. Without a step limit, model loop mein 200 baar tool call karega aur aapka $50 ka credit 3 minute mein drain ho jayega! Hamesha production mein maxSteps: 3 ya 5 enforce karein.

🛡️ Database Safety, Policy Authorization & Human-in-the-Loop
AI hallucinations aur unauthorized destructive actions se database ko protect karne ka defense-in-depth framework.

Jab aap AI ko tools provide karte hain, toh AI ke paas database par write aur delete karne ki power aa jaati hai. Agar security measures sahi na hon, toh user prompt injection ke zariye kisi doosre user ka order cancel karwa sakta hai ya pure database ko corrupt kar sakta hai!

Pillar 1: Never Trust AI Parameters for Ownership (Laravel Policies)

Agar user prompt mein likhta hai: "Order #9994 cancel kar do", toh LLM parameter mein order_id: 9994 bhej dega. Lekin kya user sach mein Order #9994 ka owner hai? Tool handler ke andar Laravel Gate/Policy check mandatory hai:

php Policy Authorization Check inside Tool 
use Illuminate\Support\Facades\Gate;

public function handle(int $order_id, string $reason): string
{
    $user = auth()->user();
    $order = Order::find($order_id);

    if (! $order) {
        return json_encode(['error' => 'Order does not exist.']);
    }

    // CRITICAL: Verify that the authenticated user actually owns this order!
    if (Gate::forUser($user)->denies('cancel', $order)) {
        return json_encode([
            'error' => 'SECURITY VIOLATION: You do not have permission to modify this order.'
        ]);
    }

    // Proceed safely...
}

Pillar 2: The Human-in-the-Loop (HITL) Confirmation Pattern

High-risk financial actions (e.g. $100+ refund, account deletion, subscription downgrade) par AI ko instant auto-execute ki permission nahi honi chahiye. Tool ek temporary approval token generate karta hai aur user se UI par explicit confirmation maangta hai:

php HITL Safety Token Generation 
if ($amount > 100.00) {
    // Generate secure single-use confirmation token
    $approvalToken = Str::random(40);

    Cache::put("ai_action_approval:{$approvalToken}", [
        'user_id'  => $user->id,
        'action'   => 'refund_order',
        'order_id' => $order->id,
        'amount'   => $amount,
        'reason'   => $reason,
    ], now()->addMinutes(15));

    // Return confirmation requirement to the AI
    return json_encode([
        'requires_human_confirmation' => true,
        'amount'                      => $amount,
        'approval_url'                => route('ai.confirm', ['token' => $approvalToken]),
        'message'                     => "Refunds over $100 require your explicit security confirmation before processing.",
    ]);
}

ECommerceAgent Service Implementation

php app/Ai/Agents/ECommerceAgent.php 
<?php

namespace App\Ai\Agents;

use App\Ai\Tools\GetOrderStatusTool;
use App\Ai\Tools\ProcessRefundTool;
use App\Ai\Tools\SearchKnowledgeBaseTool;
use Prism\Prism\Facades\Prism;
use Prism\Prism\Enums\Provider;
use Prism\Prism\ValueObjects\Messages\UserMessage;
use Symfony\Component\HttpFoundation\StreamedResponse;

class ECommerceAgent
{
    public function __construct(
        protected GetOrderStatusTool $orderStatusTool,
        protected ProcessRefundTool $refundTool,
        protected SearchKnowledgeBaseTool $knowledgeTool
    ) {}

    /**
     * Run the agent with live tool-event streaming
     */
    public function handle(string $userPrompt, int $userId): StreamedResponse
    {
        return response()->stream(function () use ($userPrompt, $userId) {
            while (ob_get_level() > 0) ob_end_flush();

            // System prompt with behavioral boundaries
            $systemPrompt = <<<PROMPT
You are a senior customer support concierge for an e-commerce platform.
You have access to tools to check orders, search company policy, and process refunds.
Always check order status before processing refunds.
Be polite, professional, and explain actions clearly.
PROMPT;

            // Execute Prism Agent Loop with MaxSteps Recursion Guard
            $response = Prism::text()
                ->using(Provider::Anthropic, 'claude-3-5-sonnet-20241022')
                ->withSystemPrompt($systemPrompt)
                ->withTools([
                    $this->orderStatusTool,
                    $this->refundTool,
                    $this->knowledgeTool,
                ])
                ->withMaxSteps(4) // Max 4 autonomous reasoning/action turns
                ->withPrompt($userPrompt)
                ->generate();

            // 1. Emit all tool steps taken to frontend for transparency
            foreach ($response->steps as $stepIndex => $step) {
                if (! empty($step->toolCalls)) {
                    foreach ($step->toolCalls as $call) {
                        echo "data: " . json_encode([
                            'event' => 'agent_action',
                            'step'  => $stepIndex + 1,
                            'tool'  => $call->name,
                            'args'  => $call->arguments(),
                        ]) . "\n\n";
                        flush();
                    }
                }
            }

            // 2. Stream the final natural language answer
            echo "data: " . json_encode([
                'event'   => 'final_answer',
                'message' => $response->text,
                'tokens'  => $response->usage->totalTokens(),
            ]) . "\n\n";

            echo "data: [DONE]\n\n";
            flush();

        }, 200, [
            'Content-Type'      => 'text/event-stream',
            'Cache-Control'     => 'no-cache, no-transform',
            'X-Accel-Buffering' => 'no',
        ]);
    }
}

Live Agent Controller Endpoint

php app/Http/Controllers/AiAgentController.php 
namespace App\Http\Controllers;

use App\Ai\Agents\ECommerceAgent;
use Illuminate\Http\Request;

        // Step 2: Final response after tool execution
        (new TextResponseFake())

2. Production Gotchas: Hallucinated Tool Names & Type Casting

⚠️ Hallucinated Tool Names

Agar aapka tool name hai getOrderStatus, toh kabhi kabhi model fetch_order_status call karne ki koshish kar sakta hai.
Defense: Tool names ko lowercase camelCase rakhein aur System Prompt mein explicit list include karein: "Available tools: getOrderStatus, processOrderRefund. Do not invent other tool names."

⚠️ Loose Type Coercion

JSON specification mein number aur string distinct hote hain, lekin LLMs kabhi order_id: "1042" (string) bhej dete hain.
Defense: Apne PHP tool handler method mein parameters ko strictly typecast karein: int $order_id = (int) $args['order_id'];.
