📡 LLM Token Generation & The Streaming UX Bottleneck
Autoregressive token generation kaise kaam karta hai aur kyun Server-Sent Events (SSE) WebSockets se behtar choice hai.

Large Language Models (LLMs) traditional MySQL queries ki tarah ek single pre-computed block mein output return nahi karte. LLMs **Autoregressive** hote hain — yaani wo probability calculation ke zariye ek time par ek single token predict karte hain.

❌ Synchronous (Non-Streaming) UX Flaw

- Latency: Agar model 600 tokens generate kar raha hai @ 40 tokens/sec, toh response aane mein 15 SECONDS lagenge.
- User Experience: User 15 seconds tak ek blank screen ya spinning loader dekhta hai. Use lagta hai system hang ho gaya hai.
- Server Load: PHP-FPM worker thread poore 15 seconds tak block rehta hai.

✅ Real-time Streaming (SSE) Excellence

- Latency: Time To First Token (TTFB) sirf 200ms - 350ms hota hai!
- User Experience: Jaise hi pehla word generate hota hai, screen par typewriter effect shuru ho jata hai. User us word ko read karne lagta hai jabki background mein baki words aate rehte hain.
- Perceived Speed: User ko lagta hai application instant aur blazing fast hai!

⚔️ SSE vs. WebSockets vs. Polling for AI in Laravel

Aksar developers sochte hain ki real-time streaming ke liye WebSockets (jaise Laravel Reverb ya Pusher) zaroori hai. Aisa bilkul nahi hai:

Feature Server-Sent Events (SSE) WebSockets (Reverb/Pusher) Long Polling
Directionality Unidirectional (Server to Client) — AI streams ke liye 100% perfect Bidirectional (Full duplex) Client initiates every request
Protocol Standard HTTP (HTTP/1.1 chunked, HTTP/2 multiplexed) Custom WebSocket protocol (ws://, wss://) Repeated HTTP requests
Infrastructure Overhead Zero — Standard PHP-FPM + NGINX handle kar leta hai Requires standalone daemon process (Reverb server + Redis) High server load & DB query overhead
Firewall & Proxy Traversal 100% transparent (Port 80/443 standard HTTPS) Corporate firewalls & proxies often block WebSocket upgrades Standard HTTP
Best Laravel Use Case ChatGPT-style conversational streams & real-time text completion Multiplayer collaboration, live notifications, trading tickers Legacy fallback only

Anatomy of the Server-Sent Events (SSE) Wire Protocol

SSE ek plain-text protocol hai jisme data chunks newline-separated format mein stream hote hain:

HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no

data: {"text": "Laravel"}

data: {"text": " ke"}

data: {"text": " andar"}

data: {"text": " AI"}

data: {"text": " streaming"}

data: {"text": " superfast"}

data: {"text": " hai!"}

data: [DONE]
💡 Why X-Accel-Buffering: no is Mandatory

Agar aapke production server par NGINX reverse proxy chal raha hai, toh by default NGINX PHP-FPM se aane wale chote 15-byte chunks ko buffer (store) kar leta hai aur jab buffer 4KB ya 8KB bhar jata hai tab ek saath bhejta hai. Result: User ko live typewriter effect nahi milta, balki ruk ruk kar bade paragraphs aate hain. Header X-Accel-Buffering: no NGINX ko instruct karta hai: "Chunk jaise hi aaye, immediately flush karo!"

2. Real-time Streaming API: Prism::stream()

Jab aapko frontend par real-time typewriter effect deliver karna ho. Prism::stream() ek PHP Generator return karta hai jise aap foreach loop ke zariye chunk-by-chunk consume kar sakte hain:

php Streaming Generator Example 
use Prism\Prism\Facades\Prism;
use Prism\Prism\Enums\Provider;
use Prism\Prism\Streaming\Events\TextDeltaChunk;
use Prism\Prism\Streaming\Events\FinishChunk;

// Create Stream Generator
$stream = Prism::stream()
    ->using(Provider::Anthropic, 'claude-3-5-sonnet-20241022')
    ->withSystemPrompt('You are a helpful coding assistant.')
    ->withPrompt('Write a clean PHP 8.3 enum for OrderStatus with payment states.')
    ->generate();

// Iterate through chunks as they arrive from Anthropic/OpenAI
foreach ($stream as $chunk) {
    if ($chunk instanceof TextDeltaChunk) {
        // Individual word ya token piece (e.g. "enum ", "OrderStatus: ", "string")
        echo $chunk->text;
    }

    if ($chunk instanceof FinishChunk) {
        // Final token metrics and completion reason
        $finalReason = $chunk->finishReason;
        $totalTokens = $chunk->usage->totalTokens();
    }
}

🛠️ Building the Production Laravel StreamedResponse
Zero-buffering controller architecture jo client disconnects aur token wastage ko handle karta hai.

Ek production-ready streaming controller likhte waqt 3 critical cheezon ka dhyan rakhna padta hai:
1. Output Buffering: PHP ke default buffers ko disable karna taaki har token instantly socket par write ho.
2. Client Abort Guard: Agar user tab close kar de ya cancel button dabaye, toh LLM loop immediately break ho jaye taaki aapke API dollars waste na hon!
3. JSON Encoded SSE Payloads: Chunks ke andar raw newlines ya double quotes hone par plain string SSE format break ho jata hai; isliye JSON encode karna mandatory hai.

AiChatStreamController Implementation

php app/Http/Controllers/AiChatStreamController.php 
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\StreamedResponse;
use Prism\Prism\Facades\Prism;
use Prism\Prism\Enums\Provider;
use Prism\Prism\Streaming\Events\TextDeltaChunk;
use Prism\Prism\Streaming\Events\FinishChunk;

class AiChatStreamController extends Controller
{
    /**
     * Stream LLM response chunks as Server-Sent Events (SSE)
     */
    public function __invoke(Request $request): StreamedResponse
    {
        $validated = $request->validate([
            'prompt'   => ['required', 'string', 'max:2000'],
            'model'    => ['nullable', 'string'],
        ]);

        $prompt = $validated['prompt'];
        $model  = $validated['model'] ?? 'gpt-4o-mini';

        return response()->stream(function () use ($prompt, $model) {
            // 1. PHP output buffering ko completely clear aur disable karein
            while (ob_get_level() > 0) {
                ob_end_flush();
            }

            // 2. Prism stream initialize karein
            $stream = Prism::stream()
                ->using(Provider::OpenAI, $model)
                ->withSystemPrompt('You are an expert Laravel pair programmer. Provide clear, concise answers.')
                ->withPrompt($prompt)
                ->withClientOptions([
                    'temperature' => 0.7,
                    'max_tokens'  => 1200,
                ])
                ->generate();

            // 3. Loop over chunks as they arrive from the AI provider
            foreach ($stream as $chunk) {
                // Client tab close guard: Agar user ne browser close kar diya toh turant exit karein!
                if (connection_aborted()) {
                    break;
                }

                if ($chunk instanceof TextDeltaChunk) {
                    // Send JSON payload in standard SSE 'data: ...' format
                    echo "data: " . json_encode(['text' => $chunk->text]) . "\n\n";
                    flush();
                }

                if ($chunk instanceof FinishChunk) {
                    // Send completion event with token metrics
                    echo "data: " . json_encode([
                        'finished'     => true,
                        'finish_reason'=> $chunk->finishReason,
                        'total_tokens' => $chunk->usage->totalTokens(),
                    ]) . "\n\n";
                    flush();
                }
            }

            // 4. Stream completion sentinel
            echo "data: [DONE]\n\n";
            flush();

        }, 200, [
            'Content-Type'      => 'text/event-stream',
            'Cache-Control'     => 'no-cache, no-transform',
            'Connection'        => 'keep-alive',
            'X-Accel-Buffering' => 'no', // NGINX buffering disable karein
        ]);
    }
}

🚨 Crucial Gotcha: Session Locking in Laravel Streaming

Default Laravel web routes par standard Session middleware active hota hai jo request ke start par session file/row ko exclusive lock kar deta hai. Agar ek user ka streaming request 20 seconds chal raha hai, toh woh user doosre tab mein koi naya page open nahi kar payega kyunki session lock release nahi hua!
Solution: Stream start karne se pehle Session::save(); call karein taaki session lock release ho jaye, ya fir is endpoint ko stateless routes/api.php mein rakhein.

<script>
function aiChat() {
    return {
        userInput: '',
        isStreaming: false,
        abortController: null,
        messages: [
            { role: 'assistant', content: 'Hello! Main aapka Laravel AI assistant hoon. Kaise madad karun?' }
        ],

        async sendMessage() {
            if (!this.userInput.trim() || this.isStreaming) return;

            const promptText = this.userInput;
            this.messages.push({ role: 'user', content: promptText });
            this.userInput = '';

            // Assistant placeholder message add karein
            this.messages.push({ role: 'assistant', content: '' });
            this.isStreaming = true;
            this.abortController = new AbortController();

            try {
                const response = await fetch('/api/ai/stream', {
                    method: 'POST',
                    headers: {
                        'Content-Type': 'application/json',
                        'X-CSRF-TOKEN': document.querySelector('meta[name="csrf-token"]')?.content,
                    },
                    body: JSON.stringify({ prompt: promptText }),
                    signal: this.abortController.signal,
                });

                if (!response.ok) throw new Error('Stream request failed');

                // Read incoming stream chunks
                const reader = response.body.getReader();
                const decoder = new TextDecoder('utf-8');
                let assistantMsgIndex = this.messages.length - 1;

                while (true) {
                    const { done, value } = await reader.read();
                    if (done) break;

                    const chunk = decoder.decode(value, { stream: true });
                    const lines = chunk.split('\n\n');

                    for (const line of lines) {
                        if (line.startsWith('data: ')) {
                            const dataStr = line.replace('data: ', '').trim();
                            if (dataStr === '[DONE]') break;

                            try {
                                const parsed = JSON.parse(dataStr);
                                if (parsed.text) {
                                    this.messages[assistantMsgIndex].content += parsed.text;
                                    this.$refs.chatBox.scrollTop = this.$refs.chatBox.scrollHeight;
                                }
                            } catch (e) {
                                // Skip non-JSON frames
                            }
                        }
                    }
                }
            } catch (err) {
                if (err.name === 'AbortError') {
                    console.log('Stream generation manually aborted by user');
                } else {
                    console.error('Streaming error:', err);
                }
            } finally {
                this.isStreaming = false;
                this.abortController = null;
            }
        },

        stopGeneration() {
            if (this.abortController) {
                this.abortController.abort(); // Browser socket close karega -> PHP connection_aborted() trigger hoga!
            }
        }
    };
}
</script>

Option B: Vue 3 (Composition API) & Inertia.js Composable

Agar aapka stack Vue 3 + Inertia hai, toh aap is logic ko ek reusable composable useAiStream() mein encapsulate kar sakte hain:

javascript resources/js/composables/useAiStream.js 
import { ref } from 'vue';

export function useAiStream(endpoint = '/api/ai/stream') {
    const isStreaming = ref(false);
    let abortController = null;

    const streamPrompt = async (prompt, onChunk, onFinish) => {
        isStreaming.value = true;
        abortController = new AbortController();

        try {
            const res = await fetch(endpoint, {
                method: 'POST',
                headers: { 'Content-Type': 'application/json' },
                body: JSON.stringify({ prompt }),
                signal: abortController.signal
            });

            const reader = res.body.getReader();
            const decoder = new TextDecoder();

            while (true) {
                const { done, value } = await reader.read();
                if (done) break;

                const textChunk = decoder.decode(value, { stream: true });
                const lines = textChunk.split('\n\n');

                for (const line of lines) {
                    if (line.startsWith('data: ')) {
                        const raw = line.slice(6).trim();
                        if (raw === '[DONE]') return onFinish && onFinish();

                        try {
                            const json = JSON.parse(raw);
                            if (json.text) onChunk(json.text);
                        } catch (e) {}
                    }
                }
            }
        } catch (err) {
            if (err.name !== 'AbortError') throw err;
        } finally {
            isStreaming.value = false;
            abortController = null;
        }
    };

    const stop = () => abortController && abortController.abort();

    return { isStreaming, streamPrompt, stop };
}
🧠 Multi-Turn Conversation Memory & Context Management
Eloquent schema, sliding window context buffers aur token inflation defense.

LLMs completely **Stateless** hote hain. Model ko yeh yaad nahi hota ki pichli request mein aapne kya pucha tha. Multi-turn conversation (jaise ChatGPT) achieve karne ke liye client ya database se pichli chat history ko har request ke saath re-send karna padta hai.

1. Database Architecture: Conversations & Messages

php database/migrations/create_ai_chat_tables.php 
Schema::create('ai_conversations', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->string('title')->default('New Chat');
    $table->string('model')->default('gpt-4o-mini');
    $table->text('system_prompt')->nullable();
    $table->timestamps();
});

Schema::create('ai_messages', function (Blueprint $table) {
    $table->id();
    $table->foreignId('conversation_id')->constrained('ai_conversations')->cascadeOnDelete();
    $table->enum('role', ['user', 'assistant', 'system']);
    $table->text('content');
    $table->unsignedInteger('tokens')->nullable();
    $table->timestamps();

    $table->index(['conversation_id', 'created_at']);
});

2. Eloquent Model Relationships & Message Mapping

Eloquent records ko Prism ke Value Objects (UserMessage, AssistantMessage) mein convert karein:

php app/Models/AiConversation.php 
namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\HasMany;
use Prism\Prism\ValueObjects\Messages\UserMessage;
use Prism\Prism\ValueObjects\Messages\AssistantMessage;

class AiConversation extends Model
{
    protected $guarded = [];

    public function messages(): HasMany
    {
        return $this->hasMany(AiMessage::class, 'conversation_id');
    }

    /**
     * Get recent messages formatted for Prism with sliding buffer
     */
    public function getRecentPrismMessages(int $limit = 10): array
    {
        return $this->messages()
            ->latest('id')
            ->take($limit)
            ->get()
            ->reverse()
            ->map(fn (AiMessage $m) => match ($m->role) {
                'user'      => new UserMessage($m->content),
                'assistant' => new AssistantMessage($m->content),
            })
            ->values()
            ->toArray();
    }
}

3. The Token Inflation Problem & Sliding Window Truncation

Agar aap ek chat mein user ke 50 previous messages bhejte rahenge, toh har request mein input tokens exponentially grow karenge. Chat lambi hote hi ek single prompt $0.15 cost karega aur context window limit (e.g. 128k tokens) hit ho jayegi!

🛡️ Strategy 1: Sliding Window (Last N Messages)

Sirf last 6 se 10 messages retrieve karke pass karein. Casual customer support chats ke liye 95% cases mein pichle 5 interactions kaafi hote hain. Low cost aur high speed.

🧠 Strategy 2: AI Summarization Buffer

Jab message count 20 exceed kare, ek background job trigger karein jo pehle 15 messages ko ek short 2-line summary mein compress kar de, aur use system prompt context mein inject kar de!

Streaming with Conversation History in Controller

php Controller Multi-turn Integration 
// User message ko DB mein persist karein

    'role'    => 'user',
    'content' => $prompt,
]);

// Stream chunks & aggregate full text in background to save assistant response
$fullAssistantResponse = '';
foreach ($stream as $chunk) {
    if ($chunk instanceof TextDeltaChunk) {

        flush();
    }
}

// Save complete assistant answer in database
$conversation->messages()->create([
    'role'    => 'assistant',
    'content' => $fullAssistantResponse,
]);

🚀 Production NGINX Configuration & Architecture Cheatsheet
Server-level tuning taaki live streaming production high concurrency par fail na ho.

Localhost (php artisan serve) par streaming perfect chalti hai, lekin production Linux server par NGINX aur PHP-FPM default settings streaming ko block kar deti hain. Yahan essential server configuration di gayi hai:

1. NGINX Site Configuration for Server-Sent Events

Apne /etc/nginx/sites-available/your-domain.conf ke andar location /api/ai/stream ya main PHP block mein yeh directives add karein:

nginx /etc/nginx/sites-available/app.conf 
location ~ \.php$ {
    include fastcgi_params;
    fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
    fastcgi_index index.php;
    fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;

    # --- Crucial SSE Streaming Directives ---
    fastcgi_buffering off;             # Disables FastCGI response buffering
    fastcgi_read_timeout 300s;         # Prevents 504 Gateway Timeout during reasoning
    fastcgi_keep_conn on;              # Keeps connection persistent
    proxy_buffering off;               # If using Nginx as reverse proxy
    proxy_read_timeout 300s;
    chunked_transfer_encoding on;      # Ensures HTTP 1.1 chunked transfer works
}

2. PHP-FPM Concurrency Trap (Worker Exhaustion)

⚠️ Warning: FPM Process Pool Starvation

Standard PHP CRUD request sirf 30ms mein worker release kar deta hai. Lekin streaming request 15 se 30 seconds tak ek dedicated PHP-FPM worker hold karke rakhta hai!
Agar aapke server par pm.max_children = 20 set hai aur 20 users ek saath streaming chat shuru kar dete hain, toh server par 21st user ka standard web page bhi 502/504 choke ho jayega!
Production Fix: AI streaming ke liye alag PHP-FPM pool banayein (e.g. [ai_pool] on dedicated socket) ya worker capacity badhayein, aur continuous background tasks ke liye Laravel Queues + Horizon use karein.
