Production AI Architecture, Horizon Queues & Cost Optimization

AI features ko production scale par chalana expensive aur challenging hota hai. Is module mein hum master karenge Laravel Horizon background queues, Multi-Model Fallback Chains (zero downtime jab OpenAI down ho), Redis Semantic Vector Caching (API bills ko 70% slash karne ka secret), aur Per-Tenant Token Budgeting with live cost tracking!

🚨 The 4 Realities of the Production AI Crisis
Kyun toy AI apps production scale par aate hi crash hoti hain aur $2,000 ka surprise bill generate karti hain.

Local development mein single user ke liye Prism::text()->generate() chalana aasan lagta hai. Lekin jab 2,000 active users aapke SaaS par aate hain, toh AI architecture traditional MySQL CRUD se 100x zyada volatile behave karti hai:

1. Latency & Worker Starvation

Traditional database query 15ms mein complete hoti hai. AI reasoning call 4,000ms se 35,000ms leti hai! Agar synchronous controllers mein call kiya, toh 50 concurrent users aapke poore PHP-FPM web pool ko freeze kar denge.

2. Runaway Token Costs

RAG pipelines mein har query ke saath 3,000 tokens ka context context window mein inject hota hai. 1,000 users * 10 queries/day = 30 Million tokens/day! Without caching, mahine ka OpenAI bill $1,800+ ban jata hai.

3. 3rd-Party API Outages & 429 Throttling

OpenAI aur Anthropic ke server incidents hote rehte hain (HTTP 500, 502, 503). Agar aapka backend single provider par hardcoded hai, toh aapka SaaS downtime face karega chahe aapka apna server 100% healthy ho!

4. Rogue Multi-Tenant Abuse

Bina token limits ke, ek single customer loop script likh kar aapka 80% quota 1 ghante mein exhaust kar sakta hai, jisse baki paying customers ko "Quota Exceeded" errors milne lagenge.

⚡ Laravel Horizon Queues: Dedicated AI Workers & Sizing
Kyun AI jobs ko standard queues mein mix nahi kiya jata aur Horizon configuration kaise tune karein.

Ek standard Laravel app mein jobs fast hoti hain (e.g. SendPasswordResetNotification takes 120ms). Agar aapne usi default queue mein ek 25-second ka heavy AI document parsing job daal diya, toh aapke sabhi transactional emails 30 second line mein latak jayenge!

1. Dedicated Redis Queue Topology

Production mein hum AI ko kam se kam 2 dedicated priority queues dete hain:

  • ai-high: User-facing interactive background tasks (e.g. user waiting on screen with progress bar). Fast supervisor with 10 workers.
  • ai-batch: Heavy bulk operations (e.g. 100-page PDF ingestion, nightly CRM summaries). Dedicated long-timeout worker.

3. The ShouldBeUnique Guard (Preventing Double Billing)

Impatience ke chalte user "Generate Summary" button par 4 baar click kar sakta hai. ShouldBeUnique interface ensure karta hai ki ek hi document ke liye simultaneously do expensive AI jobs queue mein add na hon:

php app/Jobs/SummarizeDocumentJob.php 
namespace App\Jobs;

use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Contracts\Queue\ShouldBeUnique;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;

class SummarizeDocumentJob implements ShouldQueue, ShouldBeUnique
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    // Retry settings for transient API failures
    public int $tries = 3;
    public array $backoff = [10, 30, 90]; // Exponential backoff allows rate limit window to reset!

    public function __construct(
        public int $documentId,
        public int $tenantId
    ) {
        $this->onQueue('ai-high');
    }

    /**
     * Unique lock identifier in Redis
     */
    public function uniqueId(): string
    {
        return "summarize_doc_{$this->documentId}";
    }

    /**
     * Lock expiry time in seconds
     */
    public int $uniqueFor = 300; // 5 minutes lock
}
🔄 Multi-Model Fallback Chains & Circuit Breakers
Zero-downtime architecture jo OpenAI outages par automatic Claude ya Groq par failover karta hai.

2024–2026 mein koi bhi enterprise production SaaS sirf ek AI provider par depend nahi reh sakta. Jab OpenAI status page par red incident aata hai, toh aapka customer portal bina 1 second ke downtime ke automatically fallback provider par switch ho jana chahiye!

The 3-Tier Multi-Provider Fallback Service

php app/Services/ResilientAiService.php 
<?php

namespace App\Services;

use Prism\Prism\Facades\Prism;
use Prism\Prism\Enums\Provider;
use Prism\Prism\Text\Response;
use Illuminate\Support\Facades\Cache;
use Illuminate\Support\Facades\Log;

class ResilientAiService
{
    /**
     * Generate text with 3-tier fallback and Redis circuit breaker
     */
    public function generate(string $prompt, string $systemPrompt = ''): Response
    {
        // 1. Check Circuit Breaker for Primary Provider (OpenAI)
        if (! Cache::has('ai_circuit:openai:tripped')) {
            try {
                return Prism::text()
                    ->using(Provider::OpenAI, 'gpt-4o-mini')
                    ->withSystemPrompt($systemPrompt)
                    ->withPrompt($prompt)
                    ->generate();
            } catch (\Throwable $e) {
                $this->recordFailure('openai', $e);
            }
        }

        // 2. Secondary Fallback: Anthropic Claude 3.5 Sonnet
        if (! Cache::has('ai_circuit:anthropic:tripped')) {
            try {
                Log::warning("OpenAI down or tripped. Failing over to Anthropic Claude...");
                return Prism::text()
                    ->using(Provider::Anthropic, 'claude-3-5-sonnet-20241022')
                    ->withSystemPrompt($systemPrompt)
                    ->withPrompt($prompt)
                    ->generate();
            } catch (\Throwable $e) {
                $this->recordFailure('anthropic', $e);
            }
        }

        // 3. Emergency High-Speed Fallback: Groq Llama 3.3 (Free / Ultra-fast)
        Log::critical("Both OpenAI and Claude failed! Engaging Emergency Groq fallback...");
        return Prism::text()
            ->using(Provider::Groq, 'llama-3.3-70b-versatile')
            ->withSystemPrompt($systemPrompt)
            ->withPrompt($prompt)
            ->generate();
    }

    /**
     * Trip circuit breaker if 3 failures occur within 2 minutes
     */
    protected function recordFailure(string $provider, \Throwable $e): void
    {
        Log::error("Provider [{$provider}] error: " . $e->getMessage());

        $failures = Cache::increment("ai_failures:{$provider}");
        if ($failures === 1) {
            Cache::put("ai_failures:{$provider}", 1, now()->addMinutes(2));
        }

        // Trip the circuit for 5 minutes after 3 failures
        if ($failures >= 3) {
            Log::alert("🚨 TRIP CIRCUIT: [{$provider}] has failed 3 times! Bypassing for 5 minutes.");
            Cache::put("ai_circuit:{$provider}:tripped", true, now()->addMinutes(5));
            Cache::forget("ai_failures:{$provider}");
        }
    }
}
💡 Why the Circuit Breaker is Critical

Agar OpenAI down ho aur har request 30 seconds baad timeout error de, toh circuit breaker ke bina aapka har user 30 seconds wait karega tab jaakar Claude par switch hoga. Circuit Breaker 3 failures ke baad OpenAI ko 5 minute ke liye ignore kar deta hai, jisse agle sabhi users direct Claude par 0ms failover latency ke saath serve hote hain!

💰 Redis Semantic Vector Caching: Slash 70% Off AI Bills
Kyun standard MD5 caching AI mein fail hoti hai aur Semantic Caching kaise 5ms instant answer deti hai.

Customer support aur e-commerce SaaS mein 60% se 80% customer queries identical intent wali hoti hain:
Customer A: "Where can I download my GST invoice?"
Customer B: "How to get invoice for GST tax?"
Customer C: "Invoice download procedure please"

❌ The Flaw of Traditional Cache::remember()

Agar aap Cache::remember('ai_' . md5($prompt)) karenge, toh Customer A, B, aur C ke MD5 hashes completely alag honge. Result: Teenon requests par $0.04-$0.04 ka expensive OpenAI call hoga aur teeno ko 10-second loader wait karna padega!

Semantic Cache Architecture (Cosine Similarity > 0.94)

Semantic Caching mein hum previous answers ko unke Embedding Vector ke saath store karte hain. Nayi query aane par hum $0.00002 ki micro-embedding call karke check karte hain: "Kya kisi previous answered query se 94% match hai?" Agar haan, toh 5ms mein cached answer return hota hai bina kisi LLM generation cost ke!

php app/Services/SemanticCacheService.php 
<?php

namespace App\Services;

use App\Models\SemanticCacheEntry;
use Pgvector\Laravel\Vector;
use Prism\Prism\Facades\Prism;
use Prism\Prism\Enums\Provider;

class SemanticCacheService
{
    /**
     * Look up semantic cache for identical intent (Threshold: 0.94)
     */
    public function get(string $prompt, int $tenantId): ?string
    {
        // 1. Generate fast embedding for the user prompt ($0.00002 cost)
        $embedResponse = Prism::embeddings()
            ->using(Provider::OpenAI, 'text-embedding-3-small')
            ->fromInput($prompt)
            ->generate();

        $queryVector = new Vector($embedResponse->embeddings[0]->embedding);

        // 2. Query cache table with Cosine Similarity
        $hit = SemanticCacheEntry::query()
            ->where('tenant_id', $tenantId)
            ->select('id', 'response_text')
            ->selectRaw('1 - (embedding <=> ?) AS similarity', [$queryVector])
            ->whereRaw('1 - (embedding <=> ?) >= 0.94', [$queryVector]) // 94% semantic match
            ->orderByRaw('embedding <=> ? ASC', [$queryVector])
            ->first();

        if ($hit) {
            $hit->increment('hit_count');
            return $hit->response_text;
        }

        return null;
    }

    /**
     * Store new prompt & answer with embedding vector
     */
    public function put(string $prompt, string $response, int $tenantId): void
    {
        $embedResponse = Prism::embeddings()
            ->using(Provider::OpenAI, 'text-embedding-3-small')
            ->fromInput($prompt)
            ->generate();

        SemanticCacheEntry::create([
            'tenant_id'     => $tenantId,
            'prompt'        => $prompt,
            'response_text' => $response,
            'embedding'     => new Vector($embedResponse->embeddings[0]->embedding),
            'hit_count'     => 0,
        ]);
    }
}

📊 Per-Tenant Token Budgeting, Cost Quotas & Rate Limiting
Multi-tenant SaaS financial protection: User plans, token meters aur RateLimiter guards.

Agar aapka customer $19/month ka starter plan pay kar raha hai, toh aap use unlimited $0.05 wale GPT-4o calls nahi de sakte. Production SaaS mein **Token Metering aur Quota Enforcement** mandatory hai.

1. Database Architecture: Tenant AI Usage Meter

php database/migrations/create_tenant_ai_usage_table.php 
Schema::create('tenant_ai_usages', function (Blueprint $table) {
    $table->id();
    $table->foreignId('tenant_id')->index();
    $table->date('usage_date')->index(); // Partitioned by date for fast aggregation
    $table->unsignedBigInteger('input_tokens')->default(0);
    $table->unsignedBigInteger('output_tokens')->default(0);
    $table->unsignedBigInteger('cost_in_microcents')->default(0); // $0.01 = 1,000 microcents
    $table->timestamps();

    $table->unique(['tenant_id', 'usage_date']);
});

2. Middleware: EnsureTenantHasAiCredits

Request LLM tak pahunchne se pehle hi check karein ki tenant ne apna monthly quota exceed toh nahi kiya:

php app/Http/Middleware/EnsureTenantHasAiCredits.php 
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class EnsureTenantHasAiCredits
{
    public function handle(Request $request, Closure $next): Response
    {
        $tenant = $request->user()?->tenant;

        if (! $tenant) {
            abort(403, 'Tenant context missing.');
        }

        // Get monthly token limit based on subscription plan
        $monthlyLimit = match ($tenant->plan) {
            'enterprise' => 5_000_000,
            'pro'        => 500_000,
            default      => 25_000, // Free Tier
        };

        $currentUsage = $tenant->getMonthlyTokenUsage();

        if ($currentUsage >= $monthlyLimit) {
            return response()->json([
                'error'         => 'Monthly AI quota exceeded.',
                'current_usage' => $currentUsage,
                'monthly_limit' => $monthlyLimit,
                'upgrade_url'   => route('billing.upgrade'),
            ], 402); // 402 Payment Required
        }

        return $next($request);
    }
}

3. Real-Time Rate Limiter in AppServiceProvider

Spam bot scripts ko rokne ke liye per-minute limits enforce karein:

php app/Providers/AppServiceProvider.php 
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Http\Request;

public function boot(): void
{
    RateLimiter::for('ai-chat', function (Request $request) {
        $tenantId = $request->user()?->tenant_id ?? $request->ip();

        return Limit::perMinute(15)
            ->by($tenantId)
            ->response(fn () => response()->json([
                'error' => 'Too many AI requests. Please slow down (Limit: 15 req/min).'
            ], 429));
    });
}

1. CostTrackerService Implementation

php app/Services/CostTrackerService.php 
<?php

namespace App\Services;

use App\Models\TenantAiUsage;
use Illuminate\Support\Facades\DB;

class CostTrackerService
{
    /**
     * Pricing table per 1,000,000 tokens in microcents ($1.00 = 100,000,000 microcents)
     */
    protected const PRICING = [
        'gpt-4o-mini' => ['input' => 15_000_000, 'output' => 60_000_000],  // $0.15 / $0.60
        'gpt-4o'      => ['input' => 250_000_000, 'output' => 1000_000_000],// $2.50 / $10.00
        'claude-3-5'  => ['input' => 300_000_000, 'output' => 1500_000_000],// $3.00 / $15.00
        'deepseek-r1' => ['input' => 14_000_000, 'output' => 28_000_000],  // $0.14 / $0.28
    ];

    /**
     * Record token usage and calculate financial cost
     */
    public function record(int $tenantId, string $model, int $inputTokens, int $outputTokens): void
    {
        $rates = self::PRICING[$model] ?? self::PRICING['gpt-4o-mini'];

        $inputCost  = (int) (($inputTokens / 1_000_000) * $rates['input']);
        $outputCost = (int) (($outputTokens / 1_000_000) * $rates['output']);
        $totalCost  = $inputCost + $outputCost;

        $today = now()->toDateString();

        DB::table('tenant_ai_usages')->upsert(
            [
                'tenant_id'           => $tenantId,
                'usage_date'          => $today,
                'input_tokens'        => $inputTokens,
                'output_tokens'       => $outputTokens,
                'cost_in_microcents'  => $totalCost,
                'created_at'          => now(),
                'updated_at'          => now(),
            ],
            uniqueBy: ['tenant_id', 'usage_date'],
            update: [
                'input_tokens'       => DB::raw("input_tokens + {$inputTokens}"),
                'output_tokens'      => DB::raw("output_tokens + {$outputTokens}"),
                'cost_in_microcents' => DB::raw("cost_in_microcents + {$totalCost}"),
                'updated_at'         => now(),
            ]
        );
    }
}

2. ProcessDocumentAiJob (Horizon Queued Job)

php app/Jobs/ProcessDocumentAiJob.php 
namespace App\Jobs;

use App\Models\KnowledgeDocument;
use App\Services\ResilientAiService;
use App\Services\CostTrackerService;
use App\Events\DocumentProcessedEvent;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Contracts\Queue\ShouldBeUnique;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;
use Illuminate\Queue\SerializesModels;

class ProcessDocumentAiJob implements ShouldQueue, ShouldBeUnique
{
    use Dispatchable, InteractsWithQueue, Queueable, SerializesModels;

    public int $tries = 3;
    public array $backoff = [15, 45, 120];

    public function __construct(
        public int $documentId,
        public int $tenantId
    ) {
        $this->onQueue('ai-batch');
    }

    public function uniqueId(): string
    {
        return "process_doc_{$this->documentId}";
    }

    /**
     * Horizon Tagging: Allows searching jobs by Tenant & Doc in dashboard!
     */
    public function tags(): array
    {
        return ["tenant:{$this->tenantId}", "doc:{$this->documentId}", "ai-pipeline"];
    }

    public function handle(ResilientAiService $ai, CostTrackerService $costTracker): void
    {
        $doc = KnowledgeDocument::findOrFail($this->documentId);

        // Run multi-provider fallback AI analysis
        $response = $ai->generate(
            prompt: "Summarize this enterprise policy in 3 key action points: " . $doc->raw_text,
            systemPrompt: "You are an executive documentation analyst."
        );

        // Update Document Record
        $doc->update([
            'summary'     => $response->text,
            'status'      => 'processed',
        ]);

        // Audit & Track Token Billing
        $costTracker->record(
            tenantId: $this->tenantId,
            model: 'gpt-4o-mini',
            inputTokens: $response->usage->promptTokens,
            outputTokens: $response->usage->completionTokens
        );

        // Live WebSockets Push to Frontend via Laravel Reverb!
        broadcast(new DocumentProcessedEvent(
            documentId: $this->documentId,
            tenantId: $this->tenantId,
            summary: $response->text
        ))->toOthers();
    }
}

1. Testing Queued AI Jobs with Pest PHP

php tests/Feature/ProcessDocumentJobTest.php 
<?php

use App\Jobs\ProcessDocumentAiJob;
use App\Models\User;
use App\Models\KnowledgeDocument;
use Illuminate\Support\Facades\Queue;

it('dispatches ProcessDocumentAiJob on dedicated ai-batch queue with unique lock', function () {
    Queue::fake();

    $user = User::factory()->create();
    $doc  = KnowledgeDocument::factory()->create(['tenant_id' => $user->tenant_id]);

    $response = $this->actingAs($user)->postJson("/api/documents/{$doc->id}/summarize");

    $response->assertAccepted(); // 202 Accepted status

    // Assert that the job was pushed to the dedicated ai-batch queue
    Queue::assertPushedOn('ai-batch', ProcessDocumentAiJob::class);

    // Assert unique lock id exists to prevent double-billing
    Queue::assertPushed(function (ProcessDocumentAiJob $job) use ($doc) {
        return $job->documentId === $doc->id && 
               $job->uniqueId() === "process_doc_{$doc->id}";
    });
});
